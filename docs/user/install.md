# 安装 Scriptor 8.2.0

本版配套 **DSH 0.2.0-rc.2**。先安装这个桌面端，再在 DSH 里安装插件。

> [!NOTE]
> 桌面端自带运行时。
> 为了安装插件，不需要另装 Node.js 或 pnpm。

## 1. 打开插件管理

1. 从 [DSH 官网](https://www.deepseek.com/harness/) 安装 **DSH 0.2.0-rc.2**。
   成功时，桌面端可以打开。
2. 在侧栏选择 **插件**。
3. 点击 **添加插件**。
   成功时，页面出现安装标识输入框。

“官方”分组只列出 DSH 随附的插件。Scriptor 是另行安装的第三方插件。安装成功后，它出现在 **已安装** 分组。

## 2. 填入包名

首次使用只安装写作工作台。

> [!WARNING]
> 不要同时安装完整版和单独的写作包、检索包。
> 这两种入口只能二选一。重复安装会留下两个入口。

> [!CAUTION]
> 不要在应用变更时强行关闭程序。
> 先等安装完成。新版本刚发布时，镜像可能还没有同步。如果查不到包，切回官方 npm 再试。

1. 在添加插件的输入框粘贴下表中的完整标识。
2. 核对预览里的包名、版本和来源。
3. 确认安装。
   成功时，预览中的版本是 8.2.0。

| 插件 | 输入框内容 | 用途 |
| --- | --- | --- |
| 写作工作台 | `@linfengqaqtat/dsh-scriptor@8.2.0` | 书房、设计、写章、审读、定稿与导出 |
| 检索增强（可选） | `@linfengqaqtat/dsh-scriptor-retrieval@8.2.0` | 嵌入、场景识别、重排，分别配置和启用 |
| 鲸鱼娘（可选） | `@linfengqaqtat/dsh-scriptor-companion@8.2.0` | 窗口内陪伴及会话状态反馈 |
| 完整版（二选一） | `@linfengqaqtat/dsh-scriptor-full@8.2.0` | 一次安装写作与检索，不含桌宠 |

后续正式版本发布到 npm 的 latest。本教程使用精确版本，方便核对配套的 DSH。安装源优先选官方 npm。

## 3. 应用变更并核对

> [!NOTE]
> Windows 标题栏的关闭按钮可能只把程序藏进托盘。
> 需要重启时，从应用菜单完全退出，然后再打开。

1. 按插件管理器的提示启用插件。
2. 应用变更。如果页面要求重启，按上面的方式完全退出后再打开。
   成功时，已安装列表符合下面的结果。

- **写作工作台**：包名正确，版本为 8.2.0。启用后可以打开书房。
- **检索增强**：可以找到嵌入、场景识别和重排配置。它们默认关闭。基础写作不必先填写这些项目。
- **鲸鱼娘**：界面出现角色。隐藏之后，可以从对应设置里恢复。

设置中的内置插件列表只用来查看状态。安装和卸载都使用侧栏“插件”页面。

## 4. 配置模型，开始第一本书

1. 在 DSH 中配置聊天模型和凭据。
2. 选择一个用来存放作品的工作区。
   成功时，会话显示这个工作区。

书仓的版本记录需要可用的 Git。如果桌面端提示缺少工具，按它的提示补齐。

然后阅读 [新手教程](beginner.md) 和 [第一本书与第一章](first-book.md)。10 个写作技能随主插件提供。不需要另外安装技能。

## 为什么要固定 DSH 版本

插件只针对一个 DSH 版本验证。8.2.0 配套 **DSH 0.2.0-rc.2**。旧版 preview.6 / 提供方 0.0.8 对应 0.1.5-rc.2。

DSH 接口会随版本变化。更高的 DSH 版本不代表已经兼容。

1. 安装或升级前，核对目标插件版本对应的 DSH。
2. 把插件和 DSH 一起更新。
   成功时，两边的版本与上面的对应关系一致。

## 从单装切换为完整版

完整版包含写作工作台和检索增强。书仓与配置留在原来的 profile，不随包名搬迁。

> [!WARNING]
> 不要让完整版和单独安装的包同时存在。

1. 停用正在使用的会话。
2. 移除单独安装的写作工作台和检索增强。
3. 安装 `@linfengqaqtat/dsh-scriptor-full@8.2.0`。
4. 应用变更。
   成功时，只剩下完整版这一个入口。

如果要切回单装，先移除完整版，再安装需要的单包。

## 从旧包升级

先阅读 [备份与升级](upgrade-backup.md)。旧检索包是 `webnovel-embedding-provider`。旧桌宠包是 `@linfengqaqtat/dsh-whale-companion`。

> [!WARNING]
> 不要让旧包名和新包名同时启用。

1. 备份工作区和当前 DSH profile。
2. 保存配置和凭据引用。
3. 停止正在运行的会话。
   成功时，没有会话还在写入作品。
4. 在插件管理页卸载旧检索包、旧桌宠或旧 full 入口。
5. 按提示重启。保留备份，不要删除作品。
6. 用上面表格中的新包名安装。
7. 核对原有配置和启用状态。
   如果自定义 profile 覆盖里仍写着旧模块名称，按维护文档更新模块引用。不要改条目 id，也不要改凭据引用。
8. 确认主包和检索各只有一个有效入口，然后再继续写作。
   书稿不会因为改了包名就自动搬迁。

0.1.0-preview.7 / 旧提供方 0.0.9 对应 DSH 0.1.7-rc.2。8.2.0 对应 DSH 0.2.0-rc.2。旧版资料留在相应的 Release。不要把一个版本的说明套到另一个 DSH 上。

## 平台与测试范围

| 平台 | 已有验证 |
| --- | --- |
| Windows | Node 22/24 全量测试、构建、类型检查，以及发行包安装验证 |
| Linux | CI 包含公开检查、发行脚本测试，以及 Ubuntu 上的构建和全量测试观察任务 |
| macOS | 暂无可用的测试环境，尚未验证；这不代表不支持 |

Linux 运行时测试目前是观察任务，失败不会阻塞发行。它与 Windows 的安装验证范围不同。具体配置见 [CI 验证说明](../maintenance/ci.md)。
