# 安装 Scriptor 8.4.1

本版配套 **DSH 0.2.2-rc.3**。先安装这个桌面端，再在 DSH 里安装插件。

Scriptor 8.4.1 已适配 DSH **0.2.2-rc.3**。最低兼容版仍为0.2.2-rc.1，允许从该版本开始的0.2系列，包括后续预发布版本；0.3系列需重新适配。版本范围放宽不代表每个未来版本都已验证。命令行环境需要 Node.js 24.9或更高版本，桌面端使用自带运行时。

> [!NOTE]
> 桌面端自带运行时。
> 为了安装插件，不需要另装 Node.js 或 pnpm。

## 1. 打开插件管理

1. 从 [DSH 官网](https://www.deepseek.com/harness/) 安装 **DSH 0.2.2-rc.3**。
   成功时，桌面端可以打开。
2. 在侧栏选择 **插件**。
3. 点击 **添加插件**。
   成功时，页面出现安装标识输入框。

“官方”分组只列出 DSH 随附的插件。Scriptor 是另行安装的第三方插件。安装成功后，它出现在 **已安装** 分组。

## 2. 填入包名

首次使用只安装写作工作台。填写下表中的包名和精确版本。

> [!WARNING]
> 不要同时安装完整版和单独的写作包、检索包。
> 这两种入口只能二选一。重复安装会留下两个入口。

> [!CAUTION]
> 不要在应用变更时强行关闭程序。
> 先等安装完成。新版本刚发布时，镜像可能还没有同步。如果查不到包，切回官方 npm 再试。

1. 在添加插件的输入框粘贴下表中的完整标识。
2. 核对预览里的包名、版本和来源。
3. 确认安装。
   成功时，预览中的版本是8.4.1。

| 插件 | 输入框内容 | 用途 |
| --- | --- | --- |
| 写作工作台 | `@linfengqaqtat/dsh-scriptor@8.4.1` | 书房、设计、写章、审读、定稿与导出 |
| 检索增强（可选） | `@linfengqaqtat/dsh-scriptor-retrieval@8.4.1` | 嵌入、场景识别、重排，分别配置和启用 |
| 鲸鱼娘（可选） | `@linfengqaqtat/dsh-scriptor-companion@8.4.1` | 窗口内陪伴及会话状态反馈 |
| 完整版 | `@linfengqaqtat/dsh-scriptor-full@8.4.1` | 同时安装写作工作台与检索增强 |

优先选择官方npm。也可从本版Release下载对应 `.tgz`，核对SHA256后填写本地文件路径。完整版的主包和检索依赖仍需从npm下载。

## 3. 应用变更并核对

> [!NOTE]
> Windows 标题栏的关闭按钮可能只把程序藏进托盘。
> 需要重启时，从应用菜单完全退出，然后再打开。

1. 按插件管理器的提示启用插件。
2. 应用变更。如果页面要求重启，按上面的方式完全退出后再打开。
   成功时，已安装列表符合下面的结果。

- **写作工作台**：包名正确，版本为8.4.1。启用后可以打开书房。
- **检索增强**：可以找到嵌入、场景识别和重排配置。它们默认关闭。基础写作不必先填写这些项目。
- **鲸鱼娘**：界面出现角色。隐藏之后，可以从对应设置里恢复。

设置中的内置插件列表只用来查看状态。安装和卸载都使用侧栏“插件”页面。

## 4. 配置模型，开始第一本书

1. 在 DSH 中配置聊天模型和凭据。
2. 选择一个用来存放作品的工作区。
   成功时，会话显示这个工作区。

书仓的版本记录需要可用的 Git。如果桌面端提示缺少工具，按它的提示补齐。

然后阅读 [新手教程](beginner.md) 和 [第一本书与第一章](first-book.md)。12 个写作与维护技能随主插件提供。不需要另外安装技能。

开始写作前，新建对话并选择 **写作模式**。这个模式提供主编约定、写作技能和小说工具。其他预设保持 DSH 原来的用法。旧书用新的写作模式对话打开同一工作区。遇到旧格式诊断，先检查并预览整仓升级；安装不自动迁移文件或聊天。

## DSH兼容范围与已验证版本

8.4.1允许 `>=0.2.2-rc.1 <0.3.0-0`。推荐 DSH **0.2.2-rc.3**。最低兼容版 **0.2.2-rc.1** 也已验证。版本对应如下：

| DSH 版本 | 配套 Scriptor |
| --- | --- |
| 0.2.2-rc.3 | 8.4.1 |
| 0.2.2-rc.1 | 8.4.1（最低兼容版） |
| 0.2.2-rc.1 | 8.4.0 |
| 0.2.1-rc.3 | 8.3.2 |
| 0.2.1-rc.2 | 8.3.1 |
| 0.2.0-rc.2 | 8.2.2 |

旧版 preview.6 / 提供方 0.0.8 对应 0.1.5-rc.2。

DSH 接口会随版本变化。更高的 DSH 版本不代表已经兼容。

1. 安装或升级前，核对目标插件版本对应的 DSH。
2. 把插件和 DSH 一起更新。
   成功时，两边的版本与上面的对应关系一致。

## 从单装切换为完整版

完整版会安装同版写作工作台和检索增强。切换前先备份并停止当前实例。

> [!WARNING]
> 不要让完整版和单独安装的包同时存在。

1. 移除当前profile中单独安装的写作与检索入口。
2. 安装 `@linfengqaqtat/dsh-scriptor-full@8.4.1`。
3. 核对主包与检索各只有一个有效入口，再重启。

切回单装时，先移除full，再安装需要的单包。卸载不删除书仓和凭据，仍应保留切换前的备份。

## 从旧包升级

先阅读 [备份与升级](upgrade-backup.md)。旧检索包是 `webnovel-embedding-provider`。旧桌宠包是 `@linfengqaqtat/dsh-whale-companion`。

> [!WARNING]
> 不要让旧包名和新包名同时启用。

1. 备份工作区和当前 DSH profile。
2. 保存配置和凭据引用。
3. 停止正在运行的会话。
   成功时，没有会话还在写入作品。
4. 在插件管理页卸载旧检索包、旧桌宠或旧 full 入口。
5. 按提示重启。保留备份，不要删除作品。
6. 用上面表格中的新包名安装。
7. 核对原有配置和启用状态。
   如果自定义 profile 覆盖里仍写着旧模块名称，按维护文档更新模块引用。不要改条目 id，也不要改凭据引用。
8. 确认主包和检索各只有一个有效入口，然后再继续写作。
   书稿不会因为改了包名就自动搬迁。

0.1.0-preview.7 / 旧提供方 0.0.9 对应 DSH 0.1.7-rc.2。8.3.2 对应 DSH 0.2.1-rc.3。旧版资料留在相应的 Release。不要把一个版本的说明套到另一个 DSH 上。

## 平台与测试范围

| 平台 | 已有验证 |
| --- | --- |
| Windows | Node 22/24 全量测试、构建、类型检查，以及发行包安装验证 |
| Linux | Ubuntu 构建和全量测试是必需检查；通过后才允许合入发行源码 |
| macOS | CI 包含构建和全量测试观察任务，尚不等同于桌面安装验收 |

Linux 检查失败会阻塞合入。macOS 观察项的结果单独报告。两者与 Windows 的安装验证范围不同。具体配置见 [CI 验证说明](../maintenance/ci.md)。
