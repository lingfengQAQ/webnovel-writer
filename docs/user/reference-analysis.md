# 参考小说分析

Scriptor 8.1.0 可以导入本地 TXT 或 EPUB 2/3，按选定范围分批分析原作的事件、披露、人物知情、关系和节奏，整理带证据的机制。分析与目标作品的正式设定分开保存。

## 导入与开始

1. 在当前工作范围的对话中提供原文件的绝对路径，请工作台先预检。文件不能位于受管参考库内。原文件上限 64 MiB；无法确定 TXT 编码时，明确指定 UTF-8、UTF-16、GB18030 或 Big5，不靠猜测导入。
2. 核对章节目录与缺口，提供作品、作者、版本、取得来源、允许用途和依据，区分个人声明与可核对许可。预检与导入只处理本地文件，不向模型发送原文。
3. 选择要分析的章节或范围。工作台展示实际模型服务、范围和批次数；确认允许将这些原文发送到该服务后才开始分析。服务费用及数据保留政策由所选提供方决定。
4. 每次推进下一批。可以暂停后继续；已验证结果保留，失败批次不计入覆盖。范围、模型服务、原文件或处理条件变化时重新核对。
5. 生成报告，查看覆盖情况、观察、解释假设与待解问题。对感兴趣的机制查看短原文证据，再将新点子连同参考版本保存到灵感池。

例如：“预检这个本地 EPUB，列出可读章节和缺口，先不要分析。”核对后再说：“计划分析前三章，告诉我将发送给哪个模型服务。”

## 阅读结果与继续

部分章节分析完成不等于全书完成。目录缺失、无明确章界、非文字内容或脚注缺口会单独提示。EPUB 不处理 DRM；图片、公式等未解读内容不计为已经理解。

参考库保存在工作范围的 `书房/参考书/`。报告和机制可以在书房浏览；机制修改后，引用旧版本的点子会提示依据待核对。保存机制不会自动生成点子，保存点子也不会自动确认成目标书的事实。

中断后让工作台查询覆盖与批次状态，必要时显式恢复，再继续原计划。若原文件变化，对同一来源重新预检和导入；不要直接改参考库里的隐藏机器文件。

清除指定参考库只删除对应本地副本与分析，保留原文件和已保存的作者点子；点子的参考依据将显示不可用。清除不会删除已发送到模型服务端的数据。备份时包含书房，详见[数据流与隐私](privacy.md)及[升级备份](upgrade-backup.md)。
