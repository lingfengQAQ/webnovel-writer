# 参考小说分析

Scriptor 8.2.0 可以导入本地 TXT，或 EPUB 2/3。它按你选定的范围，分批分析原作的事件、披露、人物知情、关系和节奏，并整理带证据的机制。分析结果和目标作品的正式设定分开保存。

## 导入与开始

1. 在当前工作范围的对话里，提供原文件的绝对路径，并请工作台先预检。
   文件不能放在受管参考库里。原文件上限是 64 MiB。如果无法确定 TXT 编码，明确指定 UTF-8、UTF-16、GB18030 或 Big5。不要靠猜测来导入。
2. 核对章节目录和缺口。提供作品、作者、版本、取得来源、允许用途和依据。把个人声明和可以核对的许可分开。
   成功时，预检和导入只处理本地文件，不向模型发送原文。
3. 选择要分析的章节或范围。
   工作台会展示实际的模型服务、范围和批次数。你确认允许把这些原文发到该服务之后，才开始分析。服务费用和数据保留政策由所选提供方决定。
4. 每次只推进下一批。可以暂停后再继续。已经验证的结果会保留。失败的批次不计入覆盖。
   如果范围、模型服务、原文件或处理条件变了，重新核对。
5. 生成报告。查看覆盖情况、观察、解释假设和待解问题。
6. 对感兴趣的机制查看短的原文证据。再把新点子连同参考版本保存到灵感池。

例如，可以先说：“预检这个本地 EPUB，列出可读章节和缺口，先不要分析。”核对之后再说：“计划分析前三章，告诉我将发送给哪个模型服务。”

## 阅读结果与继续

部分章节分析完成，不等于全书完成。目录缺失、没有明确章界、非文字内容或脚注缺口，会单独提示。EPUB 不处理 DRM。图片、公式等还没有解读的内容，不算已经理解。

参考库保存在工作范围的 `书房/参考书/`。报告和机制可以在书房里浏览。机制修改之后，引用旧版本的点子会提示依据待核对。保存机制不会自动生成点子。保存点子也不会自动确认成目标书的事实。

1. 中断之后，让工作台查询覆盖和批次状态。
2. 必要时显式恢复。
3. 再继续原来的计划。
   如果原文件变了，对同一来源重新预检和导入。不要直接改参考库里的隐藏机器文件。

> [!NOTE]
> 清除指定参考库，只删除对应的本地副本和分析。
> 原文件和已经保存的作者点子会保留。点子的参考依据将显示为不可用。清除不会删除已经发送到模型服务端的数据。备份时要包含书房。详见 [数据流与隐私](privacy.md) 和 [升级备份](upgrade-backup.md)。
