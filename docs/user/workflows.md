# 日常写作与恢复

## 继续章节

明确书名和范围，例如“继续这本书的第2章，先核对进度”。工作台会读取实际书仓，再决定需要准备细纲、写稿、审读还是定稿。换会话无需手动重建一份当前章节状态表。

## 修改设计或正文

通过书房编辑器保存草稿、规划或世界书后，让工作台核对影响。保存文件、提交版本、工作台理解修改是三件不同的事。若保存时报告版本冲突，先重新读取当前文件，避免覆盖更新。

修改未定稿内容时可返回相关流程；涉及既有定稿的设定变化需要核对影响并走补偿/修订流程，不要直接改已确认的设计文件或手写账本来绕过检查。

## 审核失败或模型中断

先看失败来自正文问题、材料不足、配置/网络，还是作者意见。补足材料或修复服务后继续对应步骤。模型输出的一句“完成”不能替代实际审核记录或提交结果。

## 暂停

可明确要求暂停当前章。下次开始先核对文件与 Git 状态，已完成部分可继续使用；取消或失败不是对后续写入的批准。暂停期间不要在别处手工改动同一章的文件。

## 卷末

卷末先核对计划章节、定稿和未回收事项，再准备卷摘要候选，经核对后确认。窗口用尽不等于整卷完成；无法确定时应显示未知或待核对。开始下一卷前核实前卷沉淀与当前卷规划。

## 导出

指定书、卷/章节范围、目标目录和是否包含来源清单。先检查冲突再写出；导出应可重复核对，不应把草稿混入定稿。平台排版或发布仍由你审核，工作台不会代你向小说平台投稿。
