# 知识库（references/）

`v7/references/` 是随 installer 分发的正式通用创作知识库。运行时只读取明确声明的维度目录；候选材料、来源和策展裁决不进入本目录。

## 治理真源

- [维度宪章](../docs/knowledge/维度宪章.md)：十维目的、准入、排除、相邻边界和新增维度门槛。
- [调用者与字段矩阵](../docs/knowledge/调用者与字段矩阵.md)：谁在何时读取什么信息，以及该信息必须改变的行为。
- [策展规则](../docs/knowledge/策展规则.md)：新增、近重复、拆分、合并、移动、废弃、签收和架构变更流程。

条目的归属和字段必须能在上述文件中找到依据。治理文档与正式条目冲突时，先停止内容修改并按架构变更流程裁决。

## 目标结构

```text
references/
├── README.md
├── 路由.csv
├── 题材/
├── 流派/
├── 创意约束/
├── 设定/
├── 人物/
├── 命名/
├── 节拍/
├── 场景/
├── 技法/
└── 追读/
```

| 层级 | 维度 | 运行时用途 |
|---|---|---|
| 作品契约 | 题材、流派、创意约束 | 建书和重大改纲时形成本书作品契约 |
| 故事对象 | 设定、人物、命名 | 创建计划对象，正文定稿后转为事实 |
| 篇章执行 | 节拍、场景、技法、追读 | 细纲选择后供规划、落笔和审稿精准读取 |

`路由.csv` 只负责书级 canonical 名称、别名和兼容范围归一，不得自动决定具体创意、人物、剧情或章节方案。

## 当前基线

截至 2026-07-19，十维目录和运行时调用契约已生效。当前正式内容基线为 254 条：题材 19、流派 24、创意约束 11、设定 27、人物 28、命名 17、节拍 102、场景 16、追读 10；技法正式条目由篇章内容策展任务补充，空目录或无命中不会阻断创作。

这里不建立旧路径双读、旧 schema 兼容或历史书仓迁移器。运行时、installer、fixture 和测试只认本页列出的十维结构。

## 书级调用

- 作者构想明确时，用 `knowledge-pack --类型=<主题材> [--副题材=a,b] [--流派=a,b]` 归一名称并读取题材/流派材料；路由不会选择创意约束或作品方案。
- 快穿、种田只归流派；惊悚、恐怖、青春、校园、普通竞技和复合输入保持未命中，由建书对谈继续辨别。
- 只有真实创意问题未决时，才用 `knowledge-query --维度=创意约束 --问题=<问题>` 取最多三条材料；作者可组合、修改、拒绝或自定义。
- 有副题材时必须完成材料包中的题材融合协议检查。最终只保存作者确认的 `作品契约/作品契约.md`，下游不逐章回读通用书级条目。

题材与流派 front matter 只含 `名称`；创意约束只含 `名称 / 一句话`。别名与流派兼容范围只在 `路由.csv` 保存，空兼容范围表示无需窄范围提醒。

## 故事对象调用

- 只有对象需要跨章复用或影响一致性时，才用 `knowledge-query --维度=设定|人物|命名 --问题=<未决问题> [--类型=<受控子类>]` 取最多三条方法材料；一次性路人、普通物品和临时地点不强制建档。
- 设定、人物、命名 front matter 分别只含 `名称 / 对象类型 / 一句话`、`名称 / 人物类别 / 一句话`、`名称 / 命名对象 / 一句话`；正文只含 `规划时`，没有无人读取的落笔或审稿切片。
- 选定方法须转成作者确认的 `本书设计 / 一致性边界`，可把来源和本书适配写入 `知识依据`；普通未选候选不保存。
- 命名结果附着在书名或计划对象上。写作、审稿和事实转正只精准读取本书计划对象与定稿事实，不回读通用故事对象条目。

## 内容纪律

- 每条正式知识只有一个 canonical 路径；跨维使用通过组合或拆分解决，不复制文件。
- 只写可迁移原理、操作方法、边界和失败模式，不写可直接复刻的成品剧情模板。
- front matter 只保留有真实消费者和行为测试的机器信息；通用适用范围省略，不写无信息量的“全部”。
- 固定路由只归一名称和候选范围；软策略必须允许选择、混合、修改、拒绝和自定义。
- 格式由测试机器校验；内容质量和边界由开发阶段逐条独立审查。
