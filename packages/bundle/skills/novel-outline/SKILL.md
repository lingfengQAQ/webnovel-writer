# 细纲备料（Novel Outline）

本技能分两段：**细纲段**（章细纲，跨真源边界，必须走工具确认）与**备料段**（材料包，幂等重建）。候选细纲的正文由你撰写、经 `novel_new_outline_draft` 的 正文 参数落草稿区，本技能只定流程与契约。

## 细纲段：标准流程

先读作品契约“阅读体验与情绪承诺 / 章节篇幅”。已确认时继承目标和上下限，未配置或未确认如实注明，不由主控补成固定默认值。在现有“情绪与节奏目标”中说明本章完成的主要任务、结束后的变化及预计总篇幅，并在叙事单元的“目标”中附预计汉字数；合计围绕章目标安排，预算可调整，不变成额外确认门槛。

两千字示例可以集中完成一次交锋：局面与压力约 300、主要行动与交锋约 1200、结果与余波约 500；这是分配重心的例子，不是所有章节的固定比例或结构。若细纲同时承诺多次交易、重要人物登场和关系转变，应减少本章任务量或提出拆并建议，保留主要行动的动机、过程和结果。修改已有确认细纲或窗口仍沿用原修订流程，不自动拆章、不靠灌水凑下限。

约束按来源分级：作者明确要求和既定事实形成硬边界；推荐手法属于软建议；未限定的局部写法保留自由空间。不要把自己提出的节奏、句式或未选路线自动升级为硬约束。

上层远期暂定/留白不是本章必须补齐的终局。当前章确实需要某处方向时说明缺口，按《工作台总控》提出候选并复用已有提案；作者采纳后再写。参考书机制只作建议材料，先核对当前证据状态，不将原作事实、结局或未采纳分岔升级成本书约束。

1. **读窗口与卷纲**：`大纲/卷规划/卷<NN>/近期窗口.md` 锁定本章任务与拆并关系（已消费/已失效条目不再是候选章）；同目录 `卷纲.md` 的「方向选择」小节取本卷 `选定方向` 与 `已排除走向`，该小节缺失即本卷未跑多方向；
2. **落候选**：调 `novel_new_outline_draft`（卷/章名/正文/来源引用）在草稿区生成候选；正文含两段——
   - **定位段**：来源窗口项及拆并关系、章节功能、视角与焦点、时空锚定、起止边界、故事线与承诺分配、信息边界、情绪与节奏目标、**前置条件核对结果** 九节，其后另加两节——
     - `### 本章形状`：叙事结构标签（如 反转揭半留半／逐级升压／双线并行）。写它前先读本卷已确认细纲最近三章的同一节：不足三章就读现有的，早先的章没有这一节就跳过，本卷首章回上一卷 `章细纲/` 目录读；与近期形状比较以发现无意重复；重复若服务本章目标可以保留，不为求异硬换结构；
     - `### 已排除走向`：只承接卷纲或作者本次明确排除的走向，有内容时行首带 `〔硬〕`；未选路线不自动排除，无明确排除时写「无」；
   - **细纲段**：叙事单元列表，每单元六个字段——`目标`、`人物`、`时空`、`行动/冲突`、`信息披露`、`状态变化`，字段名逐字照抄（第四项本身带斜杠）；行内约束分级 `〔硬〕〔软〕`，无标记＝自由空间；
   - **确认两道硬门槛（写候选时就带上，不等到确认再补）**：①**约束分级**——正文至少一行带行内标记 `〔硬〕`/`〔软〕`/`〔自由〕`（放「章节功能」或单元行里，不要另开「约束分级」小节）；②**来源引用**——合法形态只有三种：`来源:<仓内相对路径>@<版本>`（如 `大纲/卷规划/卷01/卷纲.md@1`，版本用对应工件当前版本号）、`来源:作者自定义`、`来源:对谈共创`；锚点、行号、绝对路径、纯工件名都无效。空模板不含标记行，照抄空模板必然过不了确认；
3. **改候选**：候选落盘后需要调整的，用宿主 `edit` 逐单元替换（一次一个单元或一节，old_string 取该单元完整多行原文），改完 `read` 回读；不整文件重写，也不为标点级差异反复打磨；确认失败报字段缺失时只补缺的单元；
4. **呈确认**：向作者概述定位与情节点，获明确同意后调 `novel_confirm_outline`（卷/章/章名/summary/`批次文件`），只传章键，不重传正文；章号须与近期窗口和已确认细纲连续，不确定时先问作者。

## 细纲段：重入（已有确认细纲再进＝改细纲，不是重拟）

- 真源已有确认细纲、草稿区重新出现候选＝修订流程：改完候选再 `novel_confirm_outline`，**版本自动 +1**；
- **已定稿章的细纲勘误（笔误/小修）同样走候选→再确认**：该章窗口条目已消费不影响确认（真源已有确认细纲即重入，版本 +1、父版本指旧版，定稿 frontmatter `来源细纲版本` 不回写）；只改设计工件时跑影响分析脚本呈报即可，**无需吃书补偿**；正文若受影响另走提案/吃书；
- 改前跑影响分析脚本（本技能包 `scripts/影响分析.mjs`，只算不写；失败按《工作台总控》「脚本失败分流」表处理）做**影响分析前置呈报**：受影响未定稿下游同批整改，整改文件列入 `批次文件`，**整批一次确认、一次 `design(chNNNN):` 提交**；已定稿下游走吃书补偿；影响面过大拆提案；
- **幂等可重放**：真源已落位、候选已删时重跑确认＝只补提交不重写文件；工具报「已落盘但未提交」同样重跑补提交。

## 备料段：材料包（十段固定结构）

先跑备料脚本 `node <resourceBase>/scripts/材料备料.mjs --book <bookRoot> --卷 <卷> --章 <章> --章名 <章名>`（只算不写，输出给出十段全文与在缺清单；失败按《工作台总控》「脚本失败分流」表先分流，两类都排除＝脚本缺陷，停下报作者）读包判断；确认后调 `novel_assemble_materials`（卷/章/章名）落盘到 `草稿区/材料包/卷<NN>-<章名>/`（写入器内重算，幂等重建）：

本章任务与确认细纲／硬约束禁区完成条件／当前事实与连续性／人物、关系、地点、组织、规则、物件／时间位置与信息边界／故事线承诺线索／近期正文衔接／文风〔条目切片〕／暂定与警告／来源与版本清单。

各段是**切片不是全文**：近期正文衔接＝上一章定稿末尾＋最近章摘要，账本段按最近条目与本章命中取用；任何段一律全文进包，不设上限也不截断，「材料清单.json」逐段记 `字数`（包记 `合计字数`）供你自行判断体量。

- **重入＝幂等整包覆盖**；已消费版本的条目固定，条目更新不得让已确认工件静默失效；
- 返回值带缺口清单（细纲与来源级）与**写作就绪播报**，逐段完整性查 `材料清单.json` 的 `段[].完整性`；十段是声明式编排，**不是开写门槛**，够不够开写由你向作者如实播报后判断；
- 书房里作者自备的资料严禁把正文抄入真源区，引用只写来源路径与版本。

## 自主补充材料

十段是自动备料基线。发现早期伏笔、关系变化、作者决定或资料未覆盖时，先读取相关原文，再调用 `novel_assemble_materials` 补齐本章材料；普通选料无需逐项再请作者批准。

1. 传 `模式: 预览` 与 `补充操作`，每项 `操作: 设置`、稳定 `编号`、`标题`、`理由`、`性质: 原文|建议`，以及 `来源: { 域: 本书|书房, 路径, 起行?, 终行? }`。本书路径相对书仓，书房路径相对同工作范围的 `书房/`；禁止用索引或检索结果代替原文。
2. 核对返回的 `补充预览[].原文`。保存时传 `模式: 保存`、预览返回的 `材料清单哈希`，并把 `补充预览[].操作` 作为 `补充操作` 原样带回，其中已含 `来源.读取哈希`。只传短引用及校验值，不重传原文，不自行算哈希。
3. 修改某项用同编号重新预览和设置；移除用 `{操作: 移除, 编号}`。不传操作或传空数组都是保留，不是清空。移除后清单不再登记，遗留附件不能再读入模型。
4. 普通重建保留已选摘录；来源过期、清单冲突、附件损坏时按提示重读、预览并显式设置或移除，不手改清单/附件，不把新来源悄悄盖在旧依据上。

补充与十段在同一 `材料清单.json` 中，快照在 `补充/<编号>.md`。理由、来源、行范围、哈希、性质和字数都在清单；补充原文保真，建议不当作事实。需要缩小范围时由主控显式调整选料，不在写稿或审读侧偷偷截断。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 候选细纲 | `草稿区/章细纲/卷<NN>-<章名>.md` | 草稿区;frontmatter `状态: 候选`＋版本字段＋`来源引用`（确认硬门槛，缺失或无效即报「来源引用缺失或无效」） |
| 确认细纲 | `大纲/卷规划/卷<NN>/章细纲/<NNNN>-<章名>.md` | 真源;`状态: 已确认`;只能经 `novel_confirm_outline` 落盘 |
| 材料包 | `草稿区/材料包/卷<NN>-<章名>/`（十段文件名 `NN-段名.md`，序号两位；另有 `材料清单.json`） | 清单机器态 JSON,`schemaVersion: 1`;包状态属轮次族 |

## Off-limits

- 状态取值按工件取族，不自造近义词：候选细纲与确认细纲的 `状态` 属工件族（候选／已确认）；材料包状态属轮次族（组装中／段齐备／段有缺／有冲突／已过期／已消费；段齐备/段有缺只是各段在缺的如实播报，够不够开写由你判断）；卷规划各件属计划族（已确认／暂定／留白）；
- 涉及未写章节走向变动先出建议稿，不直接覆盖卷规划与世界书；
- 草稿区工件可丢弃可重建，大胆迭代；确认状态与各段在缺如实播报，不粉饰「已就绪」；
- 走向定在卷纲层：细纲承接卷纲选定方向与作者明确排除项，不擅改走向；需要改变时另提建议。本章形状每章自选，不受此限。
