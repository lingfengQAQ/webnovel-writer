# 定稿沉淀（Novel Settle）

向作者呈报字数时，读取本次备包 `正文.md` 的 `字数统计.汉字数`；字符数须另标口径。不得沿用起草、润色或旧稿审读报告中的估数。该统计与审读脚本共用正文计数规则，不含 frontmatter 和草稿候选事实；换稿须重算。

本章的收束节点，次序不可颠倒：**先完整呈报，再作者裁决，后原子沉淀**。未完整呈报、未获作者明确批准，严禁调用 `novel_settle_chapter`——调用即弹作者裁决弹窗，裁决记录由裁决通道生成、不经你手，你没有任何参数可以替作者答。

## 标准流程

事实沉淀汇报若发现人物选择或结果改变上层前提，可按《工作台总控》说明证据并提出少量候选，先复用已有待裁决提案；无新依据不重复建议。每章不机械重写上层，未采纳候选不使旧计划失效。入档后停止的边界不变。

1. **派沉淀子代理**（审核完成后、组包前）：按文末模板组装任务包——`底本/沉淀对账.md` 全文＋待审稿正文与候选事实段＋确认细纲定位段＋材料包「当前事实与连续性」「故事线承诺线索」两段＋计划时间线本卷条目，材料全部内联；子代理返回五段 Markdown（时间线变更/账本变更/本书层记忆候选/章摘要/事实变更）；
2. **组包**：先跑备包脚本 `node <resourceBase>/scripts/定稿备包.mjs --book <bookRoot> --卷 <卷> --章 <章> --章名 <章名>`（只算不写，输出给出七件全文；失败按《工作台总控》「脚本失败分流」表处理）逐件预览；确认后调 `novel_prepare_pack`（卷/章/章名＋沉淀候选五个字段）落盘七件到 `草稿区/定稿准备/卷<NN>-<章名>/`——正文 / 事实变更 / 时间线变更 / 账本变更 / 章摘要 / 卷对账 / 本书层记忆候选。候选逐段预校验，失败返回解析器原话：按原因修正候选后重调，同一原因修正后最多补试一次，仍失败就报告；不同格式问题逐项核对，不无变化地循环重调（组包幂等重建）；**子代理某段整段留空就不传那个字段**，传占位文字会被判「存在未分类正文」整批拒。前置：存在唯一待审稿。组包后逐件审阅：`正文.md` 的 frontmatter 是否完整、无候选的件是否是占位、卷对账有无偏离；
3. **呈报裁决**：向作者呈报——正文完成度与字数;事实/时间线/账本变更摘要（无变更如实说无）;**卷对账偏离项**（有偏离讲清楚不掩盖）。偏离处置结论调 `novel_record_memory` 写作者层记忆（书房，`类: 决策`；`标签` 里的书名要逐字用书仓目录名或 bookId，另带本卷；正文里逐字带上偏离项名）——进度卡靠这两条对上才扣减未决偏离，少一条就静默不扣。明确请求裁决：批准入档，或退回修改；
4. **沉淀**：作者明确批准后调 `novel_settle_chapter`（卷/章/章名/summary）——按清单原子写入＋账本/时间线/本书层记忆/世界书事实经沉淀服务同步＋**单次 Git 提交（ch: 前缀）**；写入阶段失败会整体回滚不留半截；提交阶段失败则文件已落位、未形成提交，原样重跑本工具即可补提交（会再弹一次作者裁决；见 Off-limits 末条）。近期窗口的「已消费」标记不在这一步，另调 `novel_roll_window`（自带 `design:` 提交）。完成后播报入档清单与新近况；本章入档后停止；本次委托已包含的窗口已消费标记可完成，补充新窗口或开启下一章等待作者委托。

```markdown
【沉淀对账任务：第 X 卷 第 Y 章《章名》】

=== 第一部分：你的对账底本 ===
<粘贴 底本/沉淀对账.md 全文>

=== 第二部分：参考材料 ===
- 确认细纲定位段与本章相关叙事单元：<粘贴>
- 材料包「当前事实与连续性」段：<粘贴>
- 材料包「故事线承诺线索」段：<粘贴>
- 计划时间线本卷条目：<粘贴>
- 作者已给处置与例外：<粘贴本次适用决定，无则写无>
- 定稿章来源标识：<按本章身份提供仓内相对标识，用于记忆引用，不授权读写文件>
- 世界书模块清单：<粘贴 世界书/模块声明.md 全文——事实变更段的 `##` 只能从这张清单里选，选不进的写进章摘要末行待归模块>

=== 第三部分：待审稿正文与候选事实段 ===
```

## 作者介入

组包前主控须做一次独立语义核对：逐条确认“主体／时点／原文证据／事实或证言或推测或规则”，核对同名账本是不是同一对象、作者已给的例外有没有落实。将这份简短核对结果随候选摘要呈报；不把哈希完整、格式通过或审核正文通过当成沉淀语义通过。未经正文支持的通用规则不入包，没有推进的旧线索不重写。

- 作者能做什么：呈报后改沉淀候选任何一条、补事实、删记忆候选；
- 用哪个通道：直接向你说，你按作者意见改候选后重调 `novel_prepare_pack`，再呈报；
- 主 Agent 接到后：不入档前可反复改候选重组包；入档后的事实更正走吃书补偿通道（`retcon:`，工具入口 `novel_apply_retcon`），不在组包里做。

## 重入（退回后重组包）

- 作者退回：**删掉待定稿包目录**（草稿区可弃可重建），位置随即退回，按根因回对应节点（局部问题→改稿;定位/结构问题→细纲;上游设定问题→按提案回路回上游）；不手写 `清单.json` 的 `裁决` 字段；
- 改完重新调 `novel_prepare_pack`（组包幂等重建）；
- **每次入档都要重新获批**：重新呈报，再调 `novel_settle_chapter` 会重新弹一次裁决，一次调用一份新记录，没有可复用的旧批准。

## 卷末与卷摘要（当前卷收束后）

本卷已定稿章齐、卷对账处置完毕后，卷摘要走「候选→确认落盘」：

1. **候选（只算不写）**：跑 `node <resourceBase>/scripts/卷摘要候选.mjs --book <bookRoot> --卷 <卷>`——读本卷已定稿章的章摘要全文、账本已收/进行中线索、卷纲「卷末兑现」段汇编候选（JSON，`候选` 字段）；任一已定稿章缺章摘要即如实报缺（`ok:false`＋`缺章摘要`），不产候选更不落盘——先补齐章摘要再跑；
2. **呈报**：候选与对账状态一并呈作者——卷对账 `待核对` 非空时，候选与呈报都不得写「无偏离」「已兑现」；候选是汇编不是创作判断，作者可改任何字；
3. **确认落盘**：作者明确同意后调 `novel_confirm_volume_outline`（卷、`目标: 卷摘要`、正文）落真源 `大纲/卷规划/卷<NN>/卷摘要.md`——版本协议沿用（首次 v1、再确认版本 +1／父版本指旧版、原样重跑复用版本），随 `design:` 提交；不设上限、不截断；
4. 卷摘要落盘后是该卷权威摘要：下一卷首章备料的「近期正文衔接」自动带它（整文件），本卷后续章材料按章号边界切片；修订同样走候选→再确认，不手写真源。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 待定稿包 | `草稿区/定稿准备/卷<NN>-<章名>/`（七件＋`清单.json`） | 清单机器态 JSON,`schemaVersion: 1`,逐文件 sha256;另有 `裁决` 字段（`已批准`／`已退回`）是推导读的机器面——**不由你写**;卷对账是轮次工件不入档 |
| 定稿章 | `定稿/卷<NN>/<NNNN>-<章名>.md` | 真源,只增不改 |
| 章摘要 | `大纲/卷规划/卷<NN>/章摘要/<NNNN>-<章名>.md` | 真源,与定稿章同批写入,同样只增不改 |
| 作者层记忆条目 | `<工作范围>/书房/作者记忆/<名称>.md` | 一事一文件;`名称`／`描述`／`类`／`标签`／`来源` 全必填;`类` 取 决策（偏离处置）;不入书仓 git |

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| `novel_prepare_pack` | 审核完成后组装呈报 | 存在多份待审稿时组包（先裁定唯一） |
| `novel_record_memory` | 偏离处置结论当场记 | 把账本已登记的事实抄进记忆 |
| `novel_settle_chapter` | 完整呈报之后一次调用（调用即弹裁决） | 未呈报就调用;想覆盖已入档章（更正走 `novel_apply_retcon`）;把 `裁决记录` 当参数传 |
| `novel_apply_retcon` | 已定稿内容更正：提案回路走完（影响分析已呈报、作者已在对话中批准）后调用，调用即弹裁决 | 未走完提案回路就调用;拿它当退回修改的捷径;当成撤销用（历史经补偿事件留痕，不是撤销） |

## Off-limits

- 定稿区只增不改：写错的事实走「吃书补偿（retcon:）」更正通道，不直接改定稿。吃书补偿是两个裁决点之一，须作者批准，只整条替换既有条目、目标不存在即拒，是「只增不改」的唯一例外；**工具入口是 `novel_apply_retcon`**（前置：影响分析已呈报、作者已在对话中批准；调用即弹作者裁决，作者退回即拒），未走完提案回路不要调；
- `清单.json` 的 `裁决` 字段不由你写：`已批准` 是作者裁决的机器面，手写它等于替作者拍板；
- 账本与本书层记忆只有一条写入路径——沉淀服务，严禁手工编辑账本文件；
- 章号全书连续：与其他卷撞号会被拒绝，换号重报；
- 提交失败返回可读原因时，七件已落位、账本与世界书已同步、未形成提交：**原样重跑 `novel_settle_chapter` 即可补提交**（会再弹一次作者裁决；落盘内容与待写逐字节一致就幂等放行，命中已完成则不重复提交）；若目标已被作者改出不同内容则仍被拒绝，如实把这一状态报给作者，别重写文件也别改定稿。
