# 定稿沉淀（Novel Settle）

本节点是本章的收束节点。次序不可颠倒：**先完整呈报，再作者裁决，后原子沉淀**。

派发对账使用 `novel_delegate`，传 `role: settle`。运行时只向该实例注入沉淀对账规约和只读权限；仍须交接完整底本和本章材料，候选不直接写入账本或真源。

> [!WARNING]
> 完整呈报后调用 `novel_settle_chapter`，由工具弹出作者裁决窗口。
> 未获作者明确批准，严禁入档。定稿与留档清单在该次裁决中确认；裁决记录由通道生成。
> 你没有任何参数可以替作者回答。

## 字数口径

- 向作者呈报字数时，读取本次备包 `正文.md` 的 `字数统计.汉字数`。
- 字符数必须另外标明口径。
- 不得沿用起草、润色或旧稿审读报告中的估数。
- 该统计与审读脚本共用正文计数规则。它不含 frontmatter 和草稿候选事实。
- 换稿后必须重算。

## 上层前提变化

事实沉淀汇报可能发现：人物选择或结果改变了上层前提。这时：

1. 按《工作台总控》说明证据，提出少量候选。

2. 先复用已有的待裁决提案。没有新依据时，不重复建议。

3. 不要每章机械重写上层。未采纳的候选不会让旧计划失效。

4. 入档后停止的边界不变。

## 标准流程

### 第 1 步：派沉淀子代理

时机：审核完成后、组包前。

1. 按文末模板组装任务包。材料全部内联：
   - `底本/沉淀对账.md` 全文；
   - 待审稿正文与候选事实段；
   - 确认细纲定位段；
   - 材料包「当前事实与连续性」「故事线承诺线索」两段；
   - 计划时间线本卷条目；
   - 本次相关的既有本书记忆全文。先按索引定位并读取，用于查重和保留旧结论。

2. 子代理返回五段 Markdown：
   时间线变更、账本变更、本书层记忆候选、章摘要、事实变更。

### 第 2 步：组包

前置条件：存在唯一待审稿。

1. 运行备包脚本，逐件预览：
   `node <resourceBase>/scripts/定稿备包.mjs --book <bookRoot> --卷 <卷> --章 <章> --章名 <章名>`
   - 脚本只算不写，输出七件全文。
   - 脚本失败时，按《工作台总控》「脚本失败分流」表处理。

2. 确认后调用 `novel_prepare_pack`。
   - 参数：卷、章、章名，加沉淀候选五个字段。
   - 记忆候选可以为空。条目声明 `操作：新增` 或 `操作：更新`。
   - 更新候选还须传 `记忆原文`：以条目名称为键，值为主控已读的完整旧文，含 frontmatter。不要让子代理猜旧文或计算哈希。
   - 工具报告原文变化时，重读并核对候选；不改名新增。已有相同结论不重复放入包内。
   - 工具把七件写到 `草稿区/定稿准备/卷<NN>-<章名>/`。
   - 七件：正文、事实变更、时间线变更、账本变更、章摘要、卷对账、本书层记忆候选。
   - 同次采集本章草稿目录的来源稿、旧稿和起草暂存，形成 `清单.json` 的 `草稿留档`。未选用风险稿仍可列为留档，不因此提升为待审稿。

3. 工具逐段预校验候选。失败时返回解析器原话（含行号和合法值）。
   - 按报错的修正方法改候选，再重调。
   - 同一原因修正后最多补试一次。仍然失败就报告作者。
   - 不同的格式问题逐项核对。不要原样循环重调（组包幂等重建）。

4. **子代理某段整段留空时，不传那个字段。**
   - 传占位文字时，解析器判为「存在未分类正文」，整批拒绝。

5. 组包后逐件审阅：
   - `正文.md` 的 frontmatter 是否完整；
   - 没有候选的件是否是占位；
   - 卷对账有没有偏离。
   - `草稿留档` 是否列出本章来源稿及当前全部草稿、起草暂存。准备后目录变化时，重新准备并呈报，不手改清单或 `草稿留档摘要`。

### 第 3 步：呈报裁决

1. 向作者呈报以下内容：
   - 正文完成度与字数；
   - 事实、时间线、账本变更摘要。没有变更就如实说没有；
   - **卷对账偏离项**。有偏离就讲清楚，不要掩盖。
   - 来源稿和完整留档列表，说明半稿及未选稿只作本章历史留档，保留原文。确认后新出现或变化的稿件仍会进入核对。

2. 作者对偏离给出明确处置后，保留后续进度判断需要的结论：
   - 先查同一事项的既有记忆。已记录且没有变化就不再写。
   - 调用 `novel_record_memory`，传 `scope: book`、`bookId`、`类: 决策`。新事项传 `操作: 新增`；更新须先读旧文并传 `原文`。
   - 正文里逐字带上偏离项名。
   - 进度卡读取本书决定；缺少偏离项名时不会扣减未决偏离。旧作者条目只在明确标记本书时兼容读取。
   - 作者在第 4 步选择「退回」时，确认处置是否仍有效。无效时按作者意见更新原条目，不另开一条冲突记录。

3. 呈报完毕后进入第 4 步的工具裁决：批准入档及本次留档清单，或退回修改。作者已委托定稿时，无须在工具问答前额外询问是否执行。

### 第 4 步：沉淀

1. 调用 `novel_settle_chapter`。参数：卷、章、章名、summary。工具先复验备包和留档清单，再在同一次作者问答中请求明确批准。

2. 工具按清单原子写入，并完成：
   - 账本、时间线、本书层记忆、世界书事实经沉淀服务同步；
   - **单次 Git 提交（ch: 前缀）**。
   - 定稿元数据绑定本次留档清单，草稿原文仍保留在草稿区，不加入 Git。批准等待期间包或草稿变化时，旧批准失效。

3. 失败时的处理：
   - 写入阶段失败：整体回滚，不留半截。
   - 提交阶段失败：文件已落位，未形成提交。保留原包、草稿与收据，处理原因后按原参数补交；不重新采集或扩大清单。
   - 补提交会再弹一次作者裁决（见 Off-limits 末条）。

4. 近期窗口的「已消费」标记不在这一步。
   - 另外调用 `novel_roll_window`。它自带 `design:` 提交。

5. 完成后播报入档清单与新近况。

6. 本章入档后停止。
   - 本次委托已包含的窗口已消费标记可以完成。
   - 补充新窗口或开启下一章，要等作者委托。

## 沉淀子代理派发模板（材料全部内联，不提供书仓访问路径）

```markdown

=== 第一部分：你的对账底本 ===
<粘贴 底本/沉淀对账.md 全文>

=== 第二部分：参考材料 ===
- 确认细纲定位段与本章相关叙事单元：<粘贴>
- 材料包「当前事实与连续性」段：<粘贴>
- 材料包「故事线承诺线索」段：<粘贴>
- 计划时间线本卷条目：<粘贴>
- 作者已给处置与例外：<粘贴本次适用决定，无则写无>
- 相关既有本书记忆：<粘贴已读条目全文，含名称；没有相关条目写无，不把未知写成无>
- 定稿章来源标识：<按本章身份提供仓内相对标识，用于记忆引用，不授权读写文件>
- 世界书模块清单：<粘贴 世界书/模块声明.md 全文——事实变更段的 `##` 只能从这张清单里选，选不进的写进章摘要末行待归模块>

=== 第三部分：待审稿正文与候选事实段 ===
<粘贴 草稿区/草稿/卷NN-章名/稿N.md 全文>

【输出要求】
按底本「输出格式」逐字对齐，输出五段。格式错误会导致整批拒绝。
```

## 作者介入

组包前，主控必须做一次独立语义核对：

1. 逐条确认“主体／时点／原文证据／事实或证言或推测或规则”。

2. 核对同名账本是不是同一对象。

3. 核对作者已给的例外有没有落实。

4. 把这份简短核对结果随候选摘要一起呈报。

注意：

- 哈希完整、格式通过或审核正文通过，不等于沉淀语义通过。
- 没有正文支持的通用规则不入包。
- 没有推进的旧线索不重写。

作者介入的方式：

- 作者能做什么：呈报后修改任何一条沉淀候选、补事实、删记忆候选；
- 用哪个通道：作者直接告诉你。你按作者意见改候选，重调 `novel_prepare_pack`，再呈报；
- 主控接到后：入档前可以反复改候选、重组包。入档后的事实更正走吃书补偿通道（`retcon:`，工具入口 `novel_apply_retcon`），不在组包里做。

## 重入（退回后重组包）

1. 作者退回时，工具已在 `清单.json` 记「已退回」，位置自动回到改稿等节点。不需要删除待定稿包；改完重新组包会整包重建，清掉旧裁决。

2. 按根因回到对应节点：

   | 根因 | 回到 |
   |---|---|
   | 局部问题 | 改稿 |
   | 定位或结构问题 | 细纲 |
   | 上游设定问题 | 按提案回路回上游 |

3. 不要手写 `清单.json` 的 `裁决` 字段。

4. 改完后重新调用 `novel_prepare_pack`（组包幂等重建）。

5. **每次入档都要重新获批。**
   - 重新呈报，再调用 `novel_settle_chapter`。它会重新弹一次裁决。
   - 一次调用产生一份新记录。没有可复用的旧批准。

旧章节没有留档证据，需将当前半稿或未选稿确认为历史留档时，加载 `novel-maintenance`，走专门的预览和确认。不能重新定稿、手改摘要或删除历史稿来代替该确认。

## 卷末与卷摘要（当前卷收束后）

前置条件：本卷已定稿章齐全，卷对账处置完毕。卷摘要走「候选→确认落盘」：

1. **候选（只算不写）**：运行 `node <resourceBase>/scripts/卷摘要候选.mjs --book <bookRoot> --卷 <卷>`。
   - 脚本读取：本卷已定稿章的章摘要全文、账本中已收和进行中的线索、卷纲「卷末兑现」段。
   - 输出 JSON，候选在 `候选` 字段。
   - 任一已定稿章缺章摘要时，脚本如实报缺（`ok:false` 加 `缺章摘要`），不产候选，也不落盘。先补齐章摘要再运行。

2. **呈报**：把候选与对账状态一起呈给作者。
   - 卷对账 `待核对` 非空时，候选与呈报都不得写「无偏离」「已兑现」。
   - 候选是汇编，不是创作判断。作者可以改任何字。

3. **确认落盘**：作者明确批准后，调用 `novel_confirm_volume_outline`。
   - 参数：卷、`目标: 卷摘要`、正文。
   - 落到真源 `大纲/卷规划/卷<NN>/卷摘要.md`，随 `design:` 提交。
   - 版本协议沿用：首次 v1；再确认时版本 +1，父版本指向旧版；原样重跑复用版本。
   - 不设上限、不截断。

4. 卷摘要落盘后是该卷的权威摘要。
   - 下一卷首章备料的「近期正文衔接」自动带上它（整文件）。
   - 本卷后续章材料按章号边界切片。
   - 修订同样走候选→再确认，不要手写真源。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 待定稿包 | `草稿区/定稿准备/卷<NN>-<章名>/`（七件加 `清单.json`） | 清单是机器态 JSON，`schemaVersion: 1`，逐文件 sha256。卷对账是轮次工件，不入档 |
| 待定稿包的 `裁决` 字段 | `清单.json` | 取值 `已批准`／`已退回`，供推导读取。**不由你写** |
| 定稿章 | `定稿/卷<NN>/<NNNN>-<章名>.md` | 真源，只增不改 |
| 章摘要 | `大纲/卷规划/卷<NN>/章摘要/<NNNN>-<章名>.md` | 真源，与定稿章同批写入，只增不改 |
| 本书处置记忆 | `<书仓>/本书记忆/<名称>.md` | 一事一文件，与索引同批保存并留存版本 |
| 记忆字段 | 同上 | 名称、描述、类、来源、正文必填，标签可选；偏离处置的类取决策，更新另传完整原文 |

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| `novel_prepare_pack` | 审核完成后组装呈报 | 存在多份待审稿时组包（先裁定唯一） |
| `novel_record_memory` | 保存尚未留存的本书处置，或更新同一事项 | 把本书决定存到作者层；把账本事实或讨论流水抄进记忆 |
| `novel_settle_chapter` | 完整呈报之后调用一次（调用即弹裁决） | 未呈报就调用；覆盖已入档章（更正走 `novel_apply_retcon`）；把 `裁决记录` 当参数传 |
| `novel_apply_retcon` | 更正已定稿内容。前置：提案回路走完，影响分析已呈报，作者已在对话中批准。调用即弹裁决 | 未走完提案回路就调用；当作退回修改的捷径；当作撤销（历史经补偿事件留痕） |

## Off-limits

- 定稿区只增不改。写错的事实走「吃书补偿（retcon:）」更正通道，不直接改定稿。
  - 吃书补偿是两个裁决点之一，必须经作者批准。
  - 它只整条替换既有条目。目标不存在时，工具拒绝。
  - 它是「只增不改」的唯一例外。**工具入口是 `novel_apply_retcon`。**
  - 前置：影响分析已呈报，作者已在对话中批准。调用即弹作者裁决，作者退回即拒。
  - 未走完提案回路，不要调用。
- `清单.json` 的 `裁决` 字段不由你写。`已批准` 是作者裁决的机器面，手写它等于替作者拍板。
- 账本只经沉淀服务写入。本书记忆在对谈中走记忆工具，定稿候选随沉淀同批写入；两者都不得用通用写工具绕过。
- 章号全书连续。与其他卷撞号时，工具拒绝。换号后重新呈报。
- 提交失败并返回可读原因时，七件已落位，账本与世界书已同步，但未形成提交：
  - **原样重跑 `novel_settle_chapter` 即可补提交。** 它会再弹一次作者裁决。
  - 落盘内容与待写内容逐字节一致时，工具幂等放行。命中已完成时，不重复提交。
  - 如果作者已把目标改成不同内容，工具仍然拒绝。把这一状态如实报给作者。不要重写文件，也不要改定稿。
