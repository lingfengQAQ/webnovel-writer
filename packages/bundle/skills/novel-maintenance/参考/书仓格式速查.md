# 书仓格式速查

本参考解释常见字段结构、版本含义和只读环境排查。它不是整份书仓模板。字段对应当前解析与升级规则；能否升级仍以本书的只读检查和精确预览为准。

查格式时读本参考，查归属时读目标书的实际证据。不得为寻找格式样板读取其他作品，也不得把示例值、其他书的身份或通用模板填入当前书。

## 草稿身份与文件名

下面是一个虚构示例，表示第二卷、全书第十七章的第四稿。数字和章名都不是当前书的默认值。

路径：`草稿区/草稿/卷02-桥上夜话/稿4.md`

```markdown
---
身份:
  卷: 2
  章: 17
  章名: 桥上夜话
版本: 4
父版本: 3
角色: 待审稿
选定: true
---
# 桥上夜话

此处仅示意正文位置，不是要写入的正文。
```

身份也可采用合法的行内映射，含义相同：

```yaml
身份: { 卷: 2, 章: 17, 章名: "桥上夜话" }
```

| 字段或位置 | 含义 |
| --- | --- |
| `身份.卷` | 正整数卷号，须与卷目录对应 |
| `身份.章` | 全书连续的正整数章号，不按卷重新从一开始 |
| `身份.章名` | 本章名称，须与对应路径和证据一致 |
| `稿4.md`、`版本: 4` | 稿件编号与内容版本，不能用来推断章号 |
| `父版本: 3` | 内容版本关系，与章节先后顺序无关 |
| `角色: 待审稿` | 该稿的用途，不证明审核完成或章节已收尾 |
| `选定: true` | 选稿标记，不代表升级、审核或定稿批准 |

正常草稿角色使用 `草稿` 或 `待审稿`。起草暂存路径为 `稿N.起草中.txt`；暂存不代表完整交付。原稿可能还含 `生成模块`、`来源快照`、候选事实和作者扩展，不能因为示例没列出就删除。

## 旧身份的章号证据

旧式 `身份: 卷02-桥上夜话` 只有卷与章名，没有章号。受支持的转换要求旧身份与目录一致，并有唯一对应的已确认细纲或定稿证明章号。

以同一虚构示例说明证据路径：

- `大纲/卷规划/卷02/章细纲/0017-桥上夜话.md`：须为已确认，已有身份及章号元数据不能与路径矛盾。
- `定稿/卷02/0017-桥上夜话.md`：须为已定稿，已有身份及章号元数据不能与路径矛盾。

同卷同名的证据必须指向唯一章号。相互矛盾、缺少证据或不可读时停止升级，保留原稿和诊断。不能从稿件版本、最大章号、只有一份稿件或“看起来像开篇”推断归属。

缺证据时，可询问作者实际卷号、章号以及原确认细纲或定稿的位置。问题和选项不得预填任何具体章号；去掉“推荐”标记也不使“它是第一章”成为有依据的选项。可用“提供实际归属”“指出已有证据位置”“暂不升级”表达选择，不引导作者接受猜测。

不要为了通过升级临时编造一份已确认细纲。作者的口头说明有助于定位和澄清，但不会自动成为工具认可的已确认工件。

需要补充或更正设计时，另按作者明确的设计要求办理，不混入纯格式升级。不能改写草稿身份、删除稿件、套用示例或让旧章先定稿来绕过阻断。

## 几种版本号分别说明什么

| 名称 | 含义与报告方式 |
| --- | --- |
| 插件版本 | 安装的软件版本，例如8.4.0 |
| `作品契约/契约.md` 中的 `书仓格式版本: 1` | 本书当前格式标记，由建书或已批准的整仓升级维护 |
| 草稿、细纲的 `版本/父版本` | 内容修订关系 |
| 预览的 `ruleVersion` | 生成升级计划的规则版本，不能当作原书或目标书的格式号 |
| 收据的 `schema` | 本地维护证据的协议号，不能当作书仓格式号 |

缺少 `书仓格式版本` 应报告“未标注”，不能说它默认为零或一。格式标记为一也不保证全仓健康。说明升级结果时分别报告实际提交状态、格式检查和保留的未完工件，不把格式升级成功说成章节已收尾。

## Git与环境的只读排查

先记录本次工具返回的具体错误，再使用当前会话已有的终端工具。下面两条命令只查询版本及参数支持，不读取或修改提交状态：

```sh
git --version
git --no-optional-locks --no-lazy-fetch --no-pager -c core.fsmonitor=false -c log.showSignature=false --literal-pathspecs --version
```

`--no-lazy-fetch` 从上游Git 2.45开始提供。收到明确的`unknown option`才能据此确认参数不受支持，不能仅凭macOS或Windows判断。

需要核对当前终端找到的可执行文件时，按实际终端选用一条：

```sh
# macOS或Linux的常用Shell
type -a git
```

```powershell
# Windows PowerShell
Get-Command git -CommandType Application | Select-Object Source
```

这些结果只代表该次终端环境。若插件仍报告能力不可用，不能用终端成功认定故障已解决；记录两者差异，继续核对DSH实际运行环境。版本命令成功也不证明提交历史可读取，不能据此去掉安全参数执行`status`、`log`、`show`或`hash-object`。

书仓状态与历史证明继续使用维护工具的受检结果。能力不足时仍可读取当前书的文档证据，但不能把缺失的Git证明补成“已提交”或“未提交”。不得自动升级Git、修改PATH或Git配置、删除钩子、补取对象或打开可写数据库来试错。不要输出整份环境变量或完整Git配置；仅呈报与本次故障相关的信息。

## 文件与关联证据

- 以工具报告的路径为起点，区分缺失、解析失败、类型不符和读取期间变化。先核对文件头、结构与来源；不可读本身不是内容损坏的充分证明。
- 对比草稿、目录、确认细纲和定稿时，保留各自原字段及数据类型。相同正文或相近章名不能替代唯一归属证据；发现矛盾只说明矛盾，不自动选择一份覆盖另一份。
- `.DS_Store`通常是Finder元数据。只有精确名为`.DS_Store`的独立普通文件，才由当前只读检查忽略。同名目录、符号链接和硬链接仍会报告问题。旧版本可能把它当成文本；先记录插件版本与实际错误，不要求作者反复删除。
- 收据和清单中的哈希、状态是原始声明。是否与当前文件或同批历史提交相符，以工具实际完成的核验为准；主控不得重写这些字段来“恢复一致”。

## 使用这份参考的边界

正文、版本、来源、裁决和作者扩展沿用实际文件。维护工具只执行预览中列出的差异，不由主控照着示例重写文件。草稿仍不进Git；转换前后原文留在本地维护收据，后续作者改动不能被旧收据覆盖。

材料清单、审核记录、准备包和收据由各自工具维护，本参考不提供可手写替代它们的空壳。来源变化时按影响报告复核，不改哈希以沿用旧批准。
