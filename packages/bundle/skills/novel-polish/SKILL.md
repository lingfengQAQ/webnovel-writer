# 精修润色总控（Novel Polish）

本技能只管**组织**：选批次、定顺序、版本与回退怎么落；**改写执行者＝润色子代理**——主 Agent 绝不亲自改写一个字（润色稿也是正文）。每批的做法与保真边界在 `工序/` 下的参考文档里，派发时把对应文档全文放进任务包。红线只有一条：**只改表达，不改事实**——语义完全等价，保留原稿有效的独特表达；不确定能否保真时保留该处并标注，不能自行补造事实。

## 批次（三批；可按作者要求定向执行）

| 批次 | 参考文档 | 合并的原道 | 类 |
|---|---|---|---|
| 1 表达清理 | `工序/1-表达清理.md` | 去 AI 痕迹＋语言自然化＋冗余精简 | 表达 |
| 2 节奏与重塑 | `工序/2-节奏与重塑.md` | 句段节奏调整＋对话润色＋修辞与意象调整（文风贴合为总判据） | 表达 |
| 3 平台格式 | `工序/3-平台格式.md`（可选，有明确平台规范才执行） | 平台格式适配 | 格式 |

**默认顺序：批 1 → 批 2 → 批 3**（表达类在前、格式类在后）；作者要求倒序时执行但给警告，不阻断。

## 标准流程

1. **取源**：读取 `草稿区/草稿/卷<NN>-<章名>/`。只有一份 `角色: 待审稿` 时使用它；没有时核对作者已选稿，未另选且仅有一稿时使用该稿。多份待审稿或多个候选的选择不清楚时，先呈作者选定，不按最大稿号擅自选择或降级。按已明确选择修正标记后继续。
2. **默认一次派发**：完整内联批 1＋批 2 参考文档、契约文风原文和硬约束；将输入分为**正文**、**候选事实原文**、**文件操作说明**三部分。正文只送一次；`## 草稿候选事实` 段提供原文，要求一字不改搬进新稿，不作为可润色正文。操作说明给出源稿路径、原 frontmatter、各批交付路径、稿号/父版本和旧待审稿标记。子代理先跑批 1、再跑批 2，各产一版，形成两个回退点；缺交付信息先补齐。
3. 批 3（有已声明来源与版本的平台规范时）：单独一次派发，或与批 2 连跑，产物留版本链；
4. **落稿与降级由润色子代理用通用写工具执行**：批 1 的中间版标 `角色: 草稿`、`选定: false`；只有整轮终稿标 `角色: 待审稿`、`选定: true`，且**先把旧待审稿改成 `角色: 草稿` 并清 `选定`，再写新稿**——两份待审稿并存会让推导退回润色位并死锁；
5. **主 Agent 验收，只查不改**：逐条区分硬约束。明确“必须出现/提及”的词串应出现，明确“不得出现/提及”的词串不得出现；其余语义、条件或复合约束交语义审读，不要求把约束原句写入正文。核对正文汉字数删减不超过两成、候选事实段原样保留、元数据和稿件选择正确。格式/明确词串/删减检查失败先核对原因，退回相应批修正；无法仅改表达修复时交作者决定，不无变化地反复重跑。
6. 呈现整轮对照说明，播报进入《全面审读》。

**子代理回传物**：新稿路径与稿号；逐条差异按批分组；保留并标注项（为保真而没改的地方，各附一句判断）；待作者裁决项；转审读项（人设、逻辑、节奏一类内容问题，只记不改）。

**作者稿不主动派润色**：`生成模块: 作者手写` 的草稿与 `生成模块: 作者手改` 的待审稿都不主动派，作者点名要润色才派。

## 拆分与定向（作者要求或批量过重时）

- 批 1、批 2 可拆成两次派发（每批一版），作者要在批次间人工过目时用；
- 单道定向修复（如只跑去 AI 痕迹）：派发时只带对应批文档并注明「只执行第 X 节」。

## 版本与回退

- 一版一个回退点；同一父版本不得产出多个同版本兄弟稿；
- 作者要回退某批：回到该批之前的版本重跑后续批，旧稿原样留档——每版差异随版本呈作者，**可回退**到任一批次前；
- 中途失败允许 0 份待审稿（重跑即可），不允许 2 份。

## 重入（再润色）

- 作者点名再润色＝在现有待审稿之上继续，不回头消费旧稿；
- 进来多份待审稿：按取源规则先确认保留哪稿；没有明确依据不擅自降级任何一份。
- 重跑先读草稿目录现有稿号再定新稿号，不凭记忆猜；
- 旧稿一律留档，推倒重写也是新增一稿。

## 工件契约

| 工件 | 路径 | 属性 |
|---|---|---|
| 润色新稿 | `草稿区/草稿/卷<NN>-<章名>/稿<N>.md`（`<N>` ＝ 现有最大稿号+1） | frontmatter 字段序八项:`身份`／`版本`／`父版本`／`生成模块`／`来源快照`／`角色`／`选定`／`保真风险`;`版本` ＝ 父稿版本+1、`父版本` 指向父稿;`生成模块: 润色`;有保真风险时逐条记进 `保真风险` 并把该稿留在 `角色: 草稿` |

`角色` 只用待审稿/草稿，`选定` 用布尔值，不填「已确认」。草稿区不入 git。

## 工具

| 工具 | 何时用 | 不要 |
|---|---|---|
| 通用读工具 | 按需加载 `工序/` 批次文档 | 一次读全塞上下文 |
| 润色子代理 | **一切判断性改写与落稿降级**（默认一次连跑批 1+2） | 让主 Agent 代写;任务包缺批次文档或缺回传格式 |
| 通用写工具 | 由润色子代理用它落新稿、改旧稿 frontmatter | 主 Agent 自己动笔改正文 |

## 作者介入

- 作者能做什么：贴自己改过的版本，替代当前润色成果或作为新一版；
- 用哪个通道：`novel_import_draft`（卷/章/章名/正文/角色: 待审稿/生成模块: 作者手改/父版本: 被改稿的版本）；
- 主 Agent 接到后：作者稿落为新一版待审稿（旧待审稿自动降级），之后进入《全面审读》；对作者手改的稿不主动再润色、不自行改动其文字。

## Off-limits

- 润色不产生 git 提交（草稿区不入库）；
- 已有待审稿再润色＝在现有待审稿之上继续，不回头消费旧稿；
- 润色完成播报进入《全面审读》。
