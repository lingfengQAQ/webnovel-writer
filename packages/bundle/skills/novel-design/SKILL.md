# 定调设计（Novel Design）

本技能覆盖「已立项新书 → 开写就绪」。设计侧的一切写入只经工具落盘，每次作者确认由确认类工具产生 `design:` 提交；「留白」是合法状态，作者没想好就标留白，严禁编造填充。

## 标准流程

### 路径 A：快速开写

作者想先跑起来、以后再细化时走本路径：你按构想快照一次起草开写所需的全部设计，作者过目一次，同意后逐件经工具写入。省的是对谈轮数，不是内容——只有标注、没有正文的「已确认」一律不写。

1. 与作者确认「先跑起来再细化」，读 `构想/构想快照.md`；
2. 一次起草，每部写一两句实质内容：
   - 契约六部；
   - 世界书最小模块：人物档案（至少主角一条）、世界规则（至少一条）；
   - 故事骨架九部；
   - 分卷布局：「故事阶段分配」下写本卷卷行（如 `- 卷01：……〔已确认〕`），其余七部作者没想法就留白；
   - 第一卷卷纲（叙事结构、弧线、线索推进、卷末兑现四段齐全，没想好的段标留白）与计划时间线；
   - 近期窗口第一条＝第一章章名（确认细纲要求章名与窗口里可进入的条目同名）；
3. 整份呈作者过目：逐部一两句概述，标明哪些是你的提议。作者不认可的部分改到认可为止，或标留白——契约分部、骨架分部留白时设计面会停在对应阶段，不替作者编；
4. 作者明确同意后按序写入：`novel_update_contract`（六部逐部）→ `novel_confirm_worldbook_entry` → `novel_update_skeleton` → `novel_update_volume_layout` → `novel_confirm_volume_outline`（卷纲、计划时间线各一次）→ `novel_roll_window` 追加第一章条目；
5. 写完查 `novel_get_book_progress`，确认没有「无内容」标记，向作者播报写入结果与留白项。

### 路径 B：深度定制

1. **契约六部**逐部对谈（题材与读者定位 / 核心看点与差异化 / 阅读体验与情绪承诺 / 主角原则与关系边界 / 叙事方式与文风基调 / 创作禁区与不可妥协项），每聊定一部调 `novel_update_contract`——「已确认」随确认产生 `design:` 提交，「暂定/留白」只写文件；
2. **世界书**：`novel_confirm_worldbook_entry` 写入/确认条目；
3. **故事骨架**：`novel_update_skeleton`（九部，覆盖式，再确认版本+1）；
4. **分卷布局**：`novel_update_volume_layout`（八部，同上）；
5. **强制多方向**（本卷首次确认卷纲前必跑；卷纲修订与滚窗不跑，路径 A 不跑）：
   - 读 `作品契约/契约.md` 的「核心看点与差异化」「阅读体验与情绪承诺」两部，逐条列出本书底线期待并标注「不参与发散」；判据＝读者按本书题材必然预期的那几条（玄幻主角必须变强、甜宠男女主必须彼此在意），违背它比落俗更伤；
   - 方向一写本卷最典型的那一版，标题后写「典型版」三字，作对照留着；
   - 方向二、三各在一条轴上偏离方向一，两者不取同一轴，各自标明所偏之轴；轴从固定短表里选：代价落在谁身上／揭露顺序／主角失去什么／对手是谁；
   - 每个方向都写代价与放弃项，只有好处的方向打回重写；
   - 三个方向呈作者选定；`选定方向` 一行、`已排除走向` 两行，写进卷纲末尾的「方向选择」小节；三行都不带 `〔…〕` 标记，行文不复述章名。
6. **卷规划**：`novel_confirm_volume_outline` 写卷纲或计划时间线（卷纲是整文件覆盖，叙事结构等各段与「方向选择」小节一并给全）;`novel_roll_window` 追加窗口条目。

## 工具

**单文件设计写入先读目标**：六类确认/更新工具最终使用宿主原生写入。对已存在的契约、骨架、分卷、卷纲、计划时间线、窗口和世界书条目，先在当前主会话用原生 `read` 读取目标，再调用对应工具；进度卡和插件内部读取不代替这个观察。新建书的脚手架文件也已存在。首次创建不存在的条目可直接调用工具；`FS_NOT_OBSERVED` 时读目标后重试，`FS_STALE_VERSION` 时重读并核对作者/外部改动，不覆盖新内容。路径 A 与路径 B 都遵守此规则。

| 工具 | 何时用 | 不要 |
|---|---|---|
| `novel_get_book_progress` | 动手前查进度卡（留白/待补/无内容/未决偏离） | 跳过校准直接改 |
| `novel_update_contract` | 每聊定一个分部 | 以「重写整个契约」的方式操作——会抹掉书id 与既有分部 |
| `novel_update_skeleton` / `novel_update_volume_layout` | 骨架/分卷成稿或修订 | 无影响分析呈报就整批覆盖下游 |
| `novel_confirm_worldbook_entry` / `novel_confirm_volume_outline` / `novel_roll_window` | 对应工件确认 | 手工编辑真源文件 |
| 影响分析脚本 `node <resourceBase>/scripts/影响分析.mjs --book <bookRoot> --变更路径 <相对路径>` | 覆盖式写入前查受影响下游（反向闭包，只报事实不判该不该改，只算不写） | 凭印象估影响面；把草稿区受影响文件列入 `批次文件` |

## 重入

- **先查书级进度卡再动手**：哪些分部留白/暂定/无内容、哪些工件有待补便签、本卷未决偏离；
- **分部更新，绝不整体重写契约**；
- **路径 B 每一卷首次确认卷纲前都跑一次强制多方向**；路径 A 不跑，同一卷卷纲修订与滚窗不重跑；
- 骨架/分卷覆盖式写入会版本+1：改前跑影响分析脚本（本技能包 `scripts/影响分析.mjs`，只算不写；失败按《工作台总控》「脚本失败分流」表处理）做**影响分析前置呈报**，作者裁决通过后受影响未定稿下游**同批整改**，整改文件列入确认工具的 `批次文件` 一并整批提交；已定稿下游走吃书补偿；影响面过大拆提案；
- 工具报「已落盘但未提交」＝重跑该工具补提交（幂等重放），严禁重写文件。

## 工件契约

| 工件 | 路径 | frontmatter | 状态取值与族 |
|---|---|---|---|
| 契约 | `作品契约/契约.md` | 书id | 六部各 已确认/暂定/留白（计划族） |
| 故事骨架 | `大纲/故事骨架.md` | `状态: 已确认`＋`版本`/`父版本`/`生成模块`/`来源快照` | 九部各 〔…〕（计划族） |
| 分卷布局 | `大纲/分卷布局.md` | 同上 | 八部各 〔…〕＋卷行（计划族） |
| 卷纲/计划时间线 | `大纲/卷规划/卷NN/卷纲.md`、`计划时间线.md` | 无 frontmatter，状态只在段标记里 | 计划族 |
| 近期窗口 | `大纲/卷规划/卷NN/近期窗口.md` | 无 frontmatter | 条目 已确认/暂定（计划族）＋已消费/已失效/等待补设计（轮次族） |
| 世界书条目 | `世界书/<模块>/<条目>.md` | `名称`/`类型`/`性质`/`状态`/`来源` | 计划族 |

待补便签用 `novel_note_pending` 写在工件分节内（随 `design:` 提交）。

路径 B 经强制多方向确认的卷纲，末尾含「方向选择」小节：`选定方向` 一行、`已排除走向` 两行。路径 A 不跑多方向，卷纲没有该小节。

## Off-limits

- 本阶段以对谈为主，不派发起草子代理；
- 影响长期走向的设定分歧先出建议稿，不擅自拍板。

## 完成标志

`design` 段变为「开写就绪」、章节面出现「章细纲(待定位)」——进入《细纲备料》。
