# 知识库十维集成审计

## Goal

在所有实现与内容子任务完成后，对十维知识库进行跨维、跨调用链和真实使用审计，确认分类清楚、调用有效、扩充有据且不会因固定路由导致同质化。

## Requirements

- 前置依赖：父任务治理真源已冻结，运行时框架及三个内容策展子任务均已完成、通过各自验收并完成开发阶段签收。
- 审计十维边界、别名/名称唯一性、近重复、作用尺度、硬软知识分离和版本冻结。
- 审计建书、规划、写作、审稿、定稿、复盘的调用覆盖及降级路径。
- 用多本同题材/复合题材样例验证候选多样性和本书化差异。
- 审计 v6 候选资产策展清单，确认每条都有保留、重写、拆分、合并或删除裁决，且无模板化回流。
- 审计故事对象的计划/事实两阶段、章级整体确认、近期历史软降权、最小使用记录，以及运行时不存在作者扩库入口。
- 审计普通条目策展与维度架构变更的两级治理，确认每条正式知识只有一个 canonical 归属。
- 验证 installer、目标架构一次性切换、源码回滚点与文档真源一致性；明确断言不存在旧书兼容层和数据迁移器。

## Acceptance Criteria

- [ ] 每个顶层维度均有独立调用证据、真实消费者和可验证产物。
- [ ] 全部存量条目有唯一 canonical 归属；跨维使用通过组合或拆分完成，不复制条目，也不依赖无消费者的协同维度元数据。
- [ ] 同题材样例不会产生固定创意包或固定章节组合。
- [ ] 运行时没有知识评分、章后反馈、作者提交或自动扩库能力；计划对象不会被误当作定稿事实。
- [ ] 未决策清单清零，任务、README、spec、代码和测试对最终状态描述一致。
- [ ] 全量测试、格式校验、installer/e2e 与人工内容审查通过。

## Notes

- 本任务不新增功能，只负责发现偏离并将修复路由回对应子任务。
- 启动前补齐自身 `design.md` 与 `implement.md`；审计本身不建立回滚代码，任何修复由责任子任务独立提交和回退。
