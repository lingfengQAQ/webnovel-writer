# 知识库维度边界与扩充治理

## Goal

建立一套可长期执行的知识库分类与扩充治理规则：明确现有维度的职责、边界、准入与排除条件，裁决当前未决条目，并判断应新增顶层维度还是增加正交元数据，使后续新增、合并、拆分、迁移和废弃知识都有一致依据。

知识库的最终目的不是形成理论分类体系，而是服务实际使用：调用者能够在正确时机识别、选择、注入并执行正确知识，使规划、写作和审查形成闭环。分类清晰、边界明确和扩充有据都是实现这一目的的手段。

## Background

- 07-07 重构形成 146 条已提交基线；07-08 经作者签收后在 `e2410c7` 收编 20 条，当前 Git 已提交基线为 166 条：题材 16、流派 22、节拍 102、场景 16、追读 10，规划冻结时工作区干净。五个目录已有统一格式与格式测试，缺口集中在分类边界、调用价值和扩充治理。
- `v7/references/README.md` 尚未覆盖维度准入/排除、相邻边界、近重复、拆并废弃、别名迁移和架构变更留档；07-07 与 07-08 已完成签收并归档。现行 spec 0.16 保存已生效的历史决策，本任务保存待实施的目标决策，后续切换时必须明确区分当前态与目标态。
- 已知压力样本包括：题材与流派的世界观/写法混用；节拍中混入书卷结构、诊断工具和兑现模式；场景与通用技法混用；追读内部存在软边界与种属关系；规划材料中的 `题材` 与实际 book schema 的 `类型` 口径不一致。

### 当前调用实现（代码事实）

- **建书**：序1 DTO 只提供题材/流派名称菜单和 `knowledge-pack` 命令提示；AI/宿主须在问答收集类型与流派后主动运行命令。命令按 `路由.csv` 精确名称/别名命中，输出题材与流派条目全文，由 AI 与作者对撞蒸馏为 `文风/题材流派指导.md`。
- **细纲选择**：序6 每章向 AI 提供节拍 102 条、追读 10 条、场景 16 条的全量紧凑索引（编号/名称/一句话），AI 在细纲中显式声明 `本章节拍`、`章尾钩子`、`本章场景`，也可写自定义文本。
- **候选推荐**：当前只有场景有自动候选。脚本用场景关键词扫描“整个当前卷卷纲 + 上一章末尾 300 字”；命中即给候选。节拍和追读没有候选算法。
- **写作备料**：每章常驻注入完整题材流派契约；对细纲声明命中的节拍/追读/场景，仅注入该条目的 `落笔时` 小节。未命中时注入声明文本并提示按声明执行。
- **编辑审查**：当前实现注入契约中的恩怨清算档位和本书专属毒点；同时重新读取当前运行时题材/流派条目的 front matter 毒点；再注入声明命中的节拍/追读/场景毒点与 `审稿时` 小节。恩怨清算档位及运行时回读均已被后续决策判定为待删除设计。
- **降级**：知识目录缺失、路由未命中、条目缺失或声明自定义均不阻断流程。
- **当前未发挥价值的内容**：`规划这一章时` 已解析但无人读取；`适用题材` 与节拍 `关键词` 不参与实际筛选；所有作品每章收到相同的 128 条章级菜单。现有细纲只保存声明结果，没有为拒绝、修改或实际审稿问题提供最小化留痕位置。
- **实现与设计的关键漂移**：设计声明“库升级不影响在写的书，下游只消费书仓契约”，但编辑审会重新读取当前运行时题材/流派毒点；因此库升级可能静默改变存量书的审稿标准，而写作备料仍只吃旧契约，生成侧与审查侧可能不一致。
- **现有反同质化防线的实际强度**：知识条目禁止具体示例情节，建书提示要求“差异化点 ≥3”，方向正确；但 `persist-book` 只校验题材流派指导是字符串，不校验固定四节、差异化点数量或内容独立性。当前反同质化主要依赖提示词和作者自觉，尚不是可验证契约。

### v6 能力对照事实

- v6 将创意约束作为建书闸门：生成多套反套路与硬约束组合，由作者选择或明确拒绝；同时区分主题材与副题材，并要求共同冲突、规则兼容/隔离、介入条件、主副线分工和风险。v7 当前只有单值 `类型` 与多值 `流派`，这些能力没有等价落点，不能用“差异化点 ≥3”替代。
- v6 另有 104 条覆盖对白、描写、视角、情感、结构、战斗和设定执行的写作技法资产，范围大于“叙事技法”；它们需要进入更广义的 `技法/` 候选策展，而不是整体照搬。

## Requirements

### R1 决策真源校正

- 汇总 07-07 与 07-08 两个知识库任务的所有作者拍板、审查待定和未签收项。
- 区分“已决定”“审查建议”“仍需作者裁决”“已写入 spec 但证据不足”四类状态。
- 在治理方案落定前，不把未签收候选误记为正式分类规则。

### R2 维度宪章

- 为十个目标维度分别定义：目的、消费时机、允许粒度、必要条件、排除条件、相邻维度分界、正例与反例判定方法。
- 目录维度优先服务运行时消费和调用者选择清晰度；知识本体的语义纯度通过必要的元数据、边界说明和协同关系表达，不为理论整齐增加无使用价值的复杂度。
- 明确“题材/类型”的产品含义及单选依据，避免把市场主分类与纯语义题材混用而无说明。

### R3 正交切面设计

- 评估是否需要新增顶层目录，例如通用叙事/写作技法。
- 同时评估用分维字段表达 `作用尺度`、`知识类型`、`触发方式`、`适用题材` 等真实筛选需求；不预设 `协同维度`、`关联维度` 等无消费者字段。
- 仅当新目录拥有独立消费时机或独立声明键，且不能由元数据可靠表达时，才新增顶层维度。
- 作者已确认新增书级顶层维度 `创意约束/`：承载可组合的反套路限制、代价机制与差异化驱动；仅在建书和重大改纲时调用，选择后蒸馏进本书契约，不逐章直接灌入运行时上下文。
- 作者已确认新增章级顶层维度 `技法/`：范围覆盖对白、描写、视角、信息、情感呈现、结构、战斗和设定执行等可迁移操作方法；通过类别、作用层级、触发问题、适用题材、禁用条件与可组合技法筛选，不展示全量菜单。

### R3.1 Schema 字段准入与信息分层

- 作者已确认不预设跨十维统一 schema，也不为了理论完整增加公共字段；每个维度的字段必须在调用者矩阵完成后，由实际消费行为反推。
- 任一字段进入运行时条目 schema 必须同时满足：存在明确调用者；读取后会改变筛选、注入、持久化或审查行为；不能可靠地从文件路径、正文、Git 或知识使用记录中推导。
- 信息分为三层，禁止混存：
  - **front matter**：只保存机器实际读取的选择键和判定键。
  - **Markdown 正文**：保存知识原理、操作方法、边界、失败模式和调用者需要的正文小节。
  - **治理与使用记录**：保存来源、版本、状态、策展裁决、候选、选择与拒绝原因；除被选知识的 `路径@hash` 外，不进入运行时条目内容。
- `编号 / 一句话 / 类别 / 适用题材 / 关键词 / 毒点` 均不得默认成为公共字段：只有对应维度的真实调用者需要时才保留。通用适用范围直接省略，不写无信息量的“全部”。
- 若审稿只消费正文 `审稿时` 或失败模式小节，不得再在 front matter 重复保存同义毒点；若候选算法不读取关键词或适用题材，则字段必须删除而不是保留待用。
- 新增字段必须同时新增消费代码、行为测试和字段用途说明；删除最后一个消费者时必须同步删除字段与校验，不允许形成“解析了但无人使用”的僵尸 schema。

### R4 条目生命周期规则

- 建立新条目准入测试：独有问题、独有动作建议、独有毒点、可被明确触发、与邻近条目可区分。
- 建立近重复判定与处理规则：保留并锐化、父子条目、合并吸收、改为元数据/小节、驳回。
- 建立改名、移动、别名迁移、废弃、编号保留、交叉引用和兼容策略。
- 规定每次开发阶段扩库所需的研究证据、独立审查、策展签收和决策记录。

### R5 存量压力测试

- 用治理规则审计工作区 166 条候选知识，至少覆盖全部已知未决项与每个维度的边界样本。
- 产出保留、锐化、移动、合并、拆分、废弃、补元数据、新增条目候选清单，并说明理由。
- 条目数量不是扩充目标；只有确认知识缺口且满足准入测试时才建议新增。

### R6 兼容与落地

- 作者已确认 v7 尚未投入生产，没有需要兼容或迁移的旧书数据；本轮按目标架构直接重构，不保留旧路径、旧字段、双读逻辑、兼容别名或书仓数据迁移器。
- 现有实现、fixture 和测试只作为开发基线，不构成兼容契约；目录、front matter、`路由.csv`、解析器、DTO、installer 与 spec 应一次性切换到最终设计。
- 继续保留“知识缺失不阻断创作”的产品降级原则，但不为旧格式提供降级分支。
- 本任务中引用 v6 资产的“迁移”仅表示把旧知识作为素材进行审计、拆解、重写和策展收编，不表示迁移用户书稿或运行时数据。
- 在作者审核最终规划前，不修改知识条目或运行时代码。

### R7 调用者使用契约

- 明确每类调用者是谁、在什么阶段调用、用什么键或信号选知识、读取条目的哪一部分、产出什么决策或检查结果。
- 至少覆盖：建书蒸馏、细纲规划、场景/节拍候选、写作备料、事实审查、编辑审查、知识维护者扩库。
- 同一条知识在生成侧与审查侧的使用职责必须区分：生成侧获得可执行结构与禁忌，审查侧获得可核对毒点与判定依据。
- 禁止整库无差别灌入；调用机制必须在知识命中率、上下文成本、可解释性和确定性之间给出明确取舍。
- 修复“规划小节无人调用”“适用题材与节拍关键词不参与选择”“全量菜单过载”“生成侧与审查侧版本漂移”等现有价值断点。

### R8 反同质化调用原则

- 作者已确认采用“硬约束确定性注入、软策略多候选推荐、作者/AI 显式选择并允许自定义”的核心原则。
- 固定路由只能确定兼容范围、底层约束和候选池，不得自动决定具体情节、人物配置、场景解法或唯一节拍组合。
- 区分两类知识：
  - **硬约束**：题材承诺、因果边界、毒点、读者不可违背的核心预期，可确定性注入并供审查核对。
  - **软策略**：节拍、钩子、场景技法、表现手段，只能作为多候选建议，允许拒绝、变体、组合和自定义。
- 不建立跨十维统一的候选数量或候选组成模板。候选规则必须由调用阶段和知识维度分别定义；章级的“问题匹配/近期使用”逻辑不得套用到刚开始建书的作者。
- 跨维度只保留最低共同原则：只有存在真实未决选择时才给候选；不得自动替作者决定；不得用近重复项凑数；允许拒绝、自定义和继续追问；作者越明确，系统越少发散。
- 建书蒸馏必须把通用知识转化为本书独有契约，而非复制通用条目；差异化点须可验证存在且与总纲/角色/设定形成具体连接。
- 章级调用至少持久化所选知识与自定义变体；本章问题、选择理由和预期作用可直接写在细纲自然语言中，只有真实消费者需要结构化读取时才增加独立字段。
- 知识条目继续只写可迁移原理、结构约束和失败模式，不提供可直接复刻的具体剧情模板。

### R8.1 分阶段候选契约

- 作者已确认建书必须先理解作者意图，只对尚未决定的部分提供候选；作者已有明确构想时先确认和归一，不重新发散题材。
- 建书候选按作者状态分流：
  - 已明确题材或核心构想：直接归一主题材，围绕未决的副题材、流派、融合方式和创意约束补全。
  - 想法模糊：先通过问答提炼目标读者体验、主角驱动力、故事规模、偏好与禁区，再提供少量整体作品方向。
  - 完全无方向：可提供整体方向包帮助发现偏好，但不得先展示十维知识菜单。
- 建书最终提供的是少量整体创意包，而非零散知识条目列表；每套组合主题材承诺、副题材介入、流派引擎、创意约束、差异化来源与主要风险。作者可选择、混合、改造、拒绝或自定义。
- 故事对象知识在“需要创建具体对象”时调用：设定依据对象功能和规则约束，人物依据叙事功能与长期行为逻辑，命名依据对象类型、语系、阵营、功能和现有名册产生候选。
- 篇章知识在具体章节规划时调用，才允许依据细纲任务、待兑现内容、当前问题、作用层级和近期使用记录筛选节拍、场景、技法与追读候选。
- 审稿修复候选必须以已发现的问题和正文证据为输入，不得在无问题时预先灌入通用修复菜单。

### R9 反套路与复合题材能力恢复

- 作者已确认：反套路创意约束与主题材/副题材融合协议恢复为建书必经的一等契约；作者可明确拒绝，但系统必须记录拒绝原因，不得静默跳过。
- 作者已确认：`类型` 表示单一主题材；`副题材` 只能取 canonical 题材集合；`流派` 继续单独多选；反套路规则与硬约束进入书级创意契约，不得用副题材或流派字段代替。
- 将 v6 的反套路选择恢复为一等建书能力，但按 v7 的确定性 DTO、书仓契约和可测试流程重新设计，不直接照搬旧技能长文与具体示例。
- 反套路不是“把常见套路反着写”，而是选择能持续制造决策压力的限制、代价或规则变化；每条须说明它改变了什么常规、如何驱动长期冲突、如何防止被金手指绕过。
- 建书至少生成多套不同创意约束候选，由作者选择、改造或拒绝；最终结果进入书级契约并在后续规划、写作和审查中有明确调用位置。
- 恢复复合题材的主辅结构，禁止用多个并列“主题材”或把副题材误塞进流派字段；主题材负责核心读者承诺和主线逻辑，副题材负责差异化机制与新鲜感。
- 为复合题材建立融合协议：共同核心冲突、规则兼容/隔离、介入条件、主副线分工、占比/频率、冲突解决与风险清单。
- 反套路与复合题材必须参与建书差异化校验，且其使用不得把作品导向新的固定“反套路模板”。

### R10 创意约束条目边界

- `创意约束/` 条目必须是可迁移的限制或代价机制，而非具体剧情模板、人物配置、单一题材套路或普通毒点。
- 每条至少定义：被挑战的常规、决策压力、长期驱动机制、防绕过条件、适用/迁移/禁用条件、审查判据。
- 调用者须组合多个候选形成创意包，不得用路由自动选定唯一约束；作者可选择、改造、自定义或明确拒绝。

### R11 候选新增维度（审计推荐）

- 作者已确认以十个顶层维度作为后续设计基线：`题材 / 流派 / 创意约束 / 设定 / 人物 / 命名 / 节拍 / 场景 / 技法 / 追读`。
- **`命名/`**：独立服务“需要产生 canonical 名称”的任务，覆盖书名、卷名、章名、人物、地点、组织、制度、能力、招式、物品和术语。调用输入包括命名对象、题材/副题材、文化语系、阵营、功能、现有名册；产出包括候选、选定正名、别名、所属语系、选择理由和近名/重名检查。
- **`设定/`**：独立服务世界与实体机制设计，统一承载世界规则、力量体系、能力/金手指、物品/装备、资源/经济、组织/势力、制度/社会、地理/生态、技术/生产、副本/任务和题材机制。条目保存“怎样设计”，本书实例化结果进入书仓设定事实。
- **`人物/`**：独立服务角色与长期关系设计，覆盖角色功能、欲望/缺陷、行为边界、人物弧、双人关系、群体关系、反派体系与 OOC 约束。呈现方法归技法，具体姓名归命名，本章情绪涨落归节拍。

### R17 作品契约更新生命周期

  - **可调条款**：差异化点、冲突与关系结算原则、本书专属毒点、节奏与兑现参数。可依据持续写作证据修订。
- 更新触发分级：
  - 作者主动提出、契约与当前细纲直接冲突、契约本身造成阻断性审稿问题、重大改纲或核心方向变化：立即提出修订，并在继续受影响章节前确认。
  - 同类非阻断问题连续两章出现，或同一卷累计三次；作者反复否决同类方案；同一契约表述多次被误解：生成契约修订候选，在下一个作者停顿点呈报，不打断连续写作。
  - 每卷复盘必须包含一次契约复盘，检查有效条款、未使用条款、机械重复来源、未覆盖长期问题与下卷调整需求；复盘是必经检查，不强制实际修改。

- 只有会持续影响未来多章规划、写作或审查的规则进入作品契约。单章执行错误留在章级记录，世界/人物事实进入设定或角色文件，语言偏好进入文风铁律，单卷剧情安排进入卷纲。
- 每次更新至少记录契约版本、生效起章、更新原因和变更类型；详细证据、真实裁决与来源写入 `作品契约/知识选择记录.md`。单契约真源下，`生效起章` 必须精确等于下一未定稿章；若需影响已定稿内容，必须另走影响分析与吃书流程。
- 阻断性契约冲突立即停；普通重复问题在下一作者停顿点呈报；卷末强制复盘。更新须原子失效全部当前未发布批次章与工作区工件，`打回` 章也不例外；机器守卫以“待重做→绑定章号/契约版本/批次目录/原始定稿包 hash 的待提交证明→commit confirmed 后精确释放”覆盖完整生命周期。两审输入须以完整 DTO 令牌绑定章号、草稿、作品契约和审稿上下文，更新前已发出的旧两审结果不得在新契约下延迟回流。失败、提交结果未知、证明/令牌损坏、状态洗回或包篡改均保留守卫并阻断，既有守卫未收口时不得二次更新；已定稿章节不受影响。

- 开发阶段的新知识继续通过 Trellis 任务、策展裁决和代码审查进入正式库；候选材料与审查过程保存在任务产物中，只有通过边界、调用者和近重复检查的最终条目进入 `v7/references/`，不在运行时正式库旁建设长期候选目录。
- 本 PRD 中“作者确认作品契约、细纲或事实冲突”均指作品作者对自己书稿的控制权；“知识条目策展签收”属于开发治理角色，二者不得在接口和文档中混用。

### R23 条目策展与维度架构两级治理

- 作者已确认开发阶段的知识维护分为普通策展和架构变更两级，不允许在增加单条知识时顺手改变维度边界。
- **普通策展**包括在既定边界内新增或修正文案、合并近重复、拆分条目、废弃错误内容和调整别名；按所属维度的准入、排除、调用者和近重复规则审查。
- **架构变更**包括新增或删除顶层维度、改变维度定义或调用阶段、调整维度间优先级、引入公共 schema 字段以及批量移动条目；必须修改维度宪章，分析对目录、调用者、持久化、测试和全部受影响条目的影响，并单独获得架构级确认。
- 任何普通策展如果无法在现有边界内得到稳定归属，应升级为边界问题或架构变更，不得通过复制条目、扩大兜底目录或增加无消费者字段临时绕过。

### R24 单一正式归属

- 作者已确认每条通用知识只能在十个正式维度中拥有一个 canonical 归属，不允许为了跨维使用而在多个目录复制同一知识。
- 归属按条目的主要调用者、解决的问题和产出行为判断，而不是按正文中出现了哪些题材词、人物词或设定词判断。
- 一份候选材料包含多个可独立调用的方法时，应拆分后分别归位；无法拆分且必须由同一调用者整体消费时，才保留为一条，并以该调用者对应的维度为正式归属。
- 跨维需求通过调用阶段组合多个正式条目解决，不通过复制文件解决。名称相同、摘要改写但方法实质相同的跨目录条目仍视为重复。
- 不预设公共 `协同维度`、`关联维度` 或交叉引用字段；只有具体消费者能够证明读取该字段会改变筛选、注入或审查行为时，才可按架构变更流程引入。
