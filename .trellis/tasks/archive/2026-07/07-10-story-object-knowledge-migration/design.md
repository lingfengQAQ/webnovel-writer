# Design：故事对象知识策展

## 1. 目标与非目标

本任务把已经生效的故事对象运行时接口填充为可调用、可本书化、可审查的正式知识内容。通用条目只帮助设计对象；作者确认后，真正约束后续规划、写作和审查的是书仓中的计划对象与定稿事实。

目标：

- 为 `设定/人物/命名` 建立最小且互不混用的正式 schema。
- 对 284 条 v6 候选及书级任务转交项逐条裁决，删除模板、固定答案和无消费者字段。
- 每个正式条目能被真实对象问题命中，且最多返回三条材料，不替作者决定具体对象。
- 选定知识能够转化为 `本书设计 / 一致性边界 / 知识依据`，命名结果附着原对象。
- 用格式、查询、计划对象和事实转正测试证明内容确实进入调用闭环。

非目标：

- 不修改十维边界、不新增物品、能力、组织、关系等顶层目录。
- 不恢复 v6 的全量 CSV 检索、题材固定路由或具体人物/设定模板。
- 不建设作者投稿、评分、自动扩库或跨作品知识晋升。
- 不重做运行时计划/事实架构；只有内容暴露出已实现 schema 的最小不一致时才做窄修正。
- 不处理篇章技法、场景、节拍、追读或桥段资产。

## 2. 已冻结的数据流

```text
真实对象问题
  -> knowledge-query 查询 设定 / 人物 / 命名，最多三条
  -> 作者选择、组合、修改、拒绝或自定义
  -> persist-design 写入 大纲/创作设计/设定|人物/
  -> 细纲通过 本章对象 精确引用
  -> prep/review 只读计划对象的本书设计与一致性边界
  -> 正文首次出现并定稿
  -> factChanges 无冲突原子转正；冲突/歧义先由作者裁决
```

通用条目在计划对象落盘后不再被写作或审查回读。来源版本、本书采用方式和真实修改写进计划对象的 `知识依据`，普通未选候选不持久化。

## 3. 三维 schema

### 3.1 设定

front matter 只允许：

| 字段 | 必需 | 消费者 |
|---|---|---|
| `名称` | 是 | 候选展示、精确匹配、来源记录 |
| `对象类型` | 是 | `knowledge-query --类型` 的精确筛选 |
| `一句话` | 是 | 问题文本匹配与紧凑候选展示 |

`对象类型` 与计划对象校验器保持一致，只使用：`世界 / 规则 / 机制 / 能力 / 物品 / 组织 / 制度 / 地点`。资源、技术、体系等来源概念按其实际产出归入上述类型，不为来源列名扩充运行时枚举。

条目回答“这个对象如何被设计成自洽机制”。具体能力名、数值表、物品属性、组织成员和世界事实必须本书化后才进入计划对象。

### 3.2 人物

front matter 只允许：

| 字段 | 必需 | 消费者 |
|---|---|---|
| `名称` | 是 | 候选展示、精确匹配、来源记录 |
| `人物类别` | 是 | `knowledge-query --类型` 的精确筛选 |
| `一句话` | 是 | 问题文本匹配与紧凑候选展示 |

`人物类别` 只取 `角色` 或 `关系`，与计划对象的两类产出一致。角色条目解决欲望、缺陷、底线、行为逻辑、人物弧或反派职责；关系条目解决长期互动、利益、权力、信任与变化机制。旧运行时定义中的 `关系类别` 没有独立命令消费者，本任务删除该索引字段，不为分类精细度保留僵尸 schema。

对白、心理描写、视角呈现和单场关系推进属于篇章技法或场景，不进入人物条目。

### 3.3 命名

front matter 只允许：

| 字段 | 必需 | 消费者 |
|---|---|---|
| `名称` | 是 | 候选展示、精确匹配、来源记录 |
| `命名对象` | 是，列表 | `knowledge-query --类型` 的精确筛选 |
| `一句话` | 是 | 问题文本匹配与紧凑候选展示 |

`命名对象` 归一到 `书名 / 卷名 / 章节名 / 角色 / 地点 / 组织 / 能力 / 物品 / 制度 / 术语 / 任务 / 副本 / 赛事 / 代号`。一条真正通用的方法可以覆盖多个对象类型，但不得用“全部”占位。

命名条目只提供生成和校验方法。具体候选名、正名、别名、语系与近名检查结果附着到对应计划对象或书级产物，不建立平行命名实体目录。

### 3.4 正文切片

三维条目都只要求一个 `## 规划时` 运行时切片。切片内部必须同时给出：

1. 可执行的设计或命名动作；
2. 需要向本书锁定的问题；
3. 应写入计划对象的可观察一致性边界；
4. 能区分近邻方法的失败模式。

不增加 `落笔时 / 审稿时` 通用条目小节。后续写作与审稿消费的是本书化计划对象，继续回读通用条目会造成版本漂移，也会让未被选中的知识静默影响作品。

正式条目不得保留 `编号 / 适用技能 / 分类 / 层级 / 关键词 / 意图与同义词 / 适用题材 / 大模型指令 / 毒点 / 正例 / 反例 / 来源 / 状态`。来源编号与处置保存在任务研究记录中。

## 4. 候选裁决

### 4.1 输入

- `webnovel-writer/references/csv/金手指与设定.csv`：104 条。
- `webnovel-writer/references/csv/人设与关系.csv`：101 条。
- `webnovel-writer/references/csv/命名规则.csv`：79 条。
- 书级任务转交：洪荒/克苏鲁/诡秘规则、反派镜像、关系阻力、规则身份、内鬼、循环/扩张等候选。
- v6 worldbuilding 指南只作为补充证据；不能绕过 284 条来源裁决，也不能直接复制长模板。

### 4.2 单条处置

每条来源必须记录：来源 ID、主要问题、唯一维度、处置、canonical 去向、近重复、删除内容与理由。处置仅为：`保留重写 / 合并吸收 / 拆分 / 转交 / 删除`。

- **保留重写**：有独有问题、动作、失败模式和触发信号，形成正式条目。
- **合并吸收**：题材化改写或动作实质相同，归入一个 canonical 条目。
- **拆分**：一行同时含设定机制、人物配置或呈现技法；每个拆分结果重新过准入门。
- **转交**：主要产出属于创意约束或篇章技法；只在裁决记录登记，不在本任务复制正式文件。
- **删除**：依赖具体人名、书名、固定数值、事件顺序或答案模板，无法抽象为方法。

不设正式条目数量目标。缺少独有动作的候选宁可合并或删除，也不为覆盖来源行而增加近重复条目。

## 5. 批次与回滚

1. **schema 与行为样例**：格式测试、人物字段收口、三维查询与本书化链路样例。
2. **设定**：先裁决 104 条及转交规则，再按世界/规则/机制与能力/物品/组织/制度/地点分两批写正式内容。
3. **人物**：先裁决 101 条及转交项，再按角色与关系分两批写正式内容。
4. **命名**：先裁决 79 条，再按书卷章与故事对象命名分两批写正式内容。
5. **集成收口**：跨维近重复、真实问题命中、计划对象实例化、事实转正、README、技能与 installer。

每个维度形成独立提交和内容审查记录。回滚某维只删除该维正式条目与对应测试/文档，不回退已经验证的计划/事实运行时框架，也不引入旧格式双读。

## 6. 验证

- 格式：三维 front matter 只有允许字段，`规划时` 非空，禁止“全部”占位和来源字段回流。
- 查询：真实问题与类型筛选每维最多三条；无命中返回空集；允许组合、拒绝和自定义。
- 本书化：候选来源与本书适配写入计划对象，命名结果附着对象，未选候选不落盘。
- 事实：计划对象创建、修改、放弃、无冲突转正、冲突/歧义阻断和 hash 漂移行为保持通过。
- 内容：每条正式知识通过唯一归属、近重复、非模板化和失败模式独立审查。
- 分发：源码与 installer 内的 references、技能和测试保持一致。

## 7. 风险

| 风险 | 防线 |
|---|---|
| 284 条一对一平移造成知识膨胀 | 先做全量裁决和聚类，正式条目不设数量目标 |
| 具体金手指/人物/名称成为默认模板 | 删除实例、数值、正反例和固定组合；只保留方法与边界 |
| 人物与技法混维 | 只保留长期行为/关系机制；呈现方法转篇章任务 |
| 命名形成平行实体库 | 正名/别名只写计划对象或书级产物 |
| 通用知识升级改变在写作品 | 下游只读本书化计划对象和定稿事实 |
| schema 再次膨胀 | 每个字段与小节必须有当前消费者和行为测试 |
