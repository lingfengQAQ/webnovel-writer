# 知识库十维集成审计

## Goal

在所有实现与内容子任务完成后，对十维知识库进行跨维、跨调用链和真实使用审计，确认分类清楚、调用有效、扩充有据且不会因固定路由导致同质化。

## Requirements

- 前置依赖：父任务治理真源已冻结，运行时框架及三个内容策展子任务均已完成、通过各自验收并完成开发阶段签收。
- 审计十维边界、别名/名称唯一性、近重复、作用尺度、硬软知识分离和版本冻结。
- 审计建书、规划、写作、审稿、定稿、复盘的调用覆盖及降级路径。
- 用多本同题材/复合题材样例验证候选多样性和本书化差异。
- 审计 v6 候选资产策展清单，确认每条都有保留、重写、拆分、合并或删除裁决，且无模板化回流。
- 审计故事对象的计划/事实两阶段、章级整体确认、近期历史软降权、最小使用记录，以及运行时不存在作者扩库入口。
- 审计普通条目策展与维度架构变更的两级治理，确认每条正式知识只有一个 canonical 归属。
- 验证 installer、目标架构一次性切换、源码回滚点与文档真源一致性；明确断言十维知识切换不存在旧 v7 知识路径双读、知识 schema 兼容层或知识迁移器。仓库既有 v6→v7 书仓迁移不在本断言范围。
- 验证章级知识来源在确认细纲时与原文 hash 原子冻结；后续引用变更/删除不改变本章来源，缺失、旧版或不匹配快照 fail closed。
- 验证事实裁决的执行语义来自所选 option 的 `applyChange`；false 在事实写入、计划删除、碰撞、暂存 payload 与叠加视图中均无副作用。
- 验证契约更新只从下一未定稿章立即生效，全部未发布工件由持久守卫保护；暂存只生成原始定稿包 hash 证明，直到 commit confirmed 才精确释放，篡改、状态洗回和提交未知均 fail closed。
- 验证两审结果以完整 `ReviewInput` 的确定性令牌绑定章号、草稿、作品契约与审稿上下文；契约更新前已发出的旧两审结果即使正文相同也不能延迟回流，缺失或漂移令牌在 save-review、暂存和定稿入口均 fail closed。

## Acceptance Criteria

- [x] 每个顶层维度均有独立调用证据、真实消费者和可验证产物。
- [x] 全部存量条目有唯一 canonical 归属；跨维使用通过组合或拆分完成，不复制条目，也不依赖无消费者的协同维度元数据。
- [x] 同题材样例不会产生固定创意包或固定章节组合。
- [x] 运行时没有知识评分、章后反馈、作者提交或自动扩库能力；计划对象不会被误当作定稿事实。
- [x] 未决策清单清零，任务、README、spec、代码和测试对最终状态描述一致。
- [x] 全量测试、格式校验、installer/e2e 与人工内容审查通过。

## Notes

- 审计优先把偏离路由回责任域；因四个责任子任务均已签收归档，集成验收发现的阻断性契约缺口可在本任务做最小修复并补行为证据，不借机扩展无关能力。
- 启动前补齐自身 `design.md` 与 `implement.md`；审计本身不建立回滚代码，任何修复由责任子任务独立提交和回退。
