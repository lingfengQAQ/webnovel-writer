# Design：知识库十维集成审计

## 1. 目标与非目标

在十维内容全部落地(基线 286 条:题材 19/流派 24/创意约束 11/设定 27/人物 28/命名 17/节拍 63/场景 37/技法 49/追读 11)后,做跨维、跨调用链和真实使用的最终审计,产出父任务 32 条 AC 的验收证据映射。

目标:

- 全库结构审计:唯一 canonical 路径、名称/别名冲突、跨维近重复、硬软知识分离。
- 全链行为审计:建书→对象→细纲→写作→审稿→定稿→复盘的调用覆盖与降级路径。
- 反同质化实测:四类作者场景(同题材多书/复合题材/明确作者/空白作者)不产生固定答案。
- 负向断言:无旧 v7 知识路径双读或知识 schema 兼容层、无评分/反馈/作者扩库入口、无无消费者字段；既有 v6→v7 书仓迁移不在此断言范围。
- 挂账项清算:各子任务转交与建议项逐一落定或明确记入后续任务。
- 产出父 PRD A1–A32 逐条证据映射,支撑父任务收口。

非目标:

- 不新增知识条目或无关产品能力；明确内容错误直接修。责任子任务已归档后才暴露的父 AC 阻断缺口，在本任务做最小契约修复并补回归，不借审计大改架构。
- 不重做各子任务已通过的逐条内容审查;抽样复核为主。
- 不处理 beta 其余事项(真写 50 章、v6 迁移、npm 发版)。

## 2. 审计输入

- 治理真源:`v7/docs/knowledge/`(宪章/调用者矩阵/策展规则)。
- 五个已归档子任务的裁决与审查记录(archive/2026-07/07-10-*)。
- 挂账清单(来源见 implement 门 0):
  1. 签收抽查 S1–S3/S5–S7 建议项(词表统一、索引区分说明、候选密度提示)。
  2. 终测卡点:场景近邻抢位(关键词误召)、技法候选无优先级。
  3. 转交项:诊断族 PA-003/032/042(第二阶段知识族)、PA-005/SP-095/CH-052(人物维候选)、TR-073(创意约束候选)——集成审计确认登记完整并决定「本轮落地 / 立后续任务」。
  4. codex review Minor:创意约束「不可逆代价」↔ 设定「能力代价与使用边界」近重复;SP-075 双线弱覆盖(已补 PA-036,复核)。
- 文风纪律:条目正文文学化词汇——真源为 `v7/docs/knowledge/策展规则.md` 第 7 节(作者 2026-07-21 拍板,已补录);章级四维已整改,书级/故事对象维度未过整改,批次 1 抽样核查。

## 3. 审计方法

- **结构审计**用脚本化扫描(名称重复、路由表对齐、FM 字段白名单跨十维核对)+ 近重复抽样对比,不逐条人审。
- **行为审计**以现有行为测试为底,补缺口测试而非重写;真实使用走 e2e 建书样例。
- **反同质化实测**：固定路由保持确定性；用同一分类下两套作者选择证明材料包不收敛到唯一契约，并用近期历史变化证明章级软排序改变而合法复用仍保留。明确作者与空白作者另做宿主语义走查，不把静态字符串断言冒充真实生成结果。
- **修复边界**:错字/失效引用/文档数字不一致→直接修;条目归属或维度定义问题→按策展规则记录裁决建议,普通策展级的小修直接做,架构级的写入报告等作者决定。
- 全部产物落 `research/`:结构审计报告、行为审计报告、反同质化实测记录、挂账清算表、父 AC 证据映射。

## 4. 验证

- 全量测试、format、installer e2e、`git diff --check`、task validate。
- 未决清单清零:README/spec/治理文档/代码/测试对最终状态描述一致。
- 父 A1–A32 每条标注:已达成(证据路径)/ 部分达成(缺口与责任)/ 不适用(理由)。

## 5. 风险

| 风险 | 防线 |
|---|---|
| 审计变成第二次全量重审 | 结构走脚本、内容只抽样;逐条审查已由子任务完成 |
| 顺手修出新问题 | 修复只限明确错误;结构性修改一律记录不动手 |
| AC 映射流于形式 | 每条 AC 必须给出可点开的证据路径(测试名/文件/记录) |
| 挂账项悬空 | 每项二选一:本轮落定,或写明后续任务与触发条件 |
