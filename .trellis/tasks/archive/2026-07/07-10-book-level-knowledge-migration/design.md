# Design：书级知识校准与策展

## 1. 设计目标与约束

本任务只校准作品契约层的 `题材 / 流派 / 创意约束` 内容及其直接调用闭环。目标不是增加条目数量，而是让建书调用者能完成三件事：准确归一作者已经明确的分类；只对真实未决问题提供少量可改造材料；把最终选择蒸馏为本书独有、可执行、可审查的作品契约。

已冻结约束：

- 题材回答基本虚构空间与核心读者承诺，流派回答长期推进引擎，创意约束回答主动接受的限制与代价。
- `类型` 单选，`副题材` 只能取 canonical 题材，`流派` 多选；路由只归一名称和提示兼容范围。
- 正式通用知识只在开发阶段策展。作者只选择和修改本书方案，不参与通用扩库。
- v7 尚未生产，直接删除错误路径、字段和别名；不做旧书迁移、双读或兼容层。
- 不改变十维、候选上限、查询排序、作品契约八节或持久化流程。必须改变这些契约时，停止对应批次并回父任务走架构变更。

## 2. 目标内容清单

### 2.1 题材：19 个 canonical 条目

现有 16 个题材中删除题材路径 `快穿 / 种田`，保留并校准其余 14 个，新增 5 个。每个条目只承担一项核心承诺；表中“主要分界”是正文必须写清的最低边界，不是别名列表。

| 题材 | 核心承诺 | 主要分界 |
|---|---|---|
| 都市 | 当代城市空间中的身份、资源、职业或超常杠杆 | 真实制度与普通人后果主导时选现实；现代关系主导时选现言 |
| 现实 | 真实制度、职业、家庭与公共生活的因果压力 | 不以超凡或万能金手指改写基本因果；不等于泛都市背景 |
| 现言 | 当代社会中的亲密关系与情感选择 | 职业、财富或行动冒险主导时选都市 |
| 年代 | 特定近现代时期的物质条件、制度变化与生活记忆 | 泛现实生活不自动归年代；四合院等具体空间不是别名 |
| 历史 | 历史时期的公共秩序、政治制度与时代进程 | 江湖侠义选武侠；古代关系生活选古言；军队任务选军事 |
| 古言 | 古代或仿古社会中的关系、家族与生活承诺 | 不以朝代政治或战争进程作为唯一主轴 |
| 武侠 | 江湖、门派、武学、侠义与人情秩序 | 超脱修行选仙侠；朝代治理选历史 |
| 军事 | 军队组织、指挥链、任务、战术、后勤与战场代价 | 可与历史或科幻组合，但军事职责必须承担主线因果 |
| 玄幻 | 东方幻想力量秩序、成长与超凡冲突 | 修真求道主导时选仙侠；西式文明与魔法主导时选奇幻 |
| 仙侠 | 修炼、求道、因果与超脱秩序 | 宗门只是可能的组织结构，不作为题材别名 |
| 奇幻 | 非东方修真范式的魔法、种族、神话与异世界文明 | 关系承诺主导时可选幻言；不能只凭“有魔法”自动归一 |
| 幻言 | 幻想空间中的关系与情感承诺 | 世界规则或力量成长主导时选玄幻、仙侠或奇幻 |
| 科幻 | 科学技术或理性推演改变个体与文明边界 | 文明崩坏后的生存秩序主导时选末世 |
| 末世 | 文明崩坏、生存稀缺与秩序重建 | 灾变成因可以是科技，但不因此自动改判科幻 |
| 悬疑 | 公平线索、谜题推进与真相追索 | 真相承担核心兑现；惊悚体验本身不是题材归一依据 |
| 灵异 | 超自然威胁、禁忌、仪式、生存与可保留的未知 | 不要求所有未知被解释；可与悬疑组成主副题材 |
| 游戏 | 游戏规则、虚拟空间、玩家身份及电竞职业语境 | 现实运动选体育；普通竞争不等于游戏 |
| 体育 | 运动规则、训练、赛季、队伍与职业结果 | `竞技` 是推进方式候选，不是自动题材别名 |
| 衍生 | 原作识别点、改写边界与新增变量构成的来源契约 | 必须再选至少一个实际世界副题材；不复制该题材的世界规则 |

`青春` 本轮不入库，也不固定映射现言或都市。输入“青春/校园”时继续辨别关系、成长、现实空间或幻想学院承诺。

### 2.2 流派：24 个基础 canonical 条目

现有 22 个流派全部保留为基础清单，但须剥离世界设定、固定节奏和人物模板；新增从题材移入的 `快穿流 / 种田经营流`。若逐条审查证明某一基础条目无法形成独有长期引擎，必须先回到规划工件记录合并或驳回，不能在内容批次中静默删除。

| 分组 | canonical 条目 | 校准重点 |
|---|---|---|
| 身份与时间 | 穿越流、重生流、快穿流 | 一次身份转换、时间重置、跨世界任务循环三者分开 |
| 任务与规则 | 系统流、无限流、规则怪谈 | 反馈任务、副本元成长、规则生存三种引擎分开 |
| 经营与职业 | 种田经营流、直播流、娱乐圈、学院流 | 保留可重复的生产/反馈/职业/培养循环，删除具体世界默认 |
| 实力与策略 | 无敌流、稳健流、扮猪吃虎流、黑暗流 | 分清实力起点、风险策略、信息隐藏和高代价选择，不用语气或人设充当引擎 |
| 身份逆转 | 退婚流、赘婿流、多子多福 | 保留长期身份/资源反馈，删除固定开局章数和人物组合 |
| 关系推进 | 追妻火葬场、狗血言情、替身文 | 以可重复的关系因果和代价推进为核心，不能预设无条件宽恕 |
| 调查与未知 | 悬疑推理、克苏鲁、诡秘流 | 分清证据推理、认知代价和隐秘秩序推进；世界规则转交设定维度 |
| 神话介入 | 洪荒流 | 只保留已知神话时间线的介入与改写引擎；神话实体规则不复制 |

`竞技` 与“势力建设”不进入基础清单。它们保留为准入候选：只有近重复审查证明存在独有问题、动作、失败模式和调用触发，才先更新本设计与裁决记录，再建立正式条目。

### 2.3 创意约束：不设数量指标

九份 v6 来源先聚类再逐条准入，候选搜索簇包括：不可逆或可耗尽代价、条件触发、优势兼为弱点、信息不完整或会衰减、规则/对手会适应已用解法、成功引入债务/暴露/责任或更大威胁、遵守规则同样付出代价、资源总量固定或能力可被共享/夺取、知识优势因因果偏移而失效、不可绕过的法律/道德/物理边界。

这些只是查重入口，不等于十个预定条目。镜像反派转人物任务，规则实例转设定任务，开篇钩子与表现方法转篇章任务；评分、市场时效、具体案例、固定组合包和普通卖点模板删除。

## 3. 最小内容契约

### 3.1 Front matter

| 维度 | 唯一允许字段 | 理由 |
|---|---|---|
| 题材 | `名称` | canonical、别名和路径已由 `路由.csv` 负责 |
| 流派 | `名称` | 兼容题材由 `路由.csv` 负责，失败模式只保留正文真源 |
| 创意约束 | `名称`、`一句话` | 查询索引和候选展示真实消费这两个字段 |

删除题材/流派 front matter 的 `毒点`，删除流派的 `适用题材`。不增加来源、状态、评分、类别、关键词或其他无消费者字段。

### 3.2 正文小节

| 维度 | 必需小节 | 调用职责 |
|---|---|---|
| 题材 | `核心承诺 / 选择边界 / 本书化问题 / 失败模式` | 前三节供建书归一与蒸馏，失败模式供写入本书审查边界 |
| 流派 | `推进引擎 / 组合边界 / 本书化问题 / 失败模式` | 前三节确定长期引擎及组合方式，失败模式进入本书审查边界 |
| 创意约束 | `约束机制 / 适用边界 / 本书化问题 / 失败模式` | 机制内同时写明被挑战常规、决策压力、长期驱动与防绕过；其余小节负责迁移、实例化和审查 |

每条只写可迁移原理、选择问题与失败结果，不写具体书名、人名或可复刻情节。正文不再保留与 front matter 重复的“毒点展开”。

创意约束的 `一句话` 既要可展示，也要含作者真实会使用的触发短语；可用顿号分隔少量同义问题片段，复用现有索引能力，不新增关键词字段。

## 4. 路由与别名切换

`路由.csv` 仍保持 `名称,维度,题材,条目,别名` 五列：题材行的 `题材` 为自身 canonical；流派行的 `题材` 是已知兼容范围。流派兼容范围为空表示没有必要做窄范围提醒，运行时不得把空值误报为不兼容；删除无信息量的 `全部`。

别名只有在“无需继续追问也会得到同一 canonical 选择，且不会丢失另一维信息”时才允许。只是常见搭配、子情节、设定空间、人物身份、体验词或复合词的输入不作为别名；它们保持未命中并进入对谈辨别。

切换规则：

- 删除题材路由 `快穿 / 种田`，新增流派路由 `快穿流 / 种田经营流`；“快穿/种田”只作为对应流派的精确别名。
- 新增题材 `武侠 / 现实 / 军事 / 体育 / 灵异`。
- 从历史删除“武侠/争霸权谋”，从悬疑删除“灵异/惊悚”，从游戏删除普通“竞技”，从科幻删除“赛博朋克”，从年代删除“四合院”。
- 从仙侠删除“宗门流”，从玄幻删除“玄幻修仙/修仙/玄幻”等复合输入。
- 从洪荒流删除“封神/上古”，从规则怪谈删除“规则类”，从替身文删除“白月光”，从追妻火葬场删除“虐文/先虐后甜”，从学院流删除“校园成长”。
- `恐怖 / 惊悚 / 青春 / 校园 / 竞技 / 基建 / 经营 / 慢生活` 等跨维或体验词保持未命中，由建书对谈继续辨别；不建立一对一猜测别名。
- 每个 canonical 名称和别名全表唯一；每个题材/流派正式文件恰有一个路由行，每个路由路径恰有一个文件。

本任务不扩展 `resolveLabel` 语法。复合输入无法一对一表达时如实未命中，调用者继续收集主题材、副题材和流派，不静默丢掉第二维。

## 5. 建书调用闭环

```text
作者构想
  -> 精确 canonical 归一；歧义词继续辨别
  -> knowledge-pack 读取已选题材/流派全文
  -> 只对未决创意问题查询最多三条创意约束
  -> 作者选择、组合、改造、拒绝或自定义
  -> 形成题材融合协议与本书化约束
  -> 契约校验
  -> 作者确认后原子落盘
```

复合题材协议只在调用者中维护一份，不复制到 19 个题材条目。`knowledge-pack` 与建书技能在存在副题材时要求依次回答：共同核心冲突、主题材承诺与主线因果、副题材介入条件与独立贡献、规则兼容或隔离、主副线职责、冲突解决方式、主要失焦风险。标签露出次数不能证明融合成立。

通用知识只到作品契约为止。写作备料与编辑审继续读取作者确认的 `作品契约/作品契约.md`，不逐章回读这些通用条目。

## 6. 契约校验的窄改动

本任务允许两项不扩 schema 的条件校验：

1. `类型=衍生` 时，`副题材` 至少包含一个非“衍生”的 canonical 题材；否则建书和契约更新失败。原作识别点、改写边界与新增变量写入现有正文小节，不增加来源字段。
2. `节奏与兑现参数` 出现比例、每若干章一次等数值配额时，同节必须写清统计对象、使用目的和失效条件；作者确认即是采用本书专属数值的确认。没有数值时不要求占位字段。

同时修正流派空兼容范围的提醒行为。除此之外，解析器、候选排序、作品契约结构和持久化保持不变。

## 7. v6 裁决与内容审查

实施期建立三类任务内记录：

- `research/题材流派逐条裁决.md`：每个来源条目、最终 canonical、动作、相邻边界、别名/兼容变化和理由。
- `research/v6创意资产裁决.md`：九份来源按标题或表格 ID 唯一定位，记录主要问题、目标维度、近重复、保留/重写/拆分/合并/删除及去向。
- `research/content-review/`：题材、流派、创意约束分别独立审查，逐项核对唯一问题、唯一动作、失败模式、调用触发、可区分性和模板化风险。

来源片段可以多对一合并，一个来源也可以拆往不同维度；正式库不保留旧 ID、评分或来源叙事。转交其他子任务只记录候选与理由，不在本任务代写目标条目。

## 8. 验证、切换与回滚

格式测试负责字段、小节、路由全覆盖和禁止模式；行为测试负责移动后的归一、歧义未命中、空兼容提醒、衍生校验、数值配额条件校验和复合协议提示；内容质量由逐条裁决与独立审查负责，不能用测试替代。

切换按以下回滚边界执行：

1. 调用者与校验器窄改动，可独立撤销。
2. 题材、流派、路由及其格式契约作为一次 taxonomy 原子切换；内部按题材、流派分别审查，但不留下快穿/种田同时存在两个 canonical 路径的提交。
3. 创意约束正式内容与其格式测试独立提交；整批可撤销为空目录降级。
4. 技能提示、README、裁决和内容审查记录随对应内容批次提交。

每个边界执行定向测试，最终执行全量测试与 installer e2e。回滚只撤销本任务提交，不恢复旧路径或兼容逻辑。

## 9. 明确交给后续任务的事项

- `竞技`、势力建设只有通过正常准入并先更新规划才可新增，不在路由中占位。
- 洪荒、克苏鲁、诡秘拆出的世界规则候选交故事对象知识任务。
- 镜像反派、规则实例、开篇钩子和表现方法分别交人物、设定和篇章知识任务。
- 复合输入语法、跨维歧义解析、查询算法或新字段若确有必要，登记父任务或集成审计，不在本内容任务临时实现。
