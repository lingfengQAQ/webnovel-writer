# PRD：知识库重构——三层路由与内容重写

## 背景

M4 P4 把 v6 知识层平移到 `v7/references/`（37 题材模板 + genre-index.csv + 题材与调性推理.csv 26 条 + 爽点与节奏.csv 104 条 + 追读力 taxonomy），此后运行时零消费：

- spec §5 承诺「爽点是知识层……喂给细纲与两审」、§6.1 承诺「反和解建书时按题材模板写入」，实现全部缺席（序1/序6 DTO、备料、review-input、roles 任务书均不含知识层）。
- installer `RUNTIME_ENTRIES = ['bin','src','roles','package.json']` 不装 references——装出去的工作目录里知识文件不存在。
- v6 的消费机制是「CSV 存储 + AI 主动关键词检索」，与 v7 铁律「只吃整理好的 DTO」冲突：检索触发靠模型自觉，不可测试不可复现。

作者拍板（2026-07-07 讨论）：不做简单接线，对知识库整体重写以适配 v7 架构。

## 目标

AI 在需要时能拿到正确的网文方向知识引导；全链路无「AI 主动检索」动作——知识注入由脚本按确定性键查表完成，AI 只在脚本递上的菜单里点菜。

## 需求

### R1 数据层重组（维度立正）
- **题材与流派是两个维度，不得混同**：题材 = canonical genre（玄幻/都市/仙侠…，单选）；流派 = trope/route（退婚流/系统流/赘婿流…，可多选）。现 genre-index 的 label_type/trope_tags/route_tags 已有此区分，重组时保持并强化。
- 运行时知识目录分区：`路由.csv`（唯一保留的表格）+ `题材/` + `流派/` + `节拍/` + `追读/` + `场景/`。
- 多条记录一律每条一个 Markdown 文件（对齐防呆方言）；front matter 承载机器字段（关键词/适用题材/毒点/强度），正文按读者分三节：「规划这一章时」（细纲）、「落笔时」（备料注入）、「审稿时」（编辑审毒点）。
- 现 37 个模板混着题材与流派内容，拆分归位；模板内桥段详解抽出归 `场景/`。
- 「形式」维度**已拍板并入流派**：直播文按网文分类实践归流派（`流派/直播流`）；**知乎短篇删除不迁**——v7 只考虑长篇，短篇载体与平台差异后置。

### R2 三层路由（键在哪，何时注入）
| 层 | 内容 | 路由键 | 注入时机 |
|---|---|---|---|
| 书级 | 题材、流派骨架、恩怨清算力度 | book.yaml `题材`（单）+`流派`（多） | 建书蒸馏成书仓契约，随文风锚点常驻备料 |
| 章级-情绪 | 节拍、章尾钩子 | 细纲声明 `本章节拍`/`章尾钩子` | 备料查表注入 + 审稿输入毒点 |
| 章级-场景 | 场景/桥段技法 | 细纲声明 `本章场景`（多值；脚本先按关键词出候选） | 同上 |

### R3 建书蒸馏（书级知识 → 书仓契约）
- 序1 DTO 附命中的题材+流派条目全文；AI 对谈逐节对撞（「库怎么说 → 你怎么定」）；产出 `文风/题材流派指导.md`，固定结构：front matter（题材/流派/来源条目@hash 或 `来源: 对谈共创`）+ 四节（骨架约定 / 差异化点【必填≥3】/ 本书专属毒点 / 节奏参数）。
- 「恩怨清算」规则**归入知识库且不设中央条目**：反和解纪律（反派恶意落实处、冲突升级到底、禁说教式和解、禁圣母）分布在各条目的毒点与「落笔时」节里（现有条目已有大量此类内容，P2 重写时逐条目审计覆盖、缺的补进对应条目）；书级只保留一个档位——各题材文件 front matter 存 `恩怨清算默认`（三档：有仇必报 / 恩怨分明 / 留有余地，档位语义写在蒸馏范本），建书对谈作者可调，选定档位落契约文件「节奏参数」节。**不写入文风铁律**——文风铁律回归纯作者品味，spec §6.1「反和解」节回填时移除并指向知识条目毒点 + 契约档位。
- 下游消费链只认书仓契约文件，不回读运行时库——库升级不影响在写的书；作者手改契约走手改补登。

### R4 章级消费接线
- 序6 DTO：节拍紧凑索引 + 场景紧凑索引 + 场景候选（脚本拿场景关键词扫卷纲对应段与上一章结尾，只出候选不拦截）。
- 细纲 spec §7 增三字段：`本章节拍`（编号或自定义文本，可空）、`章尾钩子`（钩子类型）、`本章场景`（多值，可空/可自定义）。已获作者同意。
- 备料：按声明查表注入「落笔时」节；review-input：注入命中毒点（题材/流派/节拍/场景四源）；编辑审任务书加「按毒点清单逐条核对」。

### R5 缺口降级（知识库是旁路增益，不是必经关卡）
- 路由未命中：建书流程不变，契约文件改为对谈现场共创，front matter 标注来源。
- 声明查不到表：注入声明文本本身；编辑审退回通用维度。任何缺口不报错、不挡流程。
- 反哺：实践检验过的共创内容人工回流入库；**本期不做自动化**。

### R6 内容重写纪律（反同质化，spec 级规矩）
- 知识条目只写「什么必须发生、什么绝不能发生」（结构与禁忌），不写示例情节；示例只允许以毒点反例形式出现。
- 蒸馏模板「差异化点」必填；毒点主要喂编辑审（负面清单），写作材料只注入声明命中的条目，从不整库灌生成上下文。
- v6 检索时代的列（意图与同义词/默认查询词）随重写瘦身。
- **纪律约束对象是叙事结果与主角行动线，不禁角色设计**：恩怨清算/反和解类毒点措辞一律写「恩怨结算不得X」「主角不得X」，不写「不得出现X角色」。圣母/和事佬配角是合法人设与冲突来源（人设写角色卡，无机器字段）；红线是**叙事背书**——此类主张不得被情节证明为正确并软化恩怨结算（档位「留有余地」除外）。

### R7 installer 与升级
- 知识目录进 `RUNTIME_ENTRIES`，纳入哈希清单，走 update 升级流（改过的提示并跳过）。

### R8 spec 回填
- spec §5/§7/§8 相应措辞回填（细纲字段、知识注入点、书仓契约文件）；版本号推进并记决策。

## 验收标准

### 行为（自动化测试覆盖）
- A1 建书（含未命中路由的题材）产出契约文件且结构合规；恩怨清算档位落契约「节奏参数」节；文风铁律不含题材知识。
- A2 细纲声明节拍/场景后，写作材料含对应「落笔时」节，审稿输入含对应毒点；自定义声明降级为注入声明文本。
- A3 无契约文件的书（存量/迁移书）全流程照常，零报错。
- A4 installer 全新安装含知识目录；update 按哈希升级。
- A5 格式校验：全部知识文件 front matter 可解析、三节齐全、路由键唯一、题材/流派归维正确（label_type 与目录一致）。

### 内容质量关（作者明确要求：测试测不出来，必须仔细审查）
- A6 **每一条重写后的知识条目过逐条内容审查**，审查清单：①无示例情节（示例仅毒点反例）②毒点可执行可核对 ③三节读者定位正确 ④题材/流派维度归位正确 ⑤与 v6 原条目对照无信息遗失，或遗失记为「有意删除」。
- A7 内容审查独立于实现者（新鲜上下文审查，不由写条目的同一会话自审）；审查记录落任务目录。
- A8 作者抽查签收后条目方可入库；未过审条目不进 installer 装载范围。

## 非目标
- 反哺自动化、语义检索插件、知识库运行时热更新。
- 「AI 主动关键词检索」不保留（v6 机制废弃）。
- 短篇载体（知乎短篇等）与平台差异化预设（番茄/起点节奏）：v7 只考虑长篇，后置。
