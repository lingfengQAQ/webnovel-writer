# Design：知识库重构——三层路由与内容重写

## 1. 总原则

- 知识什么时候进上下文由脚本决定（能数的），进哪一条由 AI 在细纲里声明（要判断的）。AI 无「检索」动作。
- 知识库是旁路增益不是必经关卡：任何缺口走降级，不报错不挡流程。
- 下游只消费书仓契约与声明命中的切片，不整库灌上下文。

## 2. 数据层终态

```
.webnovel/知识/
├── 路由.csv              # 原 genre-index：label → 题材/流派/形式 + 别名。纯路由表，保留 CSV
├── 题材/玄幻.md 都市.md …           # canonical 一个一份（~15）
├── 流派/退婚流.md 系统流.md 赘婿流.md …
├── 节拍/PA-001-压抑蓄力爆发.md …     # 原爽点与节奏 104 条
├── 追读/钩子-危机钩.md 钩子-悬念钩.md …  # taxonomy 拆条
└── 场景/拍卖会.md 突破.md 打斗.md 谈判.md …  # 从题材模板桥段详解抽出 + 新写
```

条目文件统一格式：

```markdown
---
编号: PA-001            # 节拍/追读用；题材/流派/场景用名称即键
关键词: 拍卖|竞价|压价    # 场景候选扫描用；节拍菜单展示用
适用题材: 全部           # 或题材列表
毒点:
  - 逐口报价流水账
  - 底牌提前透光
---
## 规划这一章时
（细纲读：信息位排布、适用前提）
## 落笔时
（备料注入：视角纪律、节奏禁忌、必须发生/绝不能发生）
## 审稿时
（毒点展开，进审稿输入给编辑审）
```

**形式维度（作者已拍板：并入流派；2026-07-07 补充核实）**：直播文在网文分类实践中即为挂靠都市等大类下的写法流派（可跨背景叠加，常与系统流结合），归 `流派/直播流.md`；知乎短篇删除——v7 只考虑长篇，短篇载体与平台差异（番茄/起点节奏预设）后置。book.yaml 不设第三字段；`路由.csv` 的 format 列保留为空备未来扩展。

**book.yaml 增量**：`题材: 玄幻`（单值，canonical）+ `流派: [系统流, 退婚流]`（列表，可空）。别名归一在建书问答时由脚本按路由表完成（纯字符串匹配）。

## 3. 三层路由数据流

### 3.1 书级（建书，序1）
1. 问答收集题材+流派 → 脚本别名归一 → 命中的 `题材/<X>.md` + `流派/<Y>.md` 全文进序1 DTO（1 题材 + 1~2 流派，万字级，一次性成本可承受）。
2. AI 对谈逐节对撞：「库怎么说 → 你怎么定」，作者的取舍（含「不按常规」）即蒸馏结果。
3. 落纸 `文风/题材流派指导.md`：
   - front matter：`题材` / `流派` / `来源`（条目@hash 列表，或 `对谈共创`）
   - 正文四节：本书遵循的骨架约定 / 本书的差异化点（必填 ≥3）/ 本书专属毒点 / 节奏参数（如首打章数）
4. 恩怨清算不设中央规则文件：纪律分布在条目毒点（P2 审计补齐）；题材 front matter `恩怨清算默认` 三档（有仇必报/恩怨分明/留有余地，语义在蒸馏范本），作者对谈可调，选定档位落契约「节奏参数」节。**档位约束的是主角行动线与恩怨结算结果，不约束配角人设**——圣母/和事佬配角合法（角色卡自由设计），红线是其主张不得被叙事背书并软化结算（低档除外）；编辑审按此口径核对（motivation 维度本就只盯主角）。文风铁律不写题材知识（spec §6.1「反和解」节回填时移除）；契约随建书 commit 入库。
5. 备料（prep）把契约文件随文风锚点常驻注入写作材料。

蒸馏本质：把通用流派知识和本书设定连接一次，固化成作者签字的本书写作契约。之后库升级不影响在写的书；作者手改契约走手改补登（序2 范围内文件）。

### 3.2 章级-情绪（细纲声明 → 查表）
- 序6 DTO 附节拍紧凑索引（编号+关键词+一句摘要，~110 行）与追读钩子类型清单。
- 细纲声明 `本章节拍: PA-001`（或自定义文本）、`章尾钩子: 悬念钩`。
- 备料按编号注入「落笔时」节；review-input 按编号注入「审稿时」毒点。

### 3.3 章级-场景（候选 + 声明 → 查表）
- 序6 备料时脚本拿 `场景/*.md` 的关键词列扫**卷纲对应段落 + 上一章结尾**，命中的进 DTO「候选场景」——只出候选不拦截（同机检泄密候选模式）。DTO 同时附场景紧凑索引全量。
- 细纲声明 `本章场景: 拍卖会, 突破`（多值）；备料/审稿输入按声明查表注入。
- 写稿中途冒出的未声明场景不追：细纲外重大内容本就是两审「要写到的事逐条核对」的抓捕范围；顺笔小场景无加持可接受。

### 3.4 缺口降级（三处统一）
| 缺口 | 行为 |
|---|---|
| 建书路由未命中 | 契约文件改对谈共创，`来源: 对谈共创` |
| 细纲声明自定义/查不到 | 注入声明文本本身（「声明即知识」） |
| 书无契约文件（存量书/迁移书） | 备料跳过该锚点，全流程照常 |

## 5. 反同质化防线（内容纪律，进 spec）

1. 条目只写结构与禁忌，不写示例情节；示例仅毒点反例。
2. 蒸馏「差异化点」必填 ≥3——蒸馏是过滤器不是复印机。
3. 毒点喂编辑审（负面清单），生成侧只注入声明命中条目。
4. 流派骨架层的「同质」是卖点兑现（读者预期），不属同质化；机检层（复读检测/高频意象）管跟自己前文的同质。

## 6. 兼容与回滚

- 全部注入点是加法且有降级路径：存量书、v6 迁移书无契约文件照常运转（A3）。
- 回滚 = installer 不装 `知识/` + DTO/备料跳过锚点，行为退回当前状态；数据层无破坏性改动（references/ 原样保留至内容重写完成后替换）。
- 迁移书补契约：作者说一声可对存量书补跑一次「蒸馏对谈」（复用序1 的对撞流程，产物同格式）——列为本任务可选项，最坏不做也不影响主线。

## 8. 内容质量关（A6-A8 的落地机制）

- 每条重写产出附带审查记录（任务目录 `research/content-review/<条目>.md` 或汇总表）：五项清单逐项勾。
- 审查由独立新鲜上下文执行（子代理或独立会话），不与撰写同一上下文。
- 作者抽查：每批交付时给作者抽查清单（按目录分层抽样），签收后该批才进 RUNTIME_ENTRIES 生效范围。
