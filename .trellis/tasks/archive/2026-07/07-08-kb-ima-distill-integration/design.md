# Design：知识库 ima 蒸馏收编

## 1. 总原则

- 沿用 P2 内容流水线：**改写/定稿 → 独立新鲜上下文审查（五项清单）→ 作者抽查签收 → 入生效范围**。批次是内部工序，不是交付边界。
- 落盘目标只有 `v7/references/`；`v7_fix_package/` 是工作区输入，任务结束整目录删除、永不入 git。
- 内容纪律沿用 spec R6：条目只写结构与禁忌，不写示例情节；毒点措辞约束叙事结果与主角行动线（"主语+不得——须"）。

## 3. 五档扩展（唯一代码改动）

- `src/commands/knowledge-pack.js:46`：`有仇必报|恩怨分明|留有余地` → `有仇必报|宿命必偿|恩怨分明|以直报怨|留有余地`（按力度从狠到缓排序）。
- `test/references/format.test.js:66`：合法档位数组同步五档。
- 档位语义（写进 knowledge-pack.js 范本文案或其邻近说明，短句）：
  - 有仇必报：结仇必清算，代价足额落地，不留活口式收尾。
  - 宿命必偿：清算可迟到不缺席，因果闭环由叙事兜底兑现。
  - 恩怨分明：有恩报恩有仇报仇，等价对付，不扩大化。
  - 以直报怨：以公正回应仇怨，威胁未除不滥慈悲，除害不虐杀。
  - 留有余地：结算保留回旋空间，允许有代价的宽宥。
- `test/knowledge/pipeline.test.js` 用"有仇必报"作测试数据，仍合法，不动。
- 先行落地（门0）：末世条目才能过 format 校验。

## 4. 诡秘流泛化重写要点

- 维度：流派（front matter：名称/适用题材/毒点，无档位字段）。
- 知识对象定位：仿诡秘文的骨架约定——克苏鲁条目管"怎么写恐惧"，诡秘流管"怎么搭这类书"。
- 保留（泛化表述）：蒸汽朋克/近代幻想现实基底须考据落地；分层途径式晋升体系自洽（每阶有规则/限制/代价）；神秘感冰山式铺设不透支；高位存在不可祛魅；神性与人性平衡、主角不彻底非人化；宿命闭环的旅程结构。
- 去除：《诡秘之主》专名（序列/途径具体名、扮演法、愚者、旧日/外神谱系、"维多利亚"限定——泛化为"近代工业/蒸汽时代基底"）。
- 与克苏鲁的边界写清：恐惧纪律类毒点（未知留白、代价递增）不重复收录，条目内不互相引用（条目间无引用机制）。
- 适用题材：悬疑、玄幻（重写时按内容定稿，过审查确认）。

## 6. 审查协议（沿用 P2）

- 每批产物由**独立新鲜上下文**（子代理，不带本会话结论）按 P2 五项清单审查（清单模板取自 `07-07-knowledge-layer-rework/research/content-review/` 既有记录），记录落本任务 `research/content-review/批X-*.md`。
- 近重复核查随批执行：批D 节拍新 3 条 vs 全库 99 条主题比对；批F 追读新 5 钩 vs 既有 5 钩。发现近重复 → 按批3先例给合并/驳回建议，作者裁决。
- 审查意见分级：通过 / 通过-带微调（审查者直接改）/ 驳回（记录理由，不落盘）。
- 全批完成后作者抽查签收（重点：场景 5 条手法型收编、诡秘流重写、五档语义）。

## 7. 回滚与安全

- references/ 全程 git 跟踪：任一批次出问题 `git checkout -- v7/references/` 即回滚。
- v7_fix_package/ 未跟踪：删除即净（删除前确认 cloud_new 内容已消费完毕——诡秘流重写完成后原始诡秘.md 不再需要）。
- 五档扩展与内容批次解耦：若五档被否，仅末世条目档位需改，其余批次不受影响。
