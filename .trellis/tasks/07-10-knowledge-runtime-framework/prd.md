# 知识库运行时调用框架

## Goal

在父任务十维治理规范确定后，实现知识从候选、选择、本书化、持久化、精准注入到审查的运行时闭环，避免全量菜单、固定答案和无人调用的知识内容；不把开发阶段扩库治理做成作者侧运行时功能。

## Requirements

- 前置依赖：父任务 `07-10-knowledge-taxonomy-governance` 的最终规划已审核，十维宪章、分维 schema 原则、调用者矩阵和目标书仓路径已冻结。
- 支持 `类型`、canonical `副题材`、`流派`、创意约束与融合协议。
- 支持硬约束确定性注入、软策略多候选推荐、显式选择/变体/自定义。
- 支持命名、设定、人物的候选选择、本书化产物、书仓持久化与章级精准读取。
- 支持故事对象“`大纲/创作设计/` 计划对象 → 首次正文定稿后 `定稿/设定/` 事实对象”的两阶段生命周期；无冲突事实随章节原子转正，冲突或歧义必须由作者裁决。
- 支持章级知识的规划/落笔/审稿三阶段调用，修复全量菜单与 `规划这一章时` 无消费者的问题。
- 章级知识随整份细纲确认，不逐项打断作者；近期使用历史只用于降权、机械重复提醒和变体说明，不构成硬禁用。
- 使用记录保持最小化：保存流程本来需要的最终选择与自定义变体；拒绝、修改或审稿问题仅在实际发生时记录，不增加预期/效果占位字段、评分、满意度、章后反馈、自动排名或自动回写通用知识库。
- 不提供面向作品作者的知识提交、审核、评分回传或自动扩库入口；开发候选与策展裁决留在 Trellis 任务产物中。
- 保持知识缺失不阻断创作的降级原则；不实现旧书、旧路径或旧 schema 兼容。新建书从建书确认时冻结所选知识来源版本，后续升级必须由作者显式发起。

## Acceptance Criteria

- [ ] 建书、规划、写作、审稿和定稿的知识调用链均有行为测试与降级测试。
- [ ] 同题材输入不会被固定路由收敛到唯一创意或章节方案。
- [ ] 生成侧与审查侧使用同一版本的本书契约和本书化设定。
- [ ] 设定、人物和命名结果能够持久化、精准读取并接受一致性审查。
- [ ] 计划对象不会被当成既成事实；无冲突事实自动转正，冲突事实不会静默覆盖。
- [ ] 章级知识随细纲整体确认，近期重复只触发软性降权或提醒；不存在逐条评分、章后反馈或作者侧扩库流程。
- [ ] installer、目标 schema 一次性切换和源码回滚点明确且测试通过；不存在旧路径双读或书仓数据迁移器。

## Notes

- 本任务不负责大批量知识内容策展；只提供内容任务所依赖的 schema 和运行时能力。
- 本任务属于复杂任务，启动前须基于已冻结的父任务设计补齐自身 `design.md` 与 `implement.md`；实现按书级真源、故事对象、章级调用和 installer 分提交，任一部分可独立回退且不得引入旧路径双读。
