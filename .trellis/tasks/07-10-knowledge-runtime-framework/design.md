# Design：知识库运行时调用框架

## 1. 目标与非目标

本任务把已经冻结的十维治理规则落实为可验证的运行时闭环。脚本负责 canonical 归一、候选限量、版本固化、路径安全、原子写入和冲突闸门；AI 负责理解作者意图、组合软策略、形成作品方案和提出语义事实差异；作者负责确认作品契约、整份细纲以及真正发生冲突时的裁决。

目标：

- 建书只把通用知识当材料，最终以本书 `作品契约/作品契约.md` 为唯一书级真源。
- 故事对象先落计划区，首次正文定稿时才转为事实，且和章节处于同一 Git 原子提交。
- 章级规划只收到少量相关候选，写作与审稿只收到已选切片。
- 所有新增机器字段都有真实消费者和行为测试。
- 十维任一目录缺失或没有合适条目时，创作仍可自定义继续。

非目标：

- 不在本任务批量迁移或重写 v6/v7 知识内容。
- 不做旧书迁移、旧路径双读、旧 schema 兼容或运行时迁移器。
- 不做知识评分、热门榜、效果回访、作者投稿或自动扩库。
- 不用脚本关键词推断语义事实冲突，也不让固定路由选择创意或剧情答案。

## 2. 总体数据流

### 2.1 建书

    作者意图
      -> 路由只归一 类型 / 副题材 / 流派
      -> 按未决问题查询少量创意约束候选
      -> AI 组合、变体或自定义整体方向
      -> 作者确认作品契约
      -> persist-book 原子写入 book.yaml、作品契约、知识选择记录和大纲

生成和审查从此不再读取当前通用题材/流派条目。通用库后续变化不会改变在写作品；只有作者主动要求升级时，才重新查询并通过独立的契约更新命令落盘。

### 2.2 故事对象

    对象设计问题
      -> 查询 设定 / 人物 / 命名少量候选
      -> persist-design 写入 大纲/创作设计/
      -> 细纲用 本章对象 显式引用
      -> 备料与事实审查精准读取引用对象
      -> 事实审查输出结构化 factChanges
      -> 无冲突或作者已裁决后随正文原子转正

计划对象不是事实。规划可修改、替换或删除计划对象；定稿事实读取器不得把计划区混入既成事实。一次性路人、普通物品和临时地点不要求建计划对象。

### 2.3 章级知识

    本章任务 + 卷纲相关段 + 上章结尾 + 近期使用历史
      -> 节拍 / 场景 / 技法 / 追读各最多少量候选
      -> 规划者选择、组合、变体或自定义
      -> 作者确认整份细纲
      -> prepare 读取所选落笔切片
      -> review 读取同一选择的审稿切片
      -> finalize 把最终选择写进章档案，供后续近期历史使用

近期历史只改变排序并给出重复信号，永不删除候选或阻断复用。是否属于机械重复，仍由规划者结合剧情功能、落地方式和递进关系判断。

## 3. 知识读取内核

### 3.1 维度注册表

`v7/src/knowledge/` 暴露唯一维度注册表：

- 作品契约：题材、流派、创意约束；
- 故事对象：设定、人物、命名；
- 篇章执行：节拍、场景、技法、追读。

注册表只声明目录、调用阶段和允许的最小索引字段，不制造十维统一 front matter。读取器只扫描注册表中的直接目录和 Markdown 文件，不递归吞入 README、治理文档或候选材料。

### 3.2 canonical 路由

`路由.csv` 只服务题材和流派名称归一：

- 输入 `类型` 必须归一为一个主题材；
- `副题材` 和 `流派` 均为可空数组，逐项归一并保序去重；
- 流派的兼容题材只产生提醒，不自动删除作者选择；
- 未命中项原样返回，交由对谈共创，不伪装成 canonical 条目；
- 路由输出不包含创意约束、人物配置、设定方案或章节方案。

### 3.3 条目与来源版本

通用条目读取结果按调用阶段返回：

- 基本信息：维度、名称、稳定编号（仅有需要的维度）、紧凑摘要、路径；
- 规划切片：规划者需要的小节；
- 落笔切片：写作需要的小节；
- 审稿切片：审查需要的小节；
- 来源版本：原始文件内容的 SHA-256，表现为 `路径@sha256:<hex>`。

字段取值由分维适配器完成。缺字段的条目按可用子集返回；目录或文件缺失返回空集。来源 hash 同时固化进本书契约和选择记录，不回写通用条目 front matter。

### 3.4 候选查询

统一查询入口接收 `维度`、当前问题文本、可选精确筛选和近期历史，返回有限候选：

- 精确名称或编号声明优先；
- 只使用该维度已有、且调用矩阵允许的机器字段做确定性筛选；
- 关键词仅用于文字包含匹配，不承担语义理解；
- 没有机械命中时允许返回空集，由 AI 自定义；
- 默认每维最多 3 条，调用者不得改用全量索引作为作者菜单；
- 近期同名使用只降分并附提醒，不硬排除。

候选接口返回的是材料，不含 `推荐答案`、`已选择` 或自动组合结果。命令行提供 `knowledge-query`，供建书和对象设计按实际未决问题调用；章级 DTO 复用同一查询器。

## 4. 作品契约

### 4.1 建书输入契约

`persist-book` 一次性切换为以下必需输入：

    {
      "book": {
        "书名": "...",
        "类型": "canonical 主题材",
        "副题材": ["canonical 名称"],
        "流派": ["canonical 名称"]
      },
      "总纲": "...",
      "卷纲": "...",
      "作品契约": "含 front matter 的完整 Markdown",
      "知识选择": [
        {
          "维度": "题材|流派|创意约束",
          "名称": "...",
          "来源": "维度/文件.md@sha256:<hex> | 对谈共创 | 作者自定义",
          "本书变体": "可选，仅有实际变体时写"
        }
      ],
      "实际裁决": [
        {
          "对象": "实际被拒绝或修改的候选",
          "结果": "拒绝|修改",
          "原因": "仅真实发生时填写",
          "证据": "可选"
        }
      ]
    }

`作品契约` 不再可省略。front matter 必须包含 `类型`、`副题材`、`流派`、`创意约束`、`来源版本`、`契约版本`、`生效起章`、`更新原因` 和 `变更类型`；建书初始值为版本 1、从第 1 章生效、类型为“建书”。分类和来源字段必须与 `book`、`知识选择` 互相校验，不能出现两份不同答案。

正文至少包含以下一级内容小节：

- 核心读者承诺；
- 骨架约定；
- 题材融合协议；
- 创意约束落地；
- 差异化点，至少 3 条；
- 冲突与关系结算原则；
- 本书专属毒点；
- 节奏与兑现参数。

“冲突与关系结算原则”用自然语言明确主角底线、伤害后果、和解条件、救赎条件和允许余地，不存在五档枚举或题材默认值。

### 4.2 书仓产物

持久化层从结构化 `知识选择` 和可选 `实际裁决` 渲染 `作品契约/知识选择记录.md`，而不是让 AI 手写第二份格式：

- 最终选择、来源版本和真实变体同时写入契约 front matter，保证单个契约文件即可驱动下游；
- 选择记录保存本次实际采用的候选证据，以及真实发生的拒绝、修改和自定义过程；
- 不保存全量候选快照、普通未选候选、评分、效果预期或空占位；
- 作者自定义和对谈共创允许没有通用条目 hash；
- Git 历史承担版本历史，不在正文重复维护一套时间流水账。

`作品契约/` 加入源文件跟踪、手改检测、relink 和 git 健康检查。`作品契约.md` 缺失或结构损坏属于阻断性源文件错误，不得回退读取 `文风/题材流派指导.md` 或从 `文风铁律.md` 推导契约。

### 4.3 显式更新

新增 `persist-contract`：只接受作者已经确认的新契约、知识选择和非空变更说明，原子替换两份契约文件并单独提交。新契约必须满足版本严格递增、生效起章不早于下一未定稿章、更新原因和变更类型非空；若要影响已定稿章节，先走现有 impact/retcon 流程。命令不自动扫描最新版知识、不自动升级，也不从 prep/review 隐式调用。

契约更新触发分为三条运行时信号，但任何信号都只能生成修订候选：

- 作者主动提出、重大改纲或阻断性契约冲突：立即呈报差异与影响，在继续受影响章节前确认；
- 同类非阻断契约问题连续 2 章、同卷累计 3 次，或同类方案反复被否决/误解：在下一个作者停顿点呈报；
- 每卷复盘固定包含契约复盘，但没有问题时不制造修改。

只有实际发生的契约相关审稿问题才随定稿章保存最小的条款标识、严重度和问题摘要，供阈值判断；无问题章节不生成占位。阻断问题不允许定稿。卷复盘 DTO 汇总这些实际记录。契约更新后，生效起章及之后的待定稿批次标记为“受影响”，现有写作材料和审稿结果失效，必须重新备料与审查；已定稿章节不受影响。

## 5. 故事对象计划与事实

### 5.1 计划对象格式

`persist-design` 接收一个或多个对象，写入 `大纲/创作设计/设定/` 或 `大纲/创作设计/人物/`。对象最小机器字段：

| 字段 | 用途 |
|---|---|
| `ID` | 跨文件稳定引用与精确读取 |
| `名称` | 作者可读展示与精确名称匹配 |
| `对象类型` | 在设定/人物内部做精确筛选，可选 |
| `正名`、`别名` | 命名结果附着对象并参与重名检查，可选 |

正文至少有“本书设计”和“一致性边界”；知识来源及本书适配写在正文的“知识依据”中，不为了追踪而复制成通用 front matter。计划目录本身就是状态，不增加 `状态: 计划` 字段。

`read-design` 按 ID 或名称精确读取。重复 ID、重复正名以及与现有名册的正名/别名冲突在写入前返回人话错误。

### 5.2 章级引用

细纲增加 `本章对象：<ID 或名称，多个用顿号分隔>`。prep 和事实审查只读取声明命中的计划对象；未声明时不全量注入。声明找不到时按作者文本继续，但给出缺失提醒，不把普通临时对象强制建档。

### 5.3 事实差异与原子转正

事实审查输出的 `factChanges` 是 finalize payload 的可选数组：

    {
      "planPath": "大纲/创作设计/人物/CHAR-001-林晚.md",
      "factPath": "定稿/设定/角色/林晚.md",
      "content": "转正后的完整事实 Markdown",
      "decision": "无冲突 | 作者已裁决 | 冲突 | 歧义",
      "expectedHash": "更新既有事实时必填的 sha256",
      "resolution": "仅作者已裁决时必填",
      "removePlan": true
    }

脚本的责任边界：

- 在写任何文件前校验所有路径、decision 和 expectedHash；
- 发现 `冲突` 或 `歧义` 时整章零写入并要求作者裁决；
- `作者已裁决` 必须有非空 resolution；
- 覆盖既有事实必须匹配 expectedHash，防止审查后内容又被手改；
- 事实文件、计划文件删除和章节正文进入同一个 finalize Git 提交；
- commit 前失败精确回滚，批量定稿保存同一 payload，行为与手动定稿一致。

脚本不判断自然语言内容是否语义冲突。事实审查负责给出 decision；测试分别验证四种 decision 的运行时闸门和原子性。

## 6. 章级调用

### 6.1 细纲声明

旧的全量菜单和三个声明位一次性替换为：

    本章节拍：<零或多个编号/名称>
    本章场景：<零或多个名称>
    本章技法：<零或多个名称>
    本章追读：<零或多个名称>
    知识变体：<仅在实际修改或自定义时写，可多行>
    本章对象：<零或多个计划对象 ID/名称>

四个知识位都允许为空、自定义和组合。作者确认整份细纲即确认这些软策略；只有越过作品契约、人物底线、核心设定或定稿事实时才升级单独确认。

### 6.2 精准切片

- draft-outline DTO：每维最多 3 个候选，每个只含摘要、规划切片、来源和近期重复信号；
- prepare：从确认细纲解析声明，只注入命中条目的落笔切片；自定义声明原样保留；
- review：从同一细纲解析声明，只注入命中条目的审稿切片；不回读当前通用题材/流派；
- finalize：把确认细纲的四维最终选择和真实变体写入章节 front matter 的 `知识选择`，供近期历史读取。

`知识选择` 有唯一消费者：章级候选的近期历史排序与重复提醒。若最后一个消费者删除，该字段也必须删除。

### 6.3 手动与批量定稿一致

手动 finalize 在工作区细纲仍存在时提取知识选择；stage-chapter 在清理工作区之前把同一解析结果固化进暂存 payload。finalize-batch 原样消费该 payload，因此两条路径产出的章档案一致。自定义变体不需要能映射回通用条目。

## 7. 调用者切换

### 7.1 prep

prep 只读取：

- `作品契约/作品契约.md` 的本章所需小节；
- 细纲声明的计划对象；
- 细纲所选章级知识的落笔切片；
- 既有定稿事实和 staged 事实。

契约缺失或损坏时返回明确错误，不从旧路径或文风铁律补造；通用章级知识缺失仍是非阻断降级。

### 7.2 review

review 只读取同一冻结契约、本书化对象、定稿/staged 事实及已选章级审稿切片。移除 `resolveBookTags` 和当前通用题材/流派毒点回读，防止建书后知识更新导致生成侧和审查侧版本漂移。

## 8. 一次性切换范围

本任务同一阶段修改以下层：

- `src/knowledge/`：注册表、路由、查询、切片、来源 hash、声明解析和近期历史；
- `src/commands/`：knowledge-pack/query、persist-book/contract/design、read-design、finalize/stage 输入；
- `src/state-machine/`：create-book/draft-outline DTO、持久化、跟踪面与错误检测；
- `src/storage/`：作品契约和计划/事实对象适配器；
- `src/prep/`、`src/review/`、`src/finalize/`、`src/staging/`：精准读取和原子转正；
- `skills/`、`roles/`、host shells、fixtures、README、spec 和测试：删除旧名称和旧行为；
- installer：vendored 运行时加入 `docs/knowledge/`，保证 references README 链接有效。

新的正式维度目录可以暂时为空。运行时框架完成后，三个内容策展子任务再填充正式条目；空目录或未命中不得使测试靠虚构生产内容才能通过。

## 9. 提交与回滚单元

1. 知识内核：十维注册、canonical 路由、候选和切片接口。
2. 书级真源：作品契约建书/更新、prep/review 切换和源文件跟踪。
3. 故事对象：计划对象持久化、精准读取、事实差异和 finalize 原子转正。
4. 章级调用：少量候选、细纲声明、精准切片、近期历史和批量一致性。
5. 分发收口：installer、技能、角色、fixture、spec、host shells 与全量测试。

每个单元通过定向测试后提交。回滚使用版本控制按单元回退，不通过保留旧路径双读实现。
