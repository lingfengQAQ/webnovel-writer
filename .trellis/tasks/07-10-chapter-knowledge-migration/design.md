# Design：篇章知识重分类与策展

## 1. 目标与非目标

本任务把篇章执行层四维（节拍/场景/技法/追读）的存量条目和 v6 候选资产收敛为符合维度宪章与调用者矩阵的正式内容。运行时框架（细纲声明、精确切片、候选查询、近期历史软降权）已生效，本任务只做内容与 schema 收口，不重做运行时架构。

目标：

- 按已冻结的分维索引字段收口四维 front matter，删除无消费者字段，front matter `毒点` 与正文 `审稿时` 二选一保留单一真源。
- 清理存量 102 节拍、16 场景、10 追读的近重复、错维、旧书级口径（快穿/种田当题材）和未决项。
- 对 v6 写作技法 104 条、场景写法 96 条、桥段套路 108 条（共 308 条）逐条裁决，填充 `技法/` 正式内容。
- 每条正式条目能被真实章节问题命中，随细纲整体确认，`规划时/落笔时/审稿时` 各切片均有真实调用者。
- 用格式、查询、声明解析、精准注入和近期历史行为测试证明内容进入调用闭环。

非目标：

- 不修改十维边界，不新增 `桥段/结构/兑现` 顶层维度或 `本章桥段` 声明键。
- 不改动节拍/场景/技法/追读的声明键、章档案格式、近期历史接口等已验证运行时契约；只有内容暴露 schema 最小不一致时才做窄修正。
- 不建设章级候选自动推荐算法的新能力；`关键词/适用题材` 等条件式字段只在确认现有消费者后保留，不为未来算法预留。
- 不处理书级、故事对象维度内容（转交项只登记去向）。
- 不恢复 v6 全量菜单、题材固定路由或成品剧情模板。

## 2. 已冻结的数据流

```text
细纲规划
  -> 全量紧凑索引（编号/名称/一句话）或 knowledge-query 按问题取候选
  -> 近期历史只做软降权、机械重复提醒和变体说明
  -> 作者随细纲整体确认：本章节拍/本章场景/本章技法/本章追读/知识变体
  -> 写作备料精准注入命中条目的 落笔时 切片
  -> 编辑审读取命中条目的 审稿时 切片
  -> 章档案平铺保存 维度｜名称 与真实发生的 变体｜说明
```

未选候选不持久化；自定义声明不阻断流程；空目录（技法策展前）不阻断创作。

## 3. 四维 schema

### 3.1 front matter（与 `src/knowledge/index.js` 索引字段一致）

| 维度 | 字段 | 说明 |
|---|---|---|
| 节拍 | `编号 / 名称 / 一句话 / 关键词` | 编号稳定，供细纲声明与近期历史引用 |
| 场景 | `名称 / 一句话 / 关键词` | — |
| 技法 | `名称 / 类别 / 作用层级 / 触发问题 / 一句话` | `类别` 受控：对白/描写/视角/信息/情感/结构/战斗/设定执行；`作用层级` 受控：书/卷/跨章/章/场 |
| 追读 | `名称 / 一句话 / 关键词` | — |

门 0 已核实（见 `research/门0-运行时消费者核实.md`）：`关键词` 被 queryScore 语料打分真实消费,三维均保留,策展时须为低误触词；`适用题材` 与章级 FM `毒点` 在 `src/` 零消费,一律删除,审稿判据单一真源在正文 `审稿时`；format 测试对 FM 毒点的强制断言反转为禁止。`正例 / 反例 / 来源 / 状态 / 适用技能 / 大模型指令` 一律不进入正式条目。

### 3.2 正文切片

四维统一保留三个运行时切片，各有真实调用者：

- `## 规划时`：细纲规划时的选用判据——适用位置、触发信号、与近邻条目的区分。
- `## 落笔时`：写作备料注入的可执行动作。
- `## 审稿时`：编辑审核对的可观察判据与失败模式；front matter 不再重复保存同义 `毒点`。

存量条目的 `规划这一章时` 统一改名为 `规划时`，与运行时切片读取器对齐（门 0 核实读取器认哪个标题，以读取器为准，一处真源）。切片内容不得写具体剧情示例；题材相关的偏好写成触发条件而不是题材清单。

## 4. 存量清理与候选裁决

### 4.1 存量四维（128 条）

每条存量条目过一遍裁决记录（沿用父任务 `v6候选资产裁决模板.md` 区块），重点压力项：

- **节拍清桶**：诊断型、书卷结构型条目移出（书卷结构暂入技法 `类别: 结构`，诊断型删除或转第二阶段知识族）；近重复组 PA-057/072、PA-082/085、PA-089/097、PA-063/110 逐组比较问题/动作/失败模式后合并或锐化；11 条 `适用题材` 写快穿/种田的条目改为真实流派触发或随字段删除；PA-107 正文“种田”并列题材的表述修正。
- **场景边界重划**：冲突对话、名场面、对比反差、微冲突、画面感单场戏、感情推进按“事件互动容器归场景、组织呈现方法归技法”裁决——整条移动、拆分或保留锐化，不复制。
- **追读校准**：反转钩/认知钩/身份错位钩、支票/渴望按章尾未闭合压力与执行差异裁决种属关系，合并种属重复。
- 编号迁移规则：合并或删除的节拍编号废弃不复用；移动到技法的条目不带节拍编号。

### 4.2 v6 候选（308 条）与兄弟任务转交项

- 书级与故事对象任务登记的篇章转交项（含故事对象任务转交技法/节拍/追读的 11 条来源）纳入对应维度裁决输入，逐条给出唯一去向,不得悬空。
- `写作技法.csv` 104 条 → 默认去向技法；与场景写法近重复先聚类再裁决。
- `场景写法.csv` 96 条 → 按两问拆分：事件互动归场景、组织呈现归技法；同源两答拆分不复制。
- `桥段套路.csv` 108 条 → 风险最高，不整体迁入：能抽象的部分分别拆入场景/节拍/追读/技法，属创意约束的只登记转交；依赖固定人物配置、事件顺序或反转答案的删除；“换题材词仍是同一模板”不算新知识。

处置只用：`保留重写 / 锐化 / 合并吸收 / 拆分 / 移动 / 转交 / 删除`。不设条目数量目标；缺少独有问题、独有动作或独有失败模式的候选宁可合并或删除。

## 5. 批次与回滚

1. **schema 与行为样例**：格式测试收口四维字段与三切片；条件式字段消费者核实与定夺；`规划时` 标题统一；声明→注入→审稿→章档案行为样例。
2. **节拍**：102 条逐条裁决 + 清桶重写，近重复组与快穿/种田口径一并收口。
3. **场景**：存量 16 条边界重划 + v6 场景写法 96 条裁决，先裁决后分批落正式条目。
4. **技法**：v6 写作技法 104 条裁决 + 场景/节拍移入项，按类别分批落正式条目。
5. **追读**：10 条校准与种属合并。
6. **桥段拆分**：108 条逐条裁决，拆入前四批对应维度做增量补写。
7. **集成收口**：四维互相及与创意约束/人物/设定的跨维近重复审计、README 基线更新、技能与 installer 同步、全量测试。

每批独立提交并附 `research/content-review/<维度>.md` 独立审查记录。回滚某维只删除该维内容变更与对应测试/文档，不回退运行时框架；节拍/场景/追读回滚点是当前 128 条存量态,技法回滚点是空目录（运行时已容忍）。

## 6. 验证

- 格式：四维 front matter 只含允许字段与受控值，三切片非空，禁止“全部”占位、毒点回流和来源字段回流。
- 查询与声明：编号/名称精确命中、技法按 `类别/触发问题` 筛选、空目录与自定义声明不阻断。
- 注入：落笔只注入 `落笔时`，审稿只注入 `审稿时`，未命中回退声明文本。
- 历史：近期历史软降权与机械重复提醒对新内容行为不变；合法复用（作者确认递进目的）不被硬禁。
- 内容：每条正式知识通过唯一归属、近重复、非模板化和失败模式独立审查；来源清单不漏号、不重复、无悬空去向。
- 分发：源码、installer vendoring、技能、README 与 fixture 一致。

## 7. 风险

| 风险 | 防线 |
|---|---|
| 308 条候选一对一平移造成膨胀 | 先全量裁决聚类，正式条目不设数量目标 |
| 桥段拆分残留成品剧情模板 | 拆分结果逐条重过准入门；依赖固定配置/顺序/答案即删 |
| 场景与技法边界再次混淆 | 只用“哪种事件互动 vs 怎样组织呈现”两问裁决，同源两答必拆 |
| 节拍编号变动破坏细纲声明与历史 | 编号只废弃不复用；名称精确匹配保持；变更清单进审查记录 |
| 条件式字段变僵尸 schema | 门 0 核实消费者后一次定夺，删字段同步删索引定义与校验 |
| 切片改名导致注入静默失效 | 以运行时读取器为真源统一标题，行为测试覆盖注入命中 |
| installer 与源码内容漂移 | 每批同步 vendoring 检查，不保留双份知识 |
