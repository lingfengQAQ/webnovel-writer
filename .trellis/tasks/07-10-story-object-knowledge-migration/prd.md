# 故事对象知识策展

## Goal

建立 `设定/`、`人物/`、`命名/`三个故事对象维度，对旧资产进行重新策展，使知识能够在对象创建时产生本书化计划，并在正文定稿后形成可供精准读取与审查的作品事实。

## Requirements

- 前置依赖：父任务最终规划与维度宪章已冻结；运行时框架的设定/人物/命名 schema、计划对象持久化、事实转正和精准读取接口已实现并通过行为测试。
- 以 v6 `金手指与设定` 104 条、`人设与关系` 101 条、`命名规则` 79 条及相关 worldbuilding 指南为候选素材；逐条重写策展，不原样平移，也不承担旧格式兼容。
- 设定使用受控对象类型；人物包含角色与关系子类；命名覆盖标题与各类 canonical 实体名。
- 通用知识只保存设计方法、边界和审查点；具体能力、物品、组织、角色、关系和名称必须实例化后写入本书。
- 本书实例先进入 `大纲/创作设计/`；只有正文首次出现并定稿后才转入或更新 `定稿/设定/`。计划对象可修改或放弃，事实对象的根本修改需影响分析。
- 命名结果附着于对应计划对象或事实对象，不建立平行的本书命名实体目录；一次性路人、普通物品和临时地点不强制提前建档。
- 每条知识只有一个正式维度归属；跨维材料通过拆分或组合调用处理，不在多个目录复制。
- 若单任务内容量超出独立审查能力，继续按设定/人物/命名拆子任务。

## Acceptance Criteria

- [ ] 三个维度均有独立 schema、调用入口、本书化产物和审查闭环。
- [ ] 物品、能力、组织、世界规则等稳定归入设定子类，不再形成平行顶层目录。
- [ ] 命名支持语系一致、近名/重名、正名/别名和可读性检查。
- [ ] 计划与事实两阶段行为通过测试；无冲突事实自动转正，冲突或歧义由作者裁决，一次性对象不会造成书仓膨胀。
- [ ] v6 284 条候选素材均有策展裁决记录并通过独立内容审查。

## Notes

- 本任务可进一步拆成三个并行内容子任务，但集成边界由本任务负责。
- 启动前补齐自身 `design.md` 与 `implement.md`；按设定、人物、命名或更小审查批次独立提交，回滚不得删除已转正事实接口或把计划对象重新当作事实。
