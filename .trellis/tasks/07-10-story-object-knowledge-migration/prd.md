# 故事对象知识策展

## Goal

建立 `设定/`、`人物/`、`命名/`三个故事对象维度，对旧资产进行重新策展，使知识能够在对象创建时产生本书化计划，并在正文定稿后形成可供精准读取与审查的作品事实。

## Background

- 知识库运行时框架和书级知识策展已经完成并归档；`设定/人物/命名` 的查询、计划对象持久化、精准读取和事实转正接口已具备，当前三个正式内容目录仍为空。
- v6 候选素材为 `金手指与设定.csv` 104 条、`人设与关系.csv` 101 条、`命名规则.csv` 79 条，共 284 条。旧表包含具体能力/人物/名称模板、题材标签、固定数值、正反例和无消费者字段，只能作为候选证据，不能直接平移。
- 书级知识任务另转交了洪荒/克苏鲁/诡秘世界规则、反派镜像、规则身份、内鬼和关系阻力等故事对象候选；这些候选与三份 CSV 一并裁决，不能形成跨任务重复条目。
- 通用故事对象知识只在创建或修改计划对象时查询。选定方法必须本书化进 `大纲/创作设计/` 的 `本书设计 / 一致性边界 / 知识依据`；写作和审查读取计划对象或定稿事实，不持续回读通用条目。

## Requirements

- 前置依赖：父任务最终规划与维度宪章已冻结；运行时框架的设定/人物/命名 schema、计划对象持久化、事实转正和精准读取接口已实现并通过行为测试。
- 以 v6 `金手指与设定` 104 条、`人设与关系` 101 条、`命名规则` 79 条及相关 worldbuilding 指南为候选素材；逐条重写策展，不原样平移，也不承担旧格式兼容。
- 设定使用受控对象类型；人物包含角色与关系子类；命名覆盖标题与各类 canonical 实体名。
- 正式条目只保留实际查询所需的最小机器字段：设定为 `名称 / 对象类型 / 一句话`，人物为 `名称 / 人物类别 / 一句话`，命名为 `名称 / 命名对象 / 一句话`。不保留来源编号、适用题材、关键词、层级、毒点、正例、反例或治理状态。
- 故事对象条目只有 `规划时` 一个运行时切片；设计动作、本书化问题、一致性边界和失败模式均放在该切片内。后续写作与审查只读本书化计划对象，不给通用条目增加无人读取的 `落笔时 / 审稿时` 小节。
- `对象类型` 与计划对象允许值对齐为 `世界 / 规则 / 机制 / 能力 / 物品 / 组织 / 制度 / 地点`；人物以 `人物类别: 角色|关系` 区分主要产出，不保留无独立消费者的关系细分类字段；命名对象使用受控列表且允许一条方法覆盖多个真实对象类型。
- 通用知识只保存设计方法、边界和审查点；具体能力、物品、组织、角色、关系和名称必须实例化后写入本书。
- 本书实例先进入 `大纲/创作设计/`；只有正文首次出现并定稿后才转入或更新 `定稿/设定/`。计划对象可修改或放弃，事实对象的根本修改需影响分析。
- 命名结果附着于对应计划对象或事实对象，不建立平行的本书命名实体目录；一次性路人、普通物品和临时地点不强制提前建档。
- 每条知识只有一个正式维度归属；跨维材料通过拆分或组合调用处理，不在多个目录复制。
- 三份来源的每一数据行必须有唯一裁决记录；正式条目数量不是目标，无法抽象成独有问题、动作和失败模式的候选应合并、转交或删除。
- 若单任务内容量超出独立审查能力，继续按设定/人物/命名拆子任务。

## Acceptance Criteria

- [x] 三个维度均有独立最小 schema、调用入口、本书化产物和审查闭环，正式条目没有无消费者字段或小节。
- [x] 物品、能力、组织、世界规则等稳定归入设定子类，不再形成平行顶层目录。
- [x] 人物方法能稳定区分角色设计与关系设计，人物呈现技法不会混入人物维度。
- [x] 命名支持书名、卷章名和故事对象的语系一致、近名/重名、正名/别名和可读性检查，结果附着原对象。
- [x] 计划与事实两阶段行为通过测试；无冲突事实自动转正，冲突或歧义由作者裁决，一次性对象不会造成书仓膨胀。
- [x] `knowledge-query` 对三维均按真实问题或对象类型返回最多三条材料，允许空结果、自定义和组合，不形成固定人物/设定/名称答案。
- [x] v6 284 条候选素材及书级任务转交项均有策展裁决记录；每个正式条目通过近重复、非模板化和独立内容审查。

## Notes

- 本任务可进一步拆成三个并行内容子任务，但集成边界由本任务负责。
- 启动前补齐自身 `design.md` 与 `implement.md`；按设定、人物、命名或更小审查批次独立提交，回滚不得删除已转正事实接口或把计划对象重新当作事实。
- 本任务不新增顶层维度、不恢复 v6 运行时检索、不建设作者扩库、评分或自动知识晋升，也不承担篇章技法/场景/桥段策展。
