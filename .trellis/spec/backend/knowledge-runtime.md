# 知识运行时开发规范

> 版本：基线 1.5（2026-07-22）。产品边界以 PRD 1.6、story-repo-spec 0.17 和 `v7/docs/knowledge/` 为准。

## 1. Scope / Trigger

修改十维知识查询、建书、作品契约、计划对象、章级知识、事实转正、宿主壳或 installer 时适用。目标是保持“通用知识是可选材料，本书文件是运行时真源”：固定路由禁止替作者选择创意，知识缺失可自定义继续，作品契约缺失必须停止。

## 2. Signatures

```text
knowledge-pack --类型=<主题材> [--副题材=a,b] [--流派=a,b]
knowledge-query --维度=<十维之一> --问题=<真实未决问题> [--类型=<对象子类>]
persist-book --file=<json> [--dir=<目录>]
persist-contract --file=<json>
persist-design --file=<json>
read-design <ID或名称>
finalize <章号> --payload=<json>
```

章级细纲只认六个声明：`本章节拍`、`本章场景`、`本章技法`、`本章追读`、`知识变体`、`本章对象`。禁止恢复全量索引 DTO 或旧声明桥。

关键跨层 payload / DTO：

```text
persist-contract JSON += {证据: 非空字符串, 影响范围: 非空字符串}
序6 DTO = {作品契约, 章级知识候选?, 近期知识历史, 近期知识比较要求, ...}
近期知识历史章 = {章号, 选择:[{维度, 名称, 来源, 叙事功能, 实现方式}], 本章整体变体:[字符串]}
冲突 factChange += {difference, impact, options:[{optionId,label,description?,applyChange:boolean}]}
作者已裁决 factChange += {resolution, optionId, options:[原始选项...]}
细纲知识快照 = {schemaVersion:1, outlineSha256:<64位小写hex>, 知识选择:[现行章档案行...]}
ReviewInput += {作品契约版本:<正整数>, 审稿输入令牌:"sha256:<64位小写hex>"}
save-review JSON += {审稿输入令牌: 原样回传 ReviewInput.审稿输入令牌}
事实审查 / 编辑审报告 += {审稿输入令牌: 原样回传 ReviewInput.审稿输入令牌}
审稿结果 += {审稿输入令牌: 已核验令牌, 草稿哈希:"sha256:<64位小写hex>"}
```

## 3. Contracts

- `persist-book` 必须收到作者确认、完整作品契约和非空 `知识选择`；分类与来源版本必须和 `book`、选择记录一致。正式来源只接受同维度的直接 canonical `题材|流派|创意约束/文件.md@sha256:<64 位小写十六进制>`，拒绝路径逃逸、反斜杠、绝对/嵌套路径、错维来源和畸形 hash；也可精确使用 `作者自定义` 或 `对谈共创`。
- 题材/流派路由只做 canonical 归一和兼容提醒：空流派兼容范围表示无需窄范围提醒，禁止用“全部”占位；有副题材时 `knowledge-pack` 必须输出中央融合协议检查，不得输出固定比例或唯一创意答案。
- 作品契约的 `类型 / 副题材` 只能保存正式题材名称。`类型=衍生` 时至少有一个非“衍生”的正式副题材；流派名、别名和任意非题材字符串均不能充当实际世界副题材。校验器的正式题材名单必须由格式测试与 `路由.csv` 的题材行逐项对齐。
- `节奏与兑现参数` 没有数值配额时不增加占位；出现比例、固定章位或单位周期内次数时，必须分别提供非空的“统计对象 / 使用目的 / 失效条件”。仅出现三个空标签仍应拒绝。
- `persist-contract` 只保存作者确认的新版本；版本严格递增，且 `生效起章` 必须精确等于下一未定稿章。当前架构只有一份作品契约，不支持把新文件提前落盘、再延迟到未来章节生效。
- `persist-contract` 修订 payload 还必须给非空 `证据` 与 `影响范围`，两者写入 `作品契约/知识选择记录.md` 对应版本。缓存不可读时不得猜“下一章=1”；必须停止并要求重建缓存后再确认生效章。
- 契约更新必须在契约源文件提交前，原子写入所有当前未发布批次章与工作区工件的失效状态；`打回` 章仍属未定稿，不能跳过。既有失效守卫尚有待重做章或待提交证明时，禁止开始第二次契约更新。
- 契约失效守卫是机器真源，至少区分“待重做”与“待提交证明”。后者须精确绑定章号、契约版本、批次目录和 `定稿包.json` 原始字节 SHA-256；暂存只把本章转入待提交，不解除守卫。批量定稿须重验原始字节 hash，并把内部授权交给单章定稿；只有确认 git commit 成功后才能精确移除该章。提交失败或结果未知时，守卫与证明均保留。
- `restage` 必须原子替换待提交证明；`rejectFrom` 必须撤销被打回/受影响章的旧证明并回到待重做；`discardBatch` 只清被丢弃批次章的状态，不得清无关工作区章。守卫损坏、marker 与守卫语义冲突、证明缺失或包被篡改一律 fail closed。`stagedFacts` 只允许正常未失效章及 hash 验证通过的待提交章进入叠加视图，不能靠损坏/重建 `批次.json` 洗回旧事实。
- `persist-design` 写 `大纲/创作设计/设定|人物/`；对象至少含 `ID`、`名称`、`## 本书设计`、`## 一致性边界`、`## 知识依据`。知识依据至少有一行完整 `来源：<同维或命名维 canonical 文件>.md@sha256:<64 位小写十六进制>`，或精确的 `来源：作者自定义` / `来源：对谈共创`，并且有且仅有一行非空 `本书适配：…`；其余非空行、路径逃逸、反斜杠、绝对/嵌套路径、错维来源和畸形 hash 均拒绝。hash 是采用时的历史冻结标识，只验语法，不与当前知识包重算比对；目录即计划状态。
- 故事对象通用条目只在对象设计阶段调用：设定 front matter 为 `名称 / 对象类型 / 一句话`，人物为 `名称 / 人物类别 / 一句话`，命名为 `名称 / 命名对象 / 一句话`；正文只保留非空 `## 规划时`。写作和审稿只读作者确认后的计划对象与事实，不回读通用条目。
- 章级四维（节拍/场景/技法/追读）front matter 白名单：节拍 `编号/名称/一句话/关键词`，场景与追读 `名称/一句话/关键词`，技法 `名称/类别/作用层级/触发问题/一句话`（类别八受控值、作用层级 书|卷|跨章|章|场）。禁止 `毒点 / 适用题材` 回流——审稿判据单一真源在正文 `## 审稿时`。`关键词/触发问题` 是 queryScore 语料打分的真实排序输入，必须为低误触具体词。
- 章级条目正文三切片标题只认 `规划时 / 落笔时 / 审稿时`；`规划这一章时` 双读分支已删除，禁止恢复。备料只注入 `落笔时`，编辑审只注入 `审稿时`。
- 序 4 卷复盘与序 6 起草细纲必须先由同一 `ContractReader` 读取 `作品契约/作品契约.md`；缺失或损坏时返回阻断 DTO，状态机必须 `ok:false / needsAI:false`，禁止让 AI 继续复盘/起草或从旧文风路径补造。
- 作品契约的 `差异化点` 同时属于写作与审稿切片。编辑审不仅检查“是否出现过标签”，还要核对差异化点是否与本章大纲任务、人物选择/关系或设定机制形成具体因果连接。
- 作品契约 front matter 白名单以 `src/knowledge/contract.js` 校验器为准：`类型 / 副题材 / 流派 / 创意约束 / 来源版本 / 契约版本 / 生效起章 / 更新原因 / 变更类型`（列表字段为 副题材/流派/创意约束/来源版本）。
- 正式条目内容不得携带策展溯源（如「吸收 SP-xxx」）或来源/状态字段；裁决与来源真源只在 Trellis 任务 research 记录。条目正文语言纪律见 `v7/docs/knowledge/策展规则.md` 第 7 节（文学化词汇，禁工程词）。
- `knowledge-query --类型` 在故事对象三维必须使用唯一筛选字段和受控值：设定 `对象类型=世界|规则|机制|能力|物品|组织|制度|地点`；人物 `人物类别=角色|关系`；命名 `命名对象=书名|卷名|章节名|角色|地点|组织|能力|物品|制度|术语|任务|副本|赛事|代号`。人物不得恢复没有独立命令消费者的 `关系类别`。
- 命名知识只生成和校验名称；最终正名、别名、语系和近名检查附着于书级产物或设定/人物计划对象，不建立平行命名实体目录。普通未选候选不持久化。
- 事实审查可在报告顶层输出 `factChanges`；`validateReviewReport`、合并和 `工作区/评审报告/事实审查.json` 必须保留该数组。`冲突/歧义` 必须提供非空 `difference / impact` 与至少两个唯一 `optionId` 的选项，每个选项都显式给 `applyChange:boolean`；审稿单、手动 finalize 和自动暂存共用同一格式化结果，把差异、影响与全部选项呈给作者。`作者已裁决` 必须给 `resolution + optionId` 并保留原始 `options`，实际是否写事实只由选中的 `optionId` 对应 `applyChange` 派生，禁止信任调用方另传的执行布尔值。`applyChange:false` 是真正 no-op：不写事实、不删计划、不参与碰撞、不进入 staged overlay 或 staged payload。所有校验发生在章节、事实、计划或批次文件写入前，畸形或篡改裁决 fail closed。
- `review-input` 必须显式携带当前正整数 `作品契约版本`，并给完整 ReviewInput 计算确定性 `审稿输入令牌`（递归按键名排序对象后计算 SHA-256，数组顺序与字符串原文保留，散列时只排除根对象上的令牌自身），因而同时绑定章号、草稿、契约版本/审稿切片与所有审稿上下文，再把带令牌 DTO 写入 `工作区/审稿输入.json`。版本字段不可省略：一次修订即使只改了非审稿切片，也必须让旧输入失效。事实审查、编辑审及宿主合成的 `save-review` 外层 JSON 都必须原样回传同一令牌；任一缺失、畸形、混用或不相等一律拒绝，不保留旧格式兼容。
- `review-input` 的组装与写盘、`save-review` 的复核和报告写盘，必须进入作品状态共享锁。AI 往返不能长期持锁，因此 `save-review` 必须在锁内重新组装当前完整 ReviewInput，核对 sidecar 令牌自洽，并要求当前 DTO、sidecar、外层 JSON 与两份报告的令牌全部相等；只比较 sidecar 自身或只加互斥锁，既挡不住契约更新前已发出的旧两审结果，也挡不住同版本下细纲/批内上下文变化后的延迟回流。
- `工作区/评审报告/审稿结果.json` 必须同时持久化已核验的 `审稿输入令牌` 与 `草稿哈希`。手动定稿、暂存、重审收口及契约更新后的 fresh-work 校验必须再次核对当前 sidecar 与结果令牌；stage 生成待提交证明后才能清 sidecar，后续由原始定稿包 hash 继续绑定。任何令牌漂移都整章零写入。
- 批内改稿或重审必须从 `batch-status --json` 读取该章实际存在的 repo 相对 `草稿路径`，并把同一路径同时传给 `review-input --draft` 与 `save-review --draft`；禁止默认审查 `工作区/草稿-A.md` 后给暂存草稿授权。`batch-restage` 只有在新结果核对暂存 `定稿包.json` 成功并原子更新批内审稿单/状态后，才清理 `审稿输入.json`、`审稿.md` 与评审报告；清理失败只警告，不反转已经成功的重审收口。
- 章档案的 `知识选择` 保存最终选择 `维度｜名称｜来源` 与真实 `变体｜说明`；正式来源为采用时的 `路径@sha256`，自定义为 `作者自定义`。它是近期软降权与来源追溯的唯一输入；不保存未选候选、评分、满意度或空反馈。
- `persist-outline` 必须先通过 `ContractReader` 校验当前作品契约，再原子写 `工作区/细纲.md` 与 `工作区/细纲知识快照.json`。快照在作者确认细纲时冻结最终 `知识选择` 和细纲原文 hash；后续引用文件变更或删除不得改变本章 H1 来源。存在细纲时，快照缺失、旧 schema、多余字段或 `outlineSha256` 不匹配均停止暂存/定稿并要求重新确认；细纲与快照必须一起参与清理、契约失效和系统状态路径保护。批量定稿等确实没有工作区细纲的路径，只能保留并严格校验现行章档案格式：选择恰为 `维度｜名称｜来源` 三段，变体恰为 `变体｜说明` 两段，拒绝旧两段式、错维来源、畸形 hash 和多余字段。
- 序 6 读取最近八章的全部章级选择（含批内前章），而非只保留与当前候选同名项；历史必须按章分组为 `{章号, 选择:[…], 本章整体变体:[…]}`。逐项只提供名称、来源、当前同版本条目的叙事功能/实现方式；来源已删除或 hash 漂移时语义字段留空但谱系照常保留。AI 同时比较名称、功能、实现与整章变体：同名但有实质递进可复用，异名但功能/实现同质须提醒，匹配本章任务优先于表面换标签。`知识变体` 是章级整体说明，禁止复制或臆造归属到任一选择。
- npm 包和 vendored 运行时必须同时包含 `references/` 与 `docs/knowledge/`；治理 README 链接不得失效。

## 4. Validation & Error Matrix

| 条件 | 必须行为 |
|---|---|
| 通用维度目录缺失、查询无命中 | 返回空候选；允许 AI/作者自定义，创作不停 |
| 作品契约缺失或结构损坏 | 建书/备料/审稿停止并给中文错误；禁止读旧路径补造 |
| 序 4 / 序 6 的作品契约缺失或结构损坏 | 返回阻断 DTO；状态机 `ok:false / needsAI:false`，不得卷复盘、生成或保存细纲 |
| canonical 路由未命中 | 原样报告未命中，禁止伪装成正式条目 |
| 流派兼容范围为空 | 不产生兼容提醒；禁止恢复“全部”占位兼容分支 |
| `类型 / 副题材` 含非正式题材名称 | 建书或契约更新失败，要求先完成 canonical 归一 |
| `类型=衍生` 但没有非“衍生”的正式副题材 | 建书或契约更新失败，要求补充实际世界题材 |
| 数值节奏配额缺任一非空说明 | 建书或契约更新失败，指出须补统计对象、使用目的和失效条件 |
| 计划对象 ID、正名或别名冲突 | 写盘前拒绝，零文件变更 |
| 计划对象缺 `知识依据`，缺唯一非空本书适配，来源不是精确安全行、错维或 hash 畸形 | `persist-design` 写盘前拒绝；读取旧对象时进入修复确认，不保留旧格式双读 |
| 故事对象 `--类型` 不在受控值中 | 命令前置拒绝并列出该维允许值；禁止模糊归类 |
| 故事对象目录缺失或问题无命中 | 返回空候选并允许完全自定义；禁止回退全量旧 CSV |
| 契约修订缺证据/影响范围，或缓存无法确认下一未定稿章 | 更新停止；契约和选择记录零变更 |
| 契约修订生效章不等于下一未定稿章，或已有失效守卫未收口 | 更新停止；禁止覆盖当前契约或已有待重做/待提交状态 |
| `factChanges` 为冲突/歧义但缺差异/影响/至少两项处理方式 | review schema 前置拒绝；不得生成含糊的“须裁决”占位 |
| `factChanges` 选项缺 `applyChange:boolean`，或作者裁决缺 `resolution / optionId / 原始 options`、选项被篡改 | 整章零写入，要求补齐或重新审查；不得猜执行语义 |
| `factChanges` 为冲突/歧义、hash 漂移或路径逃逸 | 整章零写入，并把完整待裁决内容返回作者 |
| `save-review` 外层或任一审查报告缺/改/混用 `审稿输入令牌`，sidecar 令牌不自洽，或令牌绑定的章号/草稿/作品契约已变化 | 两审结果零写入，要求基于当前 `审稿输入.json` 重新审查；禁止靠新 mtime 冒充新契约审稿 |
| 审稿结果令牌与当前 sidecar 不一致，sidecar 在暂存/定稿前缺失、损坏，或批内重审没有绑定 `batch-status` 返回的现存草稿 | `save-review` / `batch-restage` / 定稿停止并保留现有工件；不得只凭相同正文 hash 或默认 `草稿-A.md` 给暂存包授权 |
| 细纲存在但来源快照缺失、旧版、结构错误或 hash 不一致 | 暂存/定稿停止，要求重新确认细纲；禁止从当前通用库重建历史来源 |
| 契约失效守卫/待提交证明损坏、与 marker 或批次不一致、定稿包 hash 漂移 | 暂存、叠加或定稿停止；保留守卫与工件，禁止状态洗回 |
| installer 缺治理文档或 README 链接目标 | 单测和 pack-install e2e 必须失败 |

## 5. Good / Base / Bad Cases

- Good：同一组主题材、副题材和流派按不同未决问题采用不同创意约束；融合协议写清共同冲突、副题材介入条件和失焦风险，作者确认后保存。
- Base：流派兼容范围或某知识维度为空，不制造提醒或默认答案；允许对谈自定义继续。
- Good：以“能力太万能且后遗症不落地”查询设定，选择或改写少量候选，将来源与本书适配写入计划对象；后续章节只精准读取该对象。
- Base：对象类型明确但正式知识无合适方法，直接自定义本书对象，在 `知识依据` 写 `来源：作者自定义` 与非空 `本书适配：…`；不保存未选候选，也不阻断计划落盘。
- Good：近期仍选择“伏击”，但细纲写清从“隔离目标”递进为“用假路线识别内鬼”，允许复用；若改名“围堵”却仍在同一仓库封同样出口完成同一抓捕，则提示同质。
- Base：近期条目已从当前知识库删除，仍传章号、维度、名称和真实变体，功能/实现留空，不阻断创作。
- Good：事实冲突列出旧/新差异、对后续战力的影响，以及“改正文/接受突破”两种处理方式；作者选中一项并说明后才重提。
- Good：作者选择“保留计划、不写正文事实”的 `applyChange:false` 选项；章节仍可定稿，但事实文件、计划对象、目标碰撞和批内事实叠加均保持不变。
- Good：两审原样回传当前 `审稿输入令牌`；`save-review` 在共享锁内确认 sidecar、草稿和契约仍匹配后落盘，暂存再核对同一令牌。
- Base：AI 审稿期间作品契约未变化；令牌稳定，正常保存，不要求在 AI 往返期间长期占锁。
- Good：契约更新后受影响章完成新细纲、备料、写稿和两审；暂存生成原包 hash 证明，批量入口复核后提交，并只释放已确认入档的这一章。
- Base：通用章级条目在作者确认细纲后被修改或删除；本章继续使用快照中的采用时来源，语义切片缺失时不改写历史谱系。
- Bad：按题材固定选择一个人物模板，或让 prep/review 每章重新读取当前通用人物条目。
- Bad：把快穿流写进衍生作品的副题材；只写“统计对象：/使用目的：/失效条件：”三个空标签；按题材固定选择唯一创意或关系结算答案；事实冲突只返回“须作者裁决”而不展示差异、影响与选项。
- Bad：契约更新前把 `审稿输入.json` 发给 AI，更新后用相同正文重新备料，再把旧两审 JSON 写成新 mtime 并仅凭草稿 hash 放行。
- Bad：把契约写成未来章才生效却立即覆盖唯一契约文件；在 stage 时删除守卫；只改 `批次.json` 状态或替换 `定稿包.json` 就让旧事实/正文重新进入叠加与定稿。

## 6. Tests Required

- 知识查询：每维最多三条、无命中空集、近期历史只降权不排除；序 6 传全部近期选择与四项语义比较要求，且相同源文件确定性输出。
- 故事对象：三维精确类型筛选、非法类型拒绝、最小 front matter、单一 `规划时` 切片、命名对象受控列表和禁用“全部”。
- 本书化链路：最终对象必须在 `知识依据` 留下精确来源行与唯一非空本书适配；覆盖同维/命名来源、自定义、共创、多来源，以及 traversal、反斜杠、绝对路径、错维、substring、63/65 位和非小写 hex 反例。prep/review 只加载细纲声明的计划对象；未声明不扫描，事实转正后不依赖通用条目。
- 建书/契约：必需字段、分类/来源同源、书级来源安全路径与同维约束、更新版本/证据/影响范围、`生效起章 === nextChapter`、全部未发布工件失效、待重做→待提交证明→commit 后精确释放、篡改/提交未知/批次状态洗回 fail closed、缓存不可确认下一章时阻断、旧路径不回退；序 4 / 序 6 缺/坏契约时状态机不调用 AI。
- 书级路由：题材名单与契约校验名单完全一致；流派兼容范围不含“全部”，空值不提醒；歧义词与跨维词保持未命中。
- 衍生/配额：非题材副题材被拒；至少一个正式世界副题材才能通过；“每三章”“每章 2 个”“每卷 1 次”和空说明标签均有反例，完整三项说明有正例。
- 反同质化：相同主题材/副题材/流派至少形成两套机制不同且都能通过校验的作品契约，固定路由输出不含创意约束答案。
- 计划/事实：精准读取、知识依据来源格式、重名拒绝、四种 decision、每项 `applyChange`、false no-op、hash 漂移、手动/批量原子一致。
- 审稿：顶层 `factChanges` 经 schema 归一化后仍存在于正式事实报告；冲突详情不全前置拒绝，完整详情进入审稿单和两条写盘闸门；作者裁决须填写 `optionId` 并保留原始 `options`，执行语义只从命中选项派生；审稿结果还须绑定被审草稿，另一份 payload 不得冒充已审稿。
- 审稿输入绑定：同一 ReviewInput 确定性生成同一令牌；改章号、正文、契约版本或任一 DTO 字段都会改变令牌；`save-review` 缺令牌、篡改/混用令牌、sidecar 损坏、当前 DTO 已变化、契约更新前令牌延迟回流均零写入；合法令牌持久化到审稿结果，stage/finalize 再核对。至少一条真实命令链覆盖“旧 v1 input → v2 契约 → 同正文新材料 → 旧两审回流被拒”，并覆盖同版本细纲或批内上下文改变后旧结果被拒。
- 批内重审：`batch-status --json` 对每个仍有暂存草稿的章节返回正斜杠 repo 相对 `草稿路径`，打回且工件已清的章不伪造路径；命令与序 3 DTO 都指向同一路径的 `review-input/save-review`，`batch-restage` 成功后 sidecar 与评审工作区工件被清理。
- 章级来源冻结：契约有效后细纲与快照原子写；引用文件变更/删除不改变已冻结来源；快照缺失、旧 schema、字段增删和细纲 hash 漂移均 fail closed；无细纲路径严格拒绝旧章档案格式。
- 分发：installer 文件清单、三条治理链接、host-shell drift、`npm pack → 中文路径 init → 完整契约建书 → next → update`。

## 7. Wrong vs Correct

Wrong：

```js
const choice = topicDefaults[book.类型]
const contract = await readOldStyleGuide()
const actualWorld = contract.副题材.find((name) => name !== '衍生')
const quotaOk = ['统计对象', '使用目的', '失效条件'].every((label) => pacing.includes(label))
```

Correct：

```js
const contract = validateWorkContract(contractContent)
if (!contract.ok) return { ok: false, error: contract.errors.join('；') }
const candidates = await queryKnowledge(packageRoot, dimension, { 问题: question, limit: 3 })
```

前者制造固定答案和双真源，还会把任意副题材或空说明误当有效；后者验证正式分类与非空说明，并以作者确认的本书契约驱动运行时。

故事对象查询同样不得用题材路由替代真实问题：

```js
// Wrong：无消费者字段和固定人物答案
const candidate = defaults[book.类型].反派

// Correct：唯一受控筛选字段，空结果可自定义
const candidates = await queryKnowledge(packageRoot, '人物', {
  问题: unresolvedProblem,
  筛选: { 人物类别: '角色' },
})
```

近期重复与事实冲突也不能只比较标签或返回空泛阻断：

```js
// Wrong：改名即当成不同；冲突只有布尔值
if (recentNames.has(candidate.名称)) candidates.delete(candidate)
return { ok: false, error: '须作者裁决' }

// Correct：按章保留选择与整体变体；变体不伪装成逐项归属
dto.近期知识历史 = recent.map(({ 章号, 选择, 本章整体变体 }) => ({
  章号,
  选择: 选择.map(({ 维度, 名称, 来源 }) => ({
    维度, 名称, 来源, 叙事功能, 实现方式,
  })),
  本章整体变体,
}))
return { ok: false, error: formatFactChangeValidationError(validation) }
```

审稿结果也不能只绑定正文；相同正文可能对应不同契约上下文：

```js
// Wrong：旧两审只要正文相同，就可在契约更新后重新写入
if (outcome.草稿哈希 === reviewedDraftHash(payload)) accept(outcome)

// Correct：令牌绑定完整审稿输入，回流和消费两端都复核当前 sidecar
if (submitted.审稿输入令牌 !== currentInput.审稿输入令牌) reject()
if (!validateReviewInputToken(currentInput).ok) reject()
if (outcome.审稿输入令牌 !== currentInput.审稿输入令牌) reject()
```
